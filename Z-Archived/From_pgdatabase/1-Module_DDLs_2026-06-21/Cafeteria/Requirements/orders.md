# Orders — Requirements

## Parent Tab: Orders & Attendance

## What It Does
Student meal pre-order system with cutoff enforcement, payment modes, and order lifecycle tracking. Students place orders before cutoff time; kitchen sees confirmed orders for preparation.

## Tables Covered

1. `caf_orders` — Order headers
2. `caf_order_items` — Order line items with price snapshot

---

## Entity: Orders (`caf_orders`)

### Database Fields

| Field | Type | Conditions |
|---|---|---|
| `id` | INT UNSIGNED PK | Auto-increment. |
| `order_number` | VARCHAR(30) | Required. Unique. Auto-generated: `CAF-YYYY-XXXXXXXX`. |
| `student_id` | INT UNSIGNED FK → std_students | Required. |
| `meal_card_id` | INT UNSIGNED FK → caf_meal_cards | Nullable. NULL if cash/counter. ON DELETE SET NULL. |
| `order_date` | DATE | Required. Calendar date the meal is ordered for. |
| `meal_category_id` | INT UNSIGNED FK → caf_menu_categories | Required. ON DELETE RESTRICT. |
| `total_amount` | DECIMAL(10,2) | Required. Sum of all line item totals. |
| `payment_mode` | ENUM('MealCard','Cash','Counter','Subscription') | Default 'MealCard'. |
| `status` | ENUM('Pending','Confirmed','Served','Cancelled') | Default 'Confirmed'. |
| `cancelled_at` | TIMESTAMP | Nullable. |
| `cancellation_reason` | VARCHAR(255) | Nullable. |
| `notes` | TEXT | Nullable. |
| `is_active` | TINYINT(1) | Default 1. |
| `created_by` | INT UNSIGNED FK → sys_users | Nullable. |
| `created_at` / `updated_at` | TIMESTAMP | Laravel standard. |
| `deleted_at` | TIMESTAMP | Nullable. Soft delete. |

### Business Rules

#### Field-Level Validation

| Field | Rule | Error Message / Behavior |
|---|---|---|
| `order_number` | Auto-generated, unique, max:30 | Never accepted from user input. |
| `student_id` | Required, exists:std_students,id | "The selected student is invalid." |
| `meal_card_id` | Nullable, exists:caf_meal_cards,id | Required if payment_mode is 'MealCard'. Error: "Meal card is required for card payments." |
| `order_date` | Required, date | Must be today or future. "Cannot order for a past date." |
| `total_amount` | Read-only (computed) | Sum of `caf_order_items.line_total`. Never from user input. |
| `status` | Required, enum | Transitions validated by workflow below. |

#### Order Number Auto-Generation

- Format: `CAF-YYYY-XXXXXXXX` (e.g., `CAF-2026-00000001`).
- Year locked to creation year. Sequential 8-digit number, reset per year.
- Lock-guarded to prevent duplicates under concurrent creation (SELECT...FOR UPDATE on counter).
- Generated by OrderService on create.

#### Pre-Order Cutoff Rule

- Default cutoff: 10:00 PM the day BEFORE `order_date`.
- Configurable per meal category (via `cutoff_time` field on menu_categories or a config setting).
- After cutoff: "Order cutoff time has passed for {meal_category} on {order_date}."
- Affects new orders only. Existing orders unaffected.

#### Order Lifecycle State Machine

| From | To | Guard | Side Effects |
|---|---|---|---|
| Pending | Confirmed | Payment confirmed | Order locked for kitchen prep. |
| Confirmed | Served | Must be on/after order_date | Meal handed to student. |
| Confirmed | Cancelled | Before meal's meal_start_time. After: "Cannot cancel order — meal service has already started." | Sets cancelled_at, reason. Refunds meal card if applicable. |
| Pending | Cancelled | None (payment failed or student cancelled) | Same side effects. |
| Cancelled | (any) | No transitions from Cancelled. | Immutable. |

**Cancellation Side Effects:**
1. Sets `cancelled_at = now()`, `cancellation_reason` from input.
2. If `payment_mode = 'MealCard'`: refund total_amount to meal card balance via MealCardService.
3. Creates `caf_meal_card_transactions` record with type 'Refund'.
4. Activity log: "Order {order_number} was cancelled. Reason: {reason}."

#### Duplicate Order Guard

- A student can order for multiple `meal_category_id` on the same `order_date` (e.g., Breakfast + Lunch).
- Only ONE order per `(student_id, order_date, meal_category_id)`. Duplicate: "You already have an order for {meal_category} on {order_date}."

#### Soft Delete & Restore

- Only `Pending` or `Cancelled` orders can be soft-deleted.
- `Confirmed` or `Served`: "Cannot delete a confirmed or served order."
- Restore: sets `deleted_at = NULL`. Does not change status.

#### List View

- Controller: OrderController@index. Gate: `tenant.cafeteria.order.viewAny`.
- Pagination: 15 per page, sorted by `order_date DESC, created_at DESC`.
- Columns: Order Number, Student Name, Date, Meal Category, Total Amount, Payment Mode, Status (badge), Actions.
- Filters: search by order number or student name, date range, status dropdown, meal category dropdown.
- Kitchen view: separate route `cafeteria.orders.kitchen` — shows all Confirmed orders grouped by date/meal_category for kitchen prep.

## Entity: Order Items (`caf_order_items`)

### Database Fields

| Field | Type | Conditions |
|---|---|---|
| `id` | INT UNSIGNED PK | Auto-increment. |
| `order_id` | INT UNSIGNED FK → caf_orders | Required. ON DELETE CASCADE. |
| `menu_item_id` | INT UNSIGNED FK → caf_menu_items | Required. ON DELETE RESTRICT. |
| `quantity` | TINYINT UNSIGNED | Default 1. |
| `unit_price` | DECIMAL(8,2) | Required. Price snapshot at order time. |
| `line_total` | DECIMAL(10,2) | Required. `quantity × unit_price`. |
| `created_at` / `updated_at` | TIMESTAMP | Laravel standard. |

### Business Rules

- Immutable after order placement. No mass update or batch edit.
- `unit_price` is copied from `caf_menu_items.price` at order creation time. Subsequent price changes to the menu item do NOT affect existing orders.
- `line_total` computed as `quantity × unit_price` at insert time. Not a generated column — allows future adjustment if needed (with audit trail).
- UNIQUE on `(order_id, menu_item_id)`: same dish cannot appear twice (use quantity > 1).
- No `is_active`, no `created_by`, no `deleted_at`: transactional line item.
