**2. Proposal Type CRUD tab.**

- New tab on Transport Master with full CRUD, trash/restore/force-delete, status toggle, system-row protection (cannot edit/delete `is_system` rows), form request, policy, 5 blade views and an idempotent seeder for the 10 default types.
- Permissions, breadcrumbs and routes added.
- **Action for the team:** run `ProposalTypeSeeder` (or `SeederController`); the tenant permission row may need the normal permission sync before non-superadmin roles see the tab.

**3. Non-destructive auto route proposal.**

- The old auto-generate force-deleted live routes/stops/allocations. The new `RouteProposalPlanner` writes **only** to proposal tables; live routes stay untouched until a proposal is approved.
- Shift-scoped (Pickup or Drop; `Both` is not a route-level value because `tpt_route.pickup_drop` is `ENUM('Pickup','Drop')`), capacity from `tpt_vehicle.capacity/max_capacity` (no hardcoded 40), merge/split/remove/student change types, try/catch + DB transaction + retry, and dynamic cost/km from vehicle fuel/maintenance data.
- Verified on tenant `…0001`: Pickup proposal #30 = 11 routes / 435 students / 0 warnings; Drop #31 = 12 routes / 435 students / 0 warnings; required columns non-null; geometry SRID 4326.
- **Why it matters:** generating a proposal is now safe. Nothing goes live until approval (approval/apply workflow is still Phase 3, not built).

**4. Route Proposals & Approvals page.**

- New menu item under Smart Transport, dedicated page grouped by `tpt_route_proposal_master`, shift + route filters (cascading), direction badges (`Both / Pickup / Drop`), and a detail page with a Route → Stop → Student accordion, old-vs-new route/stop mapping, fares, distances, times and optimisation audit (merged / walk-zone / removed stops).
- **Action for the team:** run `/sync-menus` to show the menu.

**5. Smart Advisor "Save as Proposal".**

- Checkboxes on suggestion cards + Save button; persists selected suggestions atomically into the 4 proposal tables (`master`, `proposed_route`, `pickup_points_route_jnt`, `student_route_allocation`) with correct proposal types, exact modal-tab-3 stops, linked transferred students, and dynamic `est_exp_per_km`.
- **Action for the team:** review a saved proposal in the UI; this is the first end-to-end path from advisor suggestion to proposal record.
