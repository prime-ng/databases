# HPC Card Generation - Full Guide

## What Is This Feature?

This feature takes all the information about a student and turns it into a printable document called a PDF. A PDF is a file type that looks the same on any computer or phone. You can print it, save it, or send it to someone.

Think of it like this: The teacher has been filling in many pages of the student's progress card. The student has written their self-assessment. The parent has filled in their observation form. All of this information is stored inside the computer. The Card Generation feature takes all that stored information, arranges it neatly on pages following the school's template design, and creates a clean PDF file.

You can make a PDF for one student at a time. Or you can make PDFs for many students at once and they all get packed into one ZIP file (a ZIP file is like a folder that holds many files together).

There is also a way for parents to view the card online without needing to log in to the system. They just need a special web address.

---

## Who Can Use This Feature?

Teachers can use this feature. This includes class teachers (who are in charge of one class) and subject teachers (who teach one subject to many classes).

School administrators can also use this feature. Admins are office staff who handle school records.

The person must have permission from the school to access this feature. Not every teacher or staff member can use it. The school decides who gets permission.

## PART 1: Making a PDF for One Student

### How the Teacher Starts

The teacher looks at the student list on the computer screen. Next to each student's name, there is a button that says "Generate PDF." The teacher clicks this button for the student they want.

The teacher can also click this button from inside the student's card form. While viewing the card on the screen, there is a "Generate PDF" button at the top or bottom.

### Step-by-Step: What Happens Inside the Computer

When the teacher clicks the button, the computer follows these steps. All of this happens in a few seconds. The teacher does not see each step. The teacher just waits for the PDF to appear.

#### Step 1: Collect All Data

The computer goes through all the stored information for this student and gathers everything together. The computer collects:

What the teacher typed: All the grades, ratings, scores, and written comments that the teacher entered into the card pages. This includes assessments for every subject and domain.

The attendance table: The working days, present days, percentages, and any absence reasons. This comes from the attendance system.

The student's self-assessment: If the student has submitted their self-assessment (for middle and secondary students), the computer collects those answers. If the student has not submitted, this section is skipped.

The parent's observations: If the parent has filled in their observation form, the computer collects those answers. If the parent has not filled it in, this section is skipped.

Peer review results: If classmates have completed peer evaluations, the computer collects those ratings. If not, this section is skipped.

#### Step 2: Check Which Template to Use

The computer checks which grade level the student is in. Each grade level uses a different template design. The four grade levels are:

Foundation: For the youngest students (typically ages 3 to 5). This is preschool and kindergarten level.

Preparatory: For slightly older students (typically ages 6 to 8). This is early primary school.

Middle: For students ages 9 to 11. This is upper primary school.

Secondary: For the oldest students (ages 12 to 14 and above). This is middle and high school.

Each template has a different layout. Foundation templates focus on play-based learning. Secondary templates include credits and career goals.

#### Step 3: Pick the Correct PDF Layout

The computer has four different PDF layouts stored inside it. One layout for each grade level. The computer picks the correct one based on the template ID number.

If the template ID is between 1 and 18, the computer uses the Foundation layout. This layout has big spaces for pictures and simple indicators.

If the template ID is between 19 and 36, the computer uses the Preparatory layout. This layout is more structured with subject areas.

If the template ID is between 37 and 54, the computer uses the Middle layout. This layout includes sections for self-assessment and peer reviews.

If the template ID is 55 or higher, the computer uses the Secondary layout. This layout includes NCrF credits and career aspiration sections.

If the template ID does not match any expected range, the computer uses a fallback layout. The fallback layout is basic but still shows all the information. It just might not look as nice as the correct layout.

#### Step 4: Arrange Data onto Pages

The computer takes all the collected data and places it into the correct positions on the PDF pages. Each piece of data goes into its proper spot.

The student name goes at the top. The attendance table goes in its section. The assessment grades go in their sections. The comments go in their sections. Everything is arranged neatly.

#### Step 5: Create the PDF File

The computer creates the PDF file. A PDF is a special file format that looks exactly the same on any device. The teacher can open it on a computer, a phone, or a tablet, and it will always look the same.

The computer sends the PDF file to the teacher's computer. The teacher sees a pop-up window that asks: "Do you want to save this file?" The teacher clicks Save, and the PDF is saved to the computer's Downloads folder.

### What Appears on the PDF

The PDF has many sections. Here is a list of everything that appears.

#### Section 1: School Header

The top of the first page shows the school name, the school logo, the school address, and contact details like phone number and email.

This header appears on every page of the PDF.

#### Section 2: Student Information

Below the header, the PDF shows the student's full name, class name, section, roll number, and date of birth.

If the school uploaded a photo of the student, the photo appears here too.

#### Section 3: Attendance Summary

The attendance table appears next. This table shows all 12 months from April to March. For each month, it shows:

Working Days: How many days the school was open that month.
Present Days: How many days the student was present.
Percentage: The attendance percentage for that month.
Reason: Any notes about absences.

At the bottom of the table, there is a total row that shows the overall attendance for the whole year.

#### Section 4: Assessment Sections for Each Subject

This is the main part of the PDF. For each subject or domain, the PDF shows:

The subject name (for example: Mathematics, English, Science).

The scores or ratings that the teacher gave. This might be numbers (like 85 out of 100) or grades (like A or B) or descriptive ratings (like "Excellent" or "Satisfactory").

The teacher's written comments for that subject. The teacher might write things like: "Priya is doing well in mathematics but needs to work on division."

If the student submitted a self-assessment, the student's own ratings and comments appear here too.

If the parent submitted observations, those appear as well.

If peer reviews were done, those ratings also appear.

#### Section 5: Life Skills Assessment

This section shows ratings for life skills. Life skills are things like:

Communication: How well the student talks and listens.
Collaboration: How well the student works with others.
Problem-solving: How well the student solves problems.
Creativity: How creative the student is.

The teacher rates each skill. These ratings appear on the PDF.

#### Section 6: Co-Curricular Assessment

This section shows the student's participation and achievement in activities outside of regular classes. This includes:

Sports and games.
Art and music.
Drama and dance.
Clubs and societies.
Community service.

The teacher rates the student's participation and performance in each activity.

#### Section 7: Student Self-Assessment (If Available)

For middle and secondary students, this section shows what the student wrote about themselves. The student might have answered questions like:

What are my strengths?
What do I want to improve?
What are my goals for next term?

The student's answers appear exactly as they typed them.

#### Section 8: Parent Observations (If Available)

If the parent filled in the observation form, this section shows the parent's answers. The parent might have answered questions like:

Does the child study at home?
How does the child behave with family?
Does the child complete homework?

The parent's answers appear exactly as they typed them.

#### Section 9: Teacher's Overall Comments

This section shows the teacher's final comments about the student. The teacher writes a summary paragraph about the student's overall performance, behavior, and progress.

This is the most important section for parents. They read this to understand how their child is doing in school.

#### Section 10: Principal's Signature (If Approved)

If the principal has approved the card, the principal's signature or digital signature appears at the bottom of the PDF. This shows that the card is official and approved.

If the principal has not approved yet, this section is left blank or shows "Pending Approval."

#### Section 11: NCrF Credits (Secondary Only)

For secondary students only, the PDF shows NCrF credits. NCrF stands for National Credit Framework. This is a system that assigns credit points to different learning activities.

The PDF shows how many credits the student earned in each area and the total credits for the term.

#### Section 12: QR Code or Card ID

At the bottom of the last page, there is a QR code or a unique identification number. A QR code is a square pattern that a phone camera can scan. When someone scans the QR code, it opens the student's card online.

The unique ID number can be used to look up the card in the system. This is useful for verification.

## PART 2: Making PDFs for Many Students at Once (Bulk Generation)

### How the Teacher Starts

The teacher goes to the student list. Next to each student's name, there is a small box called a checkbox. The teacher clicks the checkbox for each student they want to include.

The teacher can select as many students as they want, up to 50 at a time.

After selecting the students, the teacher clicks a button that says "Bulk Generate" or "Generate Bulk."

### Step-by-Step: What Happens Inside the Computer

#### Step 1: Count Selected Students

The computer counts how many students the teacher selected. If the count is 50 or fewer, the computer proceeds. If the count is more than 50, the computer stops and shows a message: "Bulk generation limited to 50 students."

#### Step 2: Generate PDF for Each Student

The computer goes through the list of selected students one by one. For each student, the computer follows the same five steps as for a single student PDF. The computer collects data, checks the template, picks the layout, arranges the data, and creates the PDF.

#### Step 3: Package into ZIP File

After all PDFs are created, the computer puts them all into one ZIP file. A ZIP file is like a container that holds many files. When the teacher opens the ZIP file, they find all the individual PDFs inside.

The ZIP file is given a name based on what it contains. For example: "Cards_Class5A_Term1.zip" or "Bulk_Generation_2024-25.zip."

The computer removes any characters from the name that might cause problems, like spaces or special symbols. Only letters, numbers, underscores, hyphens, and dots are kept.

#### Step 4: Download the ZIP File

The computer sends the ZIP file to the teacher's computer. The teacher sees a pop-up asking if they want to save the file. The teacher clicks Save.

#### Step 5: Delete Temporary Files

After the download is complete, the computer automatically deletes the ZIP file from the server. This keeps the server clean and saves storage space.

The teacher's copy on their computer is not affected. Only the server copy is deleted.

### Real-World Example

Mr. Gupta is the class teacher of Class 10. He has 42 students. He needs printed cards for the parent-teacher meeting on Saturday.

Mr. Gupta opens the student list. He clicks the checkbox next to each student's name. He selects all 42 students.

He clicks "Bulk Generate." The computer processes all 42 students. In about 10 seconds, a file called "Cards_Class10_Term1.zip" appears in his Downloads folder.

Mr. Gupta opens the ZIP file. Inside, he finds 42 individual PDF files, each named after a student. For example: "Aarav_Patel_Card.pdf", "Priya_Sharma_Card.pdf", and so on.

Mr. Gupta takes the ZIP file to a printing shop. The shop prints all 42 cards. Mr. Gupta hands them out at the parent-teacher meeting.

### Why Is There a 50-Student Limit?

Making a PDF uses computer memory and processing power. Making one PDF is easy. Making 100 PDFs at the same time uses a lot of memory. If someone tried to generate PDFs for 200 students at once, the computer might slow down or crash.

The 50-student limit is a safety measure. It keeps the system stable for everyone. If another teacher is also using the system at the same time, this limit prevents one teacher from slowing down the other.

If a class has more than 50 students, the teacher can do two batches. First 50 students, then the remaining students. This is a small inconvenience but it prevents crashes.

## PART 3: Public Card View (No Login Required)

### What Is This?

The Public Card View is a way for anyone to see a student's completed card without logging in to the school system. The viewer just needs a special web address. This is called a URL.

### Who Uses This?

Parents use this the most. When the school sends an email with a link, the parent clicks the link and sees the card on their phone or computer. The parent does not need a username or password.

External evaluators might use this. If the school shares the link with an inspector or evaluator, they can view the card without needing a school account.

Students themselves might use this to view their own completed card.

### What Does the Viewer See?

The viewer sees the same content as the PDF, but displayed as a webpage instead of a PDF file. The card appears in the web browser. The viewer can scroll through all pages, zoom in, and print the page if they want.

The view is read-only. The viewer cannot make any changes or edits. They can only look at the card.

### How Is the Link Shared?

The link can be shared in several ways:

By email: The teacher uses the "Send Email" button in the system. The system sends an email to the parent with the link inside.

By copying: The teacher can copy the URL from the system and paste it into a WhatsApp message, an SMS, or a printed letter.

### Security Note

The only security on this public view is that the URL is hard to guess. The URL contains the student's internal ID number plus some random characters. Nobody can guess the URL by trying different names.

However, there is no password and no login. Anyone who gets the URL can view the card. There is no additional protection.

This means the school should share the URL carefully. Do not post it publicly on social media or on a notice board where anyone can see it. Send it privately through email or direct message.

The email method is more secure because the parent receives the link privately. Sharing the link through WhatsApp to the parent's personal number is also good. But posting the link on the school Facebook page is not safe.

## PART 4: Report Generation (Technical Feature)

### What Is This?

This is a behind-the-scenes technical feature. It is not something the teacher sees or uses directly. It is the computer code that powers the "Generate PDF" and "Bulk Generate" buttons.

When the teacher clicks a button to generate a PDF, the computer sends a request to a special address called an endpoint. The endpoint address is: `/hpc/generate-report`. This endpoint creates the PDF and returns it for download.

### Why Is This Mentioned?

This is mentioned so that technical people (developers) understand how the system works inside. If a developer needs to fix a bug or add a new feature to PDF generation, they need to know about this endpoint.

Regular users do not need to worry about this. Just click the button and the PDF appears.

## PART 5: Card Snapshot (Future Feature)

### What Is the Current Status?

This feature has been designed but NOT built yet. The code for the model (which is a blueprint for the data) exists. But no database table has been created yet. There is no screen in the user interface.

This means the feature does not exist yet. It is planned for a future version of the software.

### What Will the Card Snapshot Do When It Is Built?

The Card Snapshot is a frozen copy of a student's card at the moment it was published. "Frozen" means it can never be changed. It stays exactly the same forever.

Think of it like taking a photograph of the card. The photograph never changes. Even if someone edits the card later, the photograph stays the same.

### Why Is This Useful?

There are three main reasons why this is useful.

#### Reason 1: Comparing Across Years

Without the Card Snapshot: Suppose Aarav's card for Class 5 is published in March 2025. Then in June 2025, a teacher edits Aarav's card to fix a mistake. Now the card looks different. Next year, when Aarav is in Class 6, his new teacher wants to see his Class 5 card. But the Class 5 card has been changed. The new teacher cannot see what the original looked like.

With the Card Snapshot: When Aarav's Class 5 card was published, a frozen copy was saved. Even if someone edits the card later, the snapshot stays the same. The Class 6 teacher can open the snapshot and see exactly what the card looked like when it was published. This helps teachers track progress year by year.

#### Reason 2: Historical Records

Without the Card Snapshot: If someone accidentally deletes Aarav's card or overwrites it with wrong data, the original information is lost forever. There is no backup.

With the Card Snapshot: The snapshot is stored in a separate place. It cannot be deleted or changed. Even if the main card is lost, the snapshot is safe. The school always has a permanent record.

#### Reason 3: Audit and Compliance

Without the Card Snapshot: If a parent disputes what the card said, the school cannot prove what the original card looked like. If an inspector asks to see old cards, the school cannot show them if they were edited.

With the Card Snapshot: The snapshot has a timestamp showing when it was saved. It is permanent. The school can prove: "This is exactly what Aarav's card looked like on March 15, 2025." This is useful for inspections and parent disputes.

### What Needs to Happen to Build This

A developer needs to do three things:

1. Create a database migration. This is like creating a new table in the database. The table will be called `student_hpc_snapshots`. It will store all the frozen copies of cards.

2. Write code so that whenever a card is published, the system automatically creates a snapshot and saves it in the new table. This should happen without anyone having to do anything extra.

3. Build a screen where teachers and admins can view the historical snapshots. This screen will show all snapshots for a student, organized by date. The user can click on any snapshot to view it.

## PART 6: Known Issue - BUG-HPC-016

### What Is the Bug?

There is a known security issue with PDF generation. The bug is called BUG-HPC-016.

When a teacher (or any logged-in user) generates a PDF for a student, the computer does NOT check whether that teacher is allowed to access that student's card.

### What Should Happen?

The computer should check:

Is this teacher the class teacher of this student? If yes, the teacher can generate the PDF.

Is this teacher a subject teacher for this student? If yes, the teacher can generate the PDF.

Is this user a school administrator with school-wide access? If yes, the admin can generate the PDF.

If none of these are true, the computer should deny the request and show an error message: "You do not have permission to generate this card."

### What Actually Happens?

The PDF is generated for any student, regardless of whether the teacher has any relationship to that student. The computer does not check anything.

A teacher from Class 5 could generate a PDF for a student in Class 10. A teacher of Mathematics could generate a PDF for a student they have never taught. Any teacher could generate any student's card.

### Why Does This Matter?

Most teachers are honest and would not misuse this. But it is still a security gap. A dishonest person could use this to view student data they should not see. This is a privacy violation.

The school stores sensitive information on the cards, including parent observations and student self-assessments. This information should only be accessible to people who need to see it.

### What Needs to Be Done?

A developer needs to add an authorization check to the PDF generation code. This is sometimes called a "policy" or a "gate."

The check should verify that the user who is requesting the PDF has a legitimate reason to access that student's data. If the user does not have permission, the request should be denied.

This bug has a priority level that the school should decide. It is a privacy issue, so it should probably be fixed soon.

## PART 7: Important Rules to Remember

### Rule 1: 50-Student Limit

Bulk generation is limited to 50 students per batch. This is a safety measure. If you need to generate PDFs for more than 50 students, do it in multiple batches.

### Rule 2: File Names Are Sanitized

ZIP file names are cleaned up automatically. Any characters that are not letters, numbers, underscores, hyphens, or dots are removed. This prevents problems with different computer systems.

### Rule 3: Bug HPC-016

There is no authorization check on PDF generation. Any authenticated user can generate any student's PDF. This needs to be fixed for security.

### Rule 4: Public Card View Has No Authentication

The public card view is protected only by the URL being hard to guess. There is no password or login. Share the URL carefully. Do not post it publicly.

### Rule 5: Card Snapshot Is Not Built

The Card Snapshot feature is designed but not built. It will allow viewing historical, frozen copies of published cards. This will be added in a future version.

### Rule 6: PDF Data Is Always Latest

When generating a PDF, the computer always uses the latest available data. The attendance is recalculated. The most recent teacher edits are included. The PDF always reflects the current state of the card.

## Summary

The Card Generation feature turns student data into PDF documents that can be printed, saved, or shared. You can generate a PDF for one student or for up to 50 students at once (packed into a ZIP file).

The PDF includes the school header, student information, attendance table, subject assessments, life skills, co-curricular activities, student self-assessment, parent observations, teacher comments, principal signature, and QR code.

The Public Card View allows anyone with the URL to view the card without logging in. The Card Snapshot feature (not built yet) will save frozen copies of published cards for historical comparison.

There is a known security issue (BUG-HPC-016) where the system does not check if the user has permission to generate a PDF for a specific student. This needs to be fixed.
