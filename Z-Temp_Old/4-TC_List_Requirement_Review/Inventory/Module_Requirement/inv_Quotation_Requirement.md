# Quotations / RFQs — Business Requirements

## What This Screen Does

The Quotations (RFQ) screen manages vendor price quotes against approved Purchase Requisitions. Each quotation belongs to one vendor and references a PR (or can be created standalone). Quotations capture vendor pricing and lead times, and serve as the basis for creating Purchase Orders.

This is the second tab (`?tab=quotations`) of the Procurement page at `/inventory/procurement`.

## When This Screen Is Used

- **Vendor Pricing**: Capturing vendor quoted rates for stock items requested via PR
- **Rate Comparison**: Comparing multiple vendor quotations side-by-side for the same PR
- **PO Creation**: Selected quotations are converted to Purchase Orders
- **Direct RFQ**: Creating RFQs without a PR for direct procurement needs

## Key Fields

### Quotation Header
- **RFQ Number** (auto-generated) — Format: RFQ-YYYY-NNNN (e.g., "RFQ-2026-0001")
- **Purchase Requisition** (optional) — FK to `inv_purchase_requisitions.id`; filtered to approved PRs in the view
- **Vendor** (required) — FK to `vnd_vendors.id` (cross-module: Vendor Management)
- **Valid Until** (optional) — Quote validity date
- **Status** (auto-managed) — Enum: `draft`, `sent`, `received`, `expired`, `converted`
- **Notes** (optional) — RFQ notes, max 2000 chars

### Quotation Items
- **Stock Item** (required) — FK to `inv_stock_items.id`
- **Quoted Rate** (required) — Vendor's quoted unit price, DECIMAL(15,2), min 0
- **Lead Time (days)** (optional) — Vendor's promised lead time for this item

## Business Rules

### Status Lifecycle
```
draft ──[send/mark sent]──→ sent ──[mark received]──→ received ──[convert to PO]──→ converted
  │                                                       │
  └──[expire]──→ expired                                  └──[expire]──→ expired
```
- **draft**: Editable, deletable; items can be modified
- **sent**: Awaiting vendor response; can be marked as received
- **received**: Vendor responded with rates; ready for PO conversion
- **converted**: PO has been created from this quotation (auto-set)
- **expired**: Past validity date

### Edit Guard
Only draft quotations can be edited. Received/sent/converted/expired quotations throw DomainException on update.

### Delete Guard
Only draft quotations can be deleted. Received quotations are protected.

### Update Behavior
When an update is performed on a draft quotation, the service:
1. Updates quotaion header fields
2. Deletes all existing items
3. Recreates items from the input (complete replacement)

### Convert to PO
When a received quotation is converted to a PO:
- A new PurchaseOrder is created with vendor_id, pr_id, quotation_id
- PO items are created with rates from quotation items
- Requires `tenant.inventory.purchase-order.create` permission

### Number Generation
RFQ numbers are auto-generated by `PurchaseOrderService::generateRfqNumber()` using format RFQ-YYYY-NNNN.

### Service Layer
Operations go through `QuotationService`:
- `create()`: Generates rfq_number, sets status=draft, creates items, logs activity
- `update()`: Guards draft status, replaces all items (delete + recreate), logs activity
- `delete()`: Guards draft status, soft-deletes, logs activity

### Cross-Module Dependencies
- `pr_id` references `inv_purchase_requisitions` (Inventory module) — FK ON DELETE SET NULL
- `vendor_id` references `vnd_vendors` (Vendor Management module) — validated via `exists` rule
- `item_id` references `inv_stock_items` (Inventory module) — hard FK

## Workflow

1. Staff navigates to Inventory → Procurement → Quotations tab
2. Staff clicks "Add Quotation" to open the create modal
3. Staff selects an approved PR (optional), vendor, and validity date
4. Staff adds items with quoted rates and optional lead times
5. Staff saves → quotation created as Draft
6. Staff can edit/update draft quotations as needed
7. Staff marks quotation as Received when vendor responds
8. Staff converts received quotation to Purchase Order

## Requirements

- MUST display paginated quotations as cards with search and status filter
- MUST authorize via `tenant.inventory.quotation.*` policy gates (5 gates)
- MUST validate store with 8+ rules including nested items array (min:1)
- MUST generate unique rfq_number in format RFQ-YYYY-NNNN
- MUST create quotation with status=draft by default
- MUST create nested items during store
- MUST guard edit/update: only draft quotations can be modified
- MUST guard delete: only draft quotations can be deleted
- MUST mark quotation as received via dedicated endpoint
- MUST convert received quotation to PO (requires PO create permission)
- MUST support soft-delete lifecycle with restore/force-delete
- MUST show quotation detail page with header info and items table
- MUST show action buttons conditionally based on status and permissions
- MUST log all CRUD operations via activityLog()
