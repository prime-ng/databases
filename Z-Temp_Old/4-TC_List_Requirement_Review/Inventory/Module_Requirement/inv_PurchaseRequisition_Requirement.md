# Purchase Requisitions — Business Requirements

## What This Screen Does

The Purchase Requisitions (PR) screen allows staff to request the purchase of stock items. Each PR belongs to a department, has a priority level, and contains one or more line items with requested quantities. PRs follow a lifecycle: Draft → Submitted → Approved (or Rejected). Approved PRs can be converted to Quotations or Purchase Orders.

This is the first tab (`?tab=prs`) of the Procurement page at `/inventory/procurement`.

## When This Screen Is Used

- **Stock Request**: Department staff request items that need to be procured
- **Approval Workflow**: Submitted PRs go through an approval/rejection process
- **Procurement Initiation**: Approved PRs serve as the basis for vendor quotations and purchase orders
- **Priority Management**: Urgent/high-priority PRs are flagged for faster processing

## Key Fields

### PR Header
- **PR Number** (auto-generated) — Format: PR-YYYY-NNNN (e.g., "PR-2026-0001")
- **Requested By** (auto-set) — Current authenticated user
- **Department** (optional) — FK to `sch_department.id` (cross-module: SchoolSetup)
- **Required Date** (required) — Expected delivery date, must be today or future
- **Priority** (required) — Enum: `low`, `normal` (default), `high`, `urgent`
- **Status** (auto-managed) — Enum: `draft`, `submitted`, `approved`, `rejected`, `converted`, `cancelled`
- **Remarks** (optional) — Notes or justification, max 2000 chars

### PR Items (Line Items)
- **Stock Item** (required) — FK to `inv_stock_items.id`
- **Quantity** (required) — Requested quantity, DECIMAL(15,3), min 0.001
- **UOM** (required) — FK to `inv_units_of_measure.id`
- **Estimated Rate** (optional) — Estimated unit price for budgetary reference
- **Remarks** (optional) — Line-level notes, max 255 chars

## Business Rules

### Status Lifecycle
```
draft ──[submit]──→ submitted ──[approve]──→ approved ──[auto when PO created]──→ converted
                             │
                             └──[reject]──→ rejected
```
- **draft**: Editable, deletable, items can be modified
- **submitted**: Locked for editing; awaiting approval; can be approved or rejected
- **approved**: Locked; can be referenced by Quotations and POs
- **rejected**: Locked; cannot be resubmitted
- **converted**: Auto-set when a PO is created referencing this PR

### Submit Guard
A PR can only be submitted if:
1. Current status is `draft` (InvalidArgumentException if not)
2. Has at least one item (`items()->count() > 0`) (DomainException if zero)

### Approval Guard
Only submitted PRs can be approved. Approval requires `tenant.inventory.pr.approve` permission (separate from update). On approval, `approved_by` and `approved_at` are recorded.

### Reject Guard
Only submitted PRs can be rejected. Requires the same `tenant.inventory.pr.approve` permission.

### Delete Guard
Only draft PRs can be deleted. Submitted/approved/rejected PRs are protected from deletion.

### Cascade Delete
When a PR is soft-deleted, all its items are cascade-deleted via DB FK (ON DELETE CASCADE).

### Number Generation
PR numbers are auto-generated by `PurchaseOrderService::generatePrNumber()` using format PR-YYYY-NNNN (sequential per year).

### Service Layer
All CRUD + lifecycle operations go through `PurchaseRequisitionService`:
- `create()`: Generates pr_number, sets status=draft, creates nested items with ordering, logs activity
- `update()`: Updates header fields, logs activity
- `delete()`: Guards non-draft status, soft-deletes, logs activity
- `submit()`: Guards draft + items>0, sets status=submitted, logs activity
- `approve()`: Guards submitted, sets status=approved + approved_by + approved_at, logs activity
- `reject()`: Guards submitted, sets status=rejected, logs activity

### Cross-Module Dependencies
- `requested_by` references `sys_users` (System/Auth module)
- `department_id` references `sch_department` (SchoolSetup module) — validated via `exists` rule
- `item_id` references `inv_stock_items` (Inventory module) — hard FK
- `uom_id` references `inv_units_of_measure` (Inventory module) — hard FK

## Workflow

1. Staff navigates to Inventory → Procurement → PRs tab
2. Staff clicks "Add PR" to open the create modal
3. Staff enters required date, selects department (optional), sets priority, adds remarks (optional)
4. Staff selects at least one stock item with qty, UOM, and optional estimated rate
5. Staff saves → PR created as Draft, redirects to show page
6. Staff can add more items on the PR detail page
7. Staff submits the PR when ready (status → Submitted)
8. Authorized approver reviews and approves (or rejects) the PR
9. Approved PRs can be converted to Quotations or POs via the relevant screens
10. Draft PRs can be edited or deleted; submitted/approved/rejected PRs are locked

## Related Screens

- **Quotations** — Second tab on Procurement page; can reference approved PRs
- **Purchase Orders** — Third tab; can reference approved PRs
- **GRNs** — Fourth tab; goods receipt against PO
- **Stock Items** — Items referenced by PR line items
- **Departments** — Cross-module (SchoolSetup); must exist before creating PRs
