# Stock Issues — Business Requirements

## What This Screen Does

The Stock Issues screen executes the physical issuance of stock from a godown. Stock issues can be raised against an approved Issue Request or issued directly (with special permission). Each issue posts outward entries to the stock ledger, updates the source IR's issued quantities, and dispatches reorder alerts.

This is the second tab (`?tab=stock-issues`) of the Stock Movement page at `/inventory/stock-movement`.

## When This Screen Is Used

- **Material Issuance**: Physically issuing stock items from a godown to employees/departments
- **IR Fulfillment**: Executing issuance against approved Issue Requests
- **Direct Issue**: Bypassing the IR process for urgent or ad-hoc issues (requires direct permission)
- **Acknowledgment**: Recipient acknowledges receipt of issued items
- **Slip Printing**: Generating a printed Material Issue Slip for record-keeping

## Key Fields

### Stock Issue Header
- **Issue Number** (auto-generated) — Format: SI-YYYY-NNNN (e.g., "SI-2026-0001")
- **Issue Request** (optional) — FK to `inv_issue_requests.id`; NULL for direct issues
- **Godown** (required) — Source godown, FK to `inv_godowns.id`
- **Issued By** (auto-set) — Storekeeper executing the issue
- **Issued To** (optional) — Receiving employee
- **Department** (required) — Receiving department
- **Issue Date** (required) — Date of issue
- **Voucher ID** (nullable) — Accounting voucher; set by StockIssued event (D21)
- **Acknowledged By** / **Acknowledged At** (set on acknowledgment)

### Stock Issue Items
- **Stock Item** (required) — FK to `inv_stock_items.id`
- **Quantity** (required) — Issued quantity, DECIMAL(15,3), min 0.01
- **Unit Cost** (auto-calculated) — From StockValuationService::getIssueRate() per item valuation method
- **Batch Number** (optional) — FIFO batch tracking

## Business Rules

### Two Issue Paths

**1. Execute Issue against IR** (`StockIssueService::executeIssue()`):
- Requires IR status = `approved` (DomainException if not) — BR-INV-010
- Links issue to the IR via `issue_request_id`
- Updates IR item `issued_qty`
- Auto-transitions IR status to `issued` or `partial`

**2. Direct Issue** (`StockIssueService::directIssue()`):
- Bypasses IR entirely
- Requires `tenant.inventory.stock-issue.direct` permission
- `issue_request_id` remains NULL

### Transaction Flow (both paths)
Inside a DB transaction:
1. Creates `StockIssue` with generated `issue_number`
2. For each item:
   a. Resolves `unit_cost` via `StockValuationService::getIssueRate()`
   b. Creates `StockIssueItem`
   c. Posts outward entry to `inv_stock_entries` via `StockLedgerService::postEntry()` (BR-INV-003 negative stock guard)
   d. If linked to IR, increments `IssueRequestItem.issued_qty`
   e. Dispatches reorder alert via `ReorderAlertService::checkAndDispatch()` (BR-INV-011)
3. If linked to IR, updates IR status (issued/partial)
4. Fires `StockIssued` event for Accounting module

### Negative Stock Prevention (BR-INV-003)
`StockLedgerService::postEntry()` for outward entries checks that sufficient stock exists before posting. If balance is insufficient, the transaction is rejected.

### Stock Ledger (BR-INV-014)
All stock entries are IMMUTABLE — append-only. No UPDATE or DELETE after insert. Soft delete only via StockLedgerService guard.

### Acknowledgment
When the recipient acknowledges receipt:
- `acknowledged_by` = current user
- `acknowledged_at` = current timestamp
- No status guard (status column not present in migration)

### Print Slip
Printable Material Issue Slip includes:
- School/institution header
- Issue number, date, issued to employee, godown
- Items table with quantities, unit costs, total values
- Signature section (storekeeper, receiver, accounts)
- Auto-print JavaScript on page load

### Number Generation
Issue numbers generated by `StockIssueService::generateIssueNumber()`: `SI-YYYY-NNNN`.

### Cross-Module Dependencies
- `issue_request_id` references `inv_issue_requests` (Inventory) — FK ON DELETE SET NULL
- `godown_id` references `inv_godowns` (Inventory) — hard FK
- `issued_by` references `sys_users` (System/Auth)
- `issued_to_employee_id` references `sch_employees` (SchoolSetup) — FK commented
- `department_id` references `sch_department` (SchoolSetup) — FK commented
- `voucher_id` references `acc_vouchers` (Accounting, D21) — set via event
- Stock items and stock ledger entries reference `inv_stock_items`, `inv_godowns`

## Workflow

1. Approved Issue Request exists (from tab 1) — or user has direct issue permission
2. Staff navigates to Stock Issues tab (or creates issue via IR show page)
3. System executes the issue against the approved IR (or directly)
4. Stock ledger updated with outward entries, stock balance reduced
5. IR status auto-updated to Issued or Partial
6. Staff views the issue details on show page
7. Staff prints the Material Issue Slip for records
8. Recipient acknowledges receipt of items

## Requirements

- MUST display paginated stock issues in a table with search/filter
- MUST authorize via `tenant.inventory.stock-issue.*` policy gates (4 gates: viewAny, view, create, update)
- MUST support two issue paths: execute against approved IR and direct issue
- MUST guard executeIssue: IR must be approved (BR-INV-010), DomainException if not
- MUST guard directIssue: requires `tenant.inventory.stock-issue.direct` permission
- MUST generate unique issue_number in format SI-YYYY-NNNN
- MUST resolve unit_cost via StockValuationService
- MUST post outward entries to stock ledger in transaction (BR-INV-003)
- MUST update IR item issued_qty and auto-transition IR status
- MUST dispatch reorder alerts (BR-INV-011)
- MUST fire StockIssued event for Accounting module
- MUST support acknowledgment with acknowledged_by and acknowledged_at
- MUST provide printable Material Issue Slip with auto-print
- MUST support soft-delete lifecycle
