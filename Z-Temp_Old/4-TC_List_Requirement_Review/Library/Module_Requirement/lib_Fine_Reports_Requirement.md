# Fine Reports — Business Requirements

## What This Screen Does

The Fine Reports screen provides analytical dashboards and visualizations of library fine collection data. It is a multi-tab reporting interface that includes fine collection analytics, circulation analysis, overdue tracking, acquisition reporting, digital resource usage, and a library performance dashboard. Data is loaded dynamically via AJAX as users switch between tabs and apply filters. Reports are generated by dedicated service classes that aggregate data from fines, payments, transactions, members, and other library tables.

---

## When This Screen Is Used

- When management requests fine collection statistics — total collected, waived, pending
- When tracking overdue trends to identify patterns and improve library policies
- When analyzing which membership types generate the most fines
- When reviewing top defaulters for targeted follow-up
- When generating monthly or quarterly library performance reports for accreditation
- When preparing budget recommendations based on fine collection rates

## Default Data Load

The report index loads with default filters: last 30 days (`start_date` = 30 days ago, `end_date` = today). All report data sections initially return empty/default structures. Actual data is fetched via AJAX when the user activates a tab and applies filters. The report supports multiple filterable tabs: Dashboard, Fine Collection, Circulation, Overdue, Acquisition, Digital, and Analytics.

## Key Fields at a Glance

**Executive Summary (Fine Tab)**
The fine report aggregates total fines issued, total collected, total waived, pending fines, outstanding fines, collection rate percentage, average fine amount, and total number of fine cases within the selected date range. These KPIs provide a high-level financial snapshot.

**Breakdown Analysis**
Fines are broken down by fine type (Late Return, Lost Book, Damaged Book, Processing Fee) showing count, total amount, collected, waived, pending, average amount, and collection rate for each type. An additional breakdown by membership type shows how many members in each category were fined, the percentage of members fined, and the collection rate per category.

**Overdue Slab Distribution**
Overdue cases are grouped into slabs: 1–10 days, 11–20 days, 21–30 days, 31–45 days, and 45+ days, showing case count, total amount, average amount, and percentage distribution for each slab.

**Trend Analysis**
A 12-month trend analysis shows total fines issued and total collected per month, with monthly collection rate percentages. This data is used for month-over-month comparison and seasonal pattern identification.

**Top Defaulters**
The top 10 defaulters list ranks members by pending fine amount, showing member name, membership number, total fines count, total amount, pending amount, and max days overdue. This helps identify members who need intervention.

## Business Rules and Conditions

**Date-Based Filtering**
All report queries are scoped by date range. Default range is the last 30 days. The `start_date` and `end_date` filters apply to `created_at` for fines, `payment_date` for payments, and `waived_at` for waivers.

**AJAX Tab Loading**
Each report tab loads its data independently via AJAX. The initial page load returns empty data structures. When a tab becomes active, an AJAX request fetches the report data from the appropriate service class. This ensures fast page load times even with large datasets.

**Recommendation Engine**
The fine report service generates automated recommendations based on thresholds: if collection rate is below 70%, a HIGH priority recommendation suggests sending reminders. If more than 5 cases are overdue by 45+ days, an URGENT recommendation suggests reviewing for lost book marking.

**Chart Data**
Chart.js data is prepared by `LibChartService` with labels, data arrays, and curated color palettes. Charts include fine-by-type pie charts and trends line charts.

## Workflow Steps

**Viewing Reports**
The librarian navigates to Library → Reports → Fine Reports. By default, the Dashboard tab is active showing KPI cards. The librarian can switch to any other tab (Fine, Circulation, Overdue, etc.) which triggers an AJAX load of that tab's report data.

**Filtering Reports**
The librarian selects a date range (start/end), and optionally filters by membership type, fine type, or category depending on the active tab. Changing filters triggers a refresh of the report data via AJAX, updating charts and summary tables.

**Exporting Data**
An export endpoint exists for fine collection data (`report.fine-collection.export`) but returns a "not yet implemented" message in the current codebase.

## Requirements

**Controller:** `Modules\Library\Http\Controllers\LibFineReportController`
**Services:** `LibFineReportService` (fine collection aggregation), `LibCirculationReportService`, `LibOverdueReportService`, `LibAcquisitionReportService`, `LibDigitalReportService`, `LibDashboardReportService`, `LibAnalyticsReportService`, `LibChartService`
**Models:** Uses `LibFine`, `LibFinePayment`, `LibFineType`, `LibMember`, `LibMembershipType`, `LibLibraryStatusMaster`
**Policy:** Uses `Gate::authorize('tenant.lib-fines.viewAny')` for fine reports; `Gate::authorize('tenant.lib-reading-behavior-analytics.viewAny')` for analytics reports
**Route:** `reports/fine-collection` (index), `reports/advanced-analytics` (analyticsIndex), `reports/fine-collection/export/{format}`, `reports/fine-collection/refresh`

Key controller methods:
- `index(Request)` — Loads all report tab data with empty defaults; AJAX requests to individual service classes per active tab; returns either JSON partials or full report view
- `analyticsIndex(Request)` — Loads advanced analytics reports (reading behavior, collection performance, predictive demand, etc.)
- `export($format)` — Not yet implemented; returns error message
- `refresh()` — Refreshes report data; returns success message

**Report Tabs (in `index()`):**
1. **Dashboard** — KPIs, quarterly trends, highlights/concerns/recommendations, budget summary (via `LibDashboardReportService`)
2. **Fine** — Executive summary, fine by type breakdown, fine by membership breakdown, overdue slab analysis, top defaulters, trends (via `LibFineReportService`)
3. **Circulation** — Issues/returns/renewals KPIs, circulation by day, by membership, top books, category analysis, hourly patterns (via `LibCirculationReportService`)
4. **Overdue** — Total overdue cases, total fine amount, avg overdue days, by range, detailed list, frequent offenders, recovery actions (via `LibOverdueReportService`)
5. **Acquisition** — Budget summary, predictive demand, high-priority replacements, gap analysis, collection performance (via `LibAcquisitionReportService`)
6. **Digital** — Total resources, new this month, views/downloads, top resources, usage by membership, license tracking, device analysis (via `LibDigitalReportService`)

## How This Screen Works — Logic Flow (Non-Technical)

The Fine Reports screen is a multi-tab dashboard. When the librarian opens it, they see a default Dashboard tab with summary statistics. Each tab has its own set of filters (date range, membership type, fine type, etc.) and loads data on demand via AJAX — meaning the page loads quickly, and data appears when the tab is clicked. The Fine tab shows total fines collected, waived, and pending, with breakdowns by fine type and membership type. A pie chart visualizes the proportion of each fine type. A trend line chart shows collection patterns over 12 months. The Overdue tab groups overdue cases by severity (1–10 days, 11–20 days, etc.). The system automatically generates recommendations: if collection rate drops below 70%, it suggests sending reminders; if there are many long-overdue cases, it suggests reviewing them for lost-book status. All data can be refreshed to get the latest numbers.

## Validate Before Save

This screen is read-only — there are no save operations. Filter inputs are validated by the service layer as query parameters:

**Filters (applied across all tabs):**
- `start_date` — Date string (default: 30 days ago)
- `end_date` — Date string (default: today)
- `membership_type` — Optional filter by membership type name
- `fine_type_id` — Optional filter by fine type (Fine tab)
- `category_id` — Optional filter by book category (Circulation/Acquisition tab)
- `overdue_range` — Optional filter by overdue day range (Overdue tab)
- `budget_range` — Optional filter by budget range (Acquisition tab)
- `resource_type` — Optional filter by digital resource type (Digital tab)

## Success Scenarios

1. The librarian opens Fine Reports, sets date range to current quarter, and views the Fine tab. The system displays: total fines ₹12,450, collected ₹9,800 (78.7%), waived ₹1,200, pending ₹1,450. A pie chart shows Late Return = 72%, Lost Book = 18%, Damaged = 10%. A trend line shows increasing fine collection over the last 3 months.
2. The librarian switches to the Overdue tab. The system shows 23 overdue cases: 8 in the 1–10 day slab, 7 in 11–20, 4 in 21–30, 2 in 31–45, and 2 in 45+ days. The system recommends reviewing the 2 cases overdue by 45+ days for lost-book marking.
3. The Principal requests year-end fine statistics. The librarian sets the date range to the full academic year and exports the data (export endpoint currently pending implementation, so the librarian captures screenshots).

---

## Failure Scenarios

1. The librarian clicks Export, but the export feature is not yet implemented. The system returns an error message: "Fine collection export is not yet implemented."
2. An AJAX request for the Overdue tab fails due to a server timeout. The tab shows "No data available" until the librarian clicks Refresh.
3. The date range filter is set to a future date, resulting in zero data. The report shows all KPIs as 0 and all charts as empty.
