# tpt_FeeLog_TcList

## Module: Transport → Student Route Fees Management → Fee Log

---

## 1. Feature Information

| Item | Details |
|------|---------|
| Module | Transport |
| Tab Group | Student Route Fees Management |
| Feature | Fee Log (Student Pay Log) |
| URL(s) | `/std-route-Fees-mgmt` (index via tab), `/student-pay-log/{id}` (destroyData DELETE) |
| Controller | `Modules\Transport\Http\Controllers\StudentRouteFeesController@index()` (tab data provider) |
| Tab Container Controller | `Modules\Transport\Http\Controllers\StudentRouteFeesController@index()` |
| Model | `Modules\Transport\Models\StudentPayLog` — table: `std_student_pay_log` |
| Validation | No dedicated Form Request — inline validation in `TptStudentFineDetailController::destroyData()` uses `findOrFail` |
| Permissions | `tenant.student-pay-log.viewAny` (tab/body visibility), `tenant.fine-detail.delete` (controller `Gate` in `destroyData()`), `tenant.student-pay-log.delete` (blade delete button) |
| Soft Deletes | Yes (`StudentPayLog` uses `SoftDeletes` trait) |
| Activity Log | `StudentPayLog` itself is not activity-logged (log-of-logs). However, all parent controllers (`FeeMasterController`, `FeeCollectionController`, `TptStudentFineDetailController`, `FineMasterController`) call `activityLog()` on their own records after every CRUD operation — 19 calls total across 4 controllers. |

---

## 2. Pre-conditions

- Required permissions: `tenant.student-pay-log.viewAny`, `tenant.student-pay-log.delete`
- Required seed data: At least one `StudentPayLog` record with `module_name = 'Transport'` (created automatically by FeeMaster/FeeCollection/FineDetail CRUD actions)
- Test user must have above permissions (default admin user)
- Tenant context must be initialized via `tenancy()->initialize()`
- Dusk environment variables: `DUSK_TENANT_URL`, `DUSK_ADMIN_EMAIL`, `DUSK_ADMIN_PASSWORD`
- The Fee Log tab is loaded as part of StudentRouteFeesMgmt — URL `/std-route-Fees-mgmt?tab=fee_log` loads `StudentRouteFeesController@index`
- StudentPayLog records are auto-generated by FeeMaster, FeeCollection, and FineDetail controllers — no manual creation form exists

---

## 3. Default Data Load

When the page loads via `StudentRouteFeesController@index()` (GET `/std-route-Fees-mgmt`):

| Data | Source | Query | Filters | Pagination |
|------|--------|-------|---------|------------|
| Student Pay Logs Grid | `StudentRouteFeesController@studentPayLogQuery()` | `StudentPayLog::query()->where('module_name', 'Transport')` with `with(['student', 'academicSession.academicSession'])` | `activity_type`, `date`, `reference_table` | 10/page via `->paginate(10)->withQueryString()` |
| Fee Log Tab Partial | view: `transport::logs.index` | Included via `@include('transport::logs.index')` | Uses `$studentLogs` variable | As above |

## 4. Test Data Strategy

- **Test data generation**: StudentPayLog records are auto-created by the following controller actions:
  - `FeeMasterController@store()` → `activity_type: 'fee_master_created'`
  - `FeeMasterController@update()` → `activity_type: 'fee_master_updated'`
  - `FeeMasterController@destroy()` → `activity_type: 'fee_master_deleted'`
  - `FeeMasterController@restore()` → `activity_type: 'fee_master_restored'`
  - `FeeMasterController@forceDelete()` → `activity_type: 'fee_master_force_deleted'`
  - `FeeMasterController@toggleStatus()` → `activity_type: 'fee_master_status_changed'`
  - `FeeCollectionController@store()` → `activity_type: 'fee_collected_create'`
  - `FeeCollectionController@update()` → `activity_type: 'fee_collected_update'`
  - `FeeCollectionController@destroy()` → `activity_type: 'fee_collected_delete'`
  - `TptStudentFineDetailController@update()` → `activity_type: 'fine_deatils_updated'`
  - `TptStudentFineDetailController@destroy()` → `activity_type: 'fine_details_deleted'`
  - `TptStudentFineDetailController@restore()` → `activity_type: 'fine_master_restored'`
  - `TptStudentFineDetailController@forceDelete()` → `activity_type: 'fine_master_deleted'`
- **Test strategy**: Perform CRUD on FeeMaster/FeeCollection/FineDetail → Verify corresponding StudentPayLog created
- **Pre-test cleanup**: Delete created pay logs by reference_id
- **Log deletion**: `TptStudentFineDetailController@destroyData($id)` deletes a specific StudentPayLog record and returns JSON response

### 8.3 Permission Chain for Delete Flow

```
User clicks Delete button in Fee Log tab
  → Blade @canany('tenant.student-pay-log.delete') — if false, button NOT rendered
  → JS fires AJAX DELETE to /student-pay-log/{id}
  → Route: delete('student-pay-log/{id}', [TptStudentFineDetailController::class, 'destroyData'])
  → Controller Gate::authorize('tenant.fine-detail.delete') — if false, 403 returned
  → StudentPayLog::findOrFail($id) — if no record, 404
  → $log->delete() — soft delete
  → JSON response {status: true, message: 'Log deleted successfully'}
```

**Note**: Two different permissions guard this flow:
- `tenant.student-pay-log.delete` — controls **UI visibility** (Blade)
- `tenant.fine-detail.delete` — controls **controller access** (Gate)

## 13. Risk Assessment & Mitigation

### 13.1 Risk Matrix

| Risk ID | Risk Description | Likelihood | Impact | Severity | Mitigation |
|---------|-----------------|-----------|--------|----------|------------|
| RSK-01 | StudentPayLog records not created due to parent controller DB transaction rollback | Low | High | Medium | FeeCollectionController@store uses DB::transaction; if create fails, pay log is also rolled back. Mitigation: Verify pay log creation order — pay log is created AFTER fee collection record within the same transaction |
| RSK-02 | Accounting service failure (RemoteEntryService) appears as error but does not rollback payment | Medium | Low | Low | Try-catch at L173-L179 explicitly prevents rollback. Logs error. Payment still completes. Mitigation: Monitoring/alert on `RemoteEntryService` failures |
| RSK-03 | Empty store() method in TptStudentFineDetailController leaves users with no feedback | High | Medium | High | Any user with `tenant.fine-detail.create` permission sees a blank page or no-op form submission. Mitigation: Either implement the method or remove the create route/button |
| RSK-04 | Fine detail restore/forceDelete logs wrong reference_table ('tpt_fine_master' instead of 'tpt_fine_details') | High | Low | Medium | Audit trail shows incorrect reference table for fine detail operations. Mitigation: Correct the reference_table strings in TptStudentFineDetailController@restore and @forceDelete |
| RSK-05 | Fee master update does NOT refresh status (missing refreshFeeMasterStatus call) | Medium | Medium | Medium | FeeMasterController@update skips status recalculation. Fee master amount changes without status update. Mitigation: Add `$this->refreshFeeMasterStatus($feeMaster)` to FeeMasterController@update |
| RSK-06 | Fee collection restore/forceDelete do NOT create StudentPayLog | Low | Low | Low | Inconsistent behavior vs FeeMasterController which creates pay logs on restore/forceDelete. Mitigation: Either add pay log creation for consistency or document as intentional |
| RSK-07 | Soft-deleted student cascades to delete StudentPayLog records | Medium | Medium | Medium | DDL CASCADE on student_id FK. If a student is accidentally deleted, all their payment history is lost. Mitigation: Ensure student deletion has confirmation + backup workflow |
| RSK-08 | Performance degradation with large pay log volume | Low | Medium | Low | 5 DB indexes mitigate query performance. Pagination limits to 10/page. Without indexes, WHERE module_name='Transport' scans full table. Mitigation: Indexes already defined (BC-BIZ-08) |

### 13.2 Failure Mode Analysis

| Component | Failure Mode | Observable Symptom | Recovery |
|-----------|-------------|-------------------|----------|
