## 2. Pre-conditions

- Required permissions: `tenant.topic.viewAny`, `tenant.topic.view`, `tenant.topic.create`, `tenant.topic.update`, `tenant.topic.delete`
- Required seed data: At least one active `SchoolClass`, one active `Subject`, one active `Lesson`, one active `TopicLevelType`
- Test user must have all above permissions (default admin user)
- Tenant context must be initialized via `tenancy()->initialize()`
- Dusk environment variables: `DUSK_TENANT_URL`, `DUSK_ADMIN_EMAIL`, `DUSK_ADMIN_PASSWORD`
- For drag-drop tests: At least 2 root topics under the same lesson with different ordinals
- For prerequisite tests: At least 3 topics in the same lesson to establish dependencies
- For import tests: A valid `.xlsx` or `.csv` file with columns: `topic_name`, `ordinal`, `duration_minutes`, `weightage_in_lesson`, `is_assessable`, `is_active`, `description`, `learning_objectives`

## 4. Test Data Strategy

- **Unique suffix**: `now()->format('His') . random_int(100, 999)` via `uniqueSuffix()` method
- **Topic code**: Auto-generated hierarchical code by model `creating` event (e.g., `CLS_SUB_LES_TOP01`)
- **Analytics code**: Auto-generated by combining class/subject/lesson/topic codes
- **Name uniqueness**: Scoped to `(lesson_id, parent_id)` combination
- **Ordinal**: Auto-set to max(ordinal) + 1 for siblings; unique within same parent scope
- **Path**: Auto-generated in `creating` event as `/parentId/TEMP/`, replaced in `created` event with `/topicId/`
- **Level auto-compute**: `prepareForValidation()` sets `level_id`: if parent exists → parent.level+1; else → level 0
- **UUID**: Auto-generated `Str::random(16)` on create (binary 16)
- **Pre-test cleanup**: Delete created topics by UUID before/after tests to avoid collisions
- **JSON fields**: `learning_objectives`, `keywords`, `prerequisite_topic_ids` stored as JSON in DB
- **Drag-drop two-phase**: Phase 1 sets temp ordinals (50000 + index), Phase 2 assigns final parent/level/ordinal

### 4.5 Business Logic

| BC ID | Condition | Expected Behavior |
|-------|-----------|-------------------|
| BC-BIZ-01 | Auto-generate analytics_code | Combining class/subject/lesson/topic code on create |
| BC-BIZ-02 | Auto-set path on creating | `path = /parentId/TEMP/` initially, replaced in `created` event |
| BC-BIZ-03 | Auto-set ordinal | `max(ordinal) + 1` for siblings when not provided |
| BC-BIZ-04 | Change parent updates path | `updateHierarchy()` updates path for moved topic |
| BC-BIZ-05 | Cascade analytics on move | When parent changes via drag-drop, children analytics auto-updated |
| BC-BIZ-06 | Level auto-compute | parent exists → parent.level + 1; no parent → level 0 |
| BC-BIZ-07 | Prerequisite circular check | Topic A cannot require B if B requires A; topic cannot require itself |
| BC-BIZ-08 | Destroy uses forceDelete | `destroy()` calls `forceDelete()` not soft delete |
| BC-BIZ-09 | Delete blocked by quizzes | `Quiz::where('scope_topic_id', $id)->exists()` → 500 |
| BC-BIZ-10 | Delete blocked by children | `Topic::where('parent_id', $id)->exists()` → 500 |
| BC-BIZ-11 | Toggle release status | `TopicReleaseControlService` handles schedule/lesson/sync_all types |
| BC-BIZ-12 | Import file validation | Pre-validates each row, returns error file on failure |
| BC-BIZ-13 | Import session storage | Validated file stored in `storage/app/public/imports/`, filters in session |
| BC-BIZ-14 | Import execution | `startImport()` runs `TopicImport`, returns create/skip counts |
| BC-BIZ-15 | Drag-drop two-phase update | Phase 1: temp ordinals 50000+N; Phase 2: final parent/level/ordinal |
| BC-BIZ-16 | UUID auto-generation | `Str::random(16)` on `creating` event |
| BC-BIZ-17 | Soft-delete cascading | Model `deleting` event cascades to children, competencies, syllabus schedules |
| BC-BIZ-18 | Restore does not cascade | Children remain deleted after parent restore |
| BC-BIZ-19 | Screen loads via SyllabusController@master() at GET /syllabus/master with master tab group | Navigating to GET /syllabus/master with appropriate permissions loads the Master tab group; this screen's grid data is fetched and displayed |
