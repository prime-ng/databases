## 2. Pre-conditions

- Required permissions: `standard-timetable.viewAny`, `standard-timetable.manualPlace`, `standard-timetable.delete`
- Required seed data: At least one active `AcademicTerm`, one active `TimetableType`, one active `PeriodSet` with at least one `ClassTimetableType` record linking the term+type to a `period_set_id`
- Required system data: At least one active `SchoolDay`, one active `ClassSection` with class+section, one active `Activity`, one active `Room`, one active `TimetableCell` record for meaningful dashboard stats
- Test user must have all above permissions (default admin user or user assigned via role)
- Tenant context must be initialized via `tenancy()->initialize()`
- Dusk environment variables: `DUSK_TENANT_URL`, `DUSK_ADMIN_EMAIL`, `DUSK_ADMIN_PASSWORD`

---

## 3. Default Data Load

When the dashboard loads via `StandardTimetableController@index()` (`GET /standard-timetable`), the following data is fetched:

| Data | Source | Query | Filters | Pagination |
|------|--------|-------|---------|------------|
| Dashboard Stats | `index()` | `Timetable::count()`, `Timetable::whereNotNull('published_at')->count()`, `Timetable::whereNull('published_at')->count()`, `Activity::where('is_active',true)->count()`, `ClassSection::where('is_active',true)->count()`, `TimetableCell::count()`, `SchoolDay::where('is_active',true)->count()`, `PeriodSet::where('is_active',true)->count()`, `TimetableType::where('is_active',true)->count()`, `Room::where('is_active',true)->count()` | `is_active=true` where applicable | None (single agg rows) |
| Recent Timetables | `index()` | `Timetable::with(['academicTerm','timetableType'])->withCount('cells')->orderByDesc('updated_at')->limit(5)` | None | Limit 5 |
| Coverage Matrix | `index()` | Derived from `$recentTimetables` collection — maps `name`, `type`, `term`, `cells`, `status`, `updated` | None | Per recent timetables (max 5) |
| Menu Pages | `index()` | Hard-coded array of 6 navigation cards with route names | Route existence check | None |

---

## 4. Test Data Strategy

- **Stat cards**: Seed `tt_timetables` records with varying `status` and `published_at` values — some published (`published_at IS NOT NULL, status='PUBLISHED'`), some draft (`published_at IS NULL, status='DRAFT'`), some GENERATED
- **Recent timetables**: Seed at least 5 timetables with staggered `updated_at` timestamps to verify ordering
- **Create timetable**: Use `POST /standard-timetable/create-timetable` with JSON body containing `name`, `academic_term_id`, `timetable_type_id`
- **Period set resolution**: Ensure `ClassTimetableType` records exist linking the target `academic_term_id` + `timetable_type_id` to a `period_set_id`
- **Code generation**: Auto-generated by controller as `'MT_' . now()->format('Ymd_His') . '_' . Str::random(4)`
- **Delete timetable**: Use `DELETE /standard-timetable/delete-timetable/{id}` via AJAX; only DRAFT timetables can be deleted
- **Pre-test cleanup**: Delete created timetables by ID or code before/after tests to avoid collisions
- **Empty state**: Create a tenant with zero timetable records to test empty UI state
