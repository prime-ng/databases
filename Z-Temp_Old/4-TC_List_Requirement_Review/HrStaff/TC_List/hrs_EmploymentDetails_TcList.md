## 2. Pre-conditions

- User must be logged in with the `hrs.employment.manage` permission (or be the employee viewing own record, though the controller gate requires the permission)
- At least one employee record must exist in `sch_employees` for testing (created via SchoolSetup)
- Dusk environment variables: `DUSK_TENANT_URL`, `DUSK_ADMIN_EMAIL`, `DUSK_ADMIN_PASSWORD` must be configured

---

## 3. Default Data Load

`EmploymentController::show()` loads the employee via route-model-binding and queries `EmploymentDetail::where('employee_id', $employee->id)->first()`. If no record exists, the view displays an empty create form. If a record exists, it displays the edit form with pre-filled data.

| Data | Source | Query | Filters | Pagination |
|------|--------|-------|---------|------------|
| Employment Detail | `show()` | `EmploymentDetail::where('employee_id', $employee->id)->first()` | None | None |
| Employment History | `history()` | `EmploymentService::getHistory($employee->id)` | `is_active = true`, ordered by `effective_date` DESC, `created_at` DESC | None |

---

## 4. Test Data Strategy

- Create employee records via SchoolSetup module (direct DB insert or UI)
- Create an `EmploymentDetail` record directly in DB to test the "already exists" guard on store
- Use consistent test values: contract_type = "permanent", notice_period_days = 30, bank_ifsc of exactly 11 characters
- For history: create an initial record then update a field (triggers automatic history entry)
- Pre-test cleanup: truncate `hrs_employment_details` and `hrs_employment_history`
