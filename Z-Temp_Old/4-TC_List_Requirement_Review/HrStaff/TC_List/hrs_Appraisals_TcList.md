## 2. Pre-conditions

- Required permissions: `hrs.appraisal.manage` (HR), `hrs.appraisal.self` (employee), `hrs.appraisal.review` (reviewer)
- Required seed data: At least one active `Employee`, one active `AppraisalCycle` (draft), one active `KpiTemplate` with items, one active `OrganizationAcademicSession`
- Create at least 2 employees: one as appraisee, one as reviewer (with reporting hierarchy or manual assignment)
- For each test scenario: generate appraisal records for a cycle first
- Dusk environment variables: `DUSK_TENANT_URL`, `DUSK_ADMIN_EMAIL`, `DUSK_ADMIN_PASSWORD`

---

## 3. Default Data Load

When the page loads via `HrMenuController@appraisalsIncrements()` (GET `/appraisals-overview?tab=appraisals`):

| Data | Source | Query | Filters | Pagination |
|------|--------|-------|---------|------------|
| Appraisals Grid | `AppraisalController@index()` | `Appraisal::with(['employee', 'cycle', 'reviewer'])->active()` | Role-based: HR=all, reviewer=own+assignments, employee=own | 25/page |

> **Data Source:** Appraisal records are generated by `AppraisalController@generate()` which creates them for all active employees in a cycle.

---

## 4. Test Data Strategy

- Generate appraisals for a cycle with known KPI template items (at least 3 items with defined weights)
- Create appraisals in each status (draft, submitted, reviewed, finalized) for different test scenarios
- For role-based tests: login as HR user, as reviewer user, and as employee user
- For rating computation: use KPI items with exact weights (e.g., 40, 35, 25) and known ratings to verify computed overall rating
- Pre-test cleanup: Remove generated appraisals by cycle_id after tests
