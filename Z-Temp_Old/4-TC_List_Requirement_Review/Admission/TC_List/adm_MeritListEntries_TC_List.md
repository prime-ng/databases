# adm_MeritListEntries — Test Case List & Business Conditions

**Module:** Admission (CODE `ADM`, prefix `adm_`) · **Feature:** Merit List Entries (Ranked Candidates)
**DB scope:** TENANT-side (`adm_merit_list_entries`) · **Test style:** Browser Dusk
**Primary table:** `adm_merit_list_entries` · **Module URL prefix:** `/admission/merit-lists/{id}`
**Test file:** `adm_MeritListEntries_TestCas.php`

Controller: No direct CRUD — entries are generated by `MeritListService::computeScores()` and read-only from UI

Routes: Read-only through merit list show page

---

## 1. Business Conditions

### BC-DB — Schema
| ID | Condition | Source |
|----|-----------|--------|
| BC-DB-01 | Table `adm_merit_list_entries`: id (BIGINT PK AI), merit_list_id (BIGINT UNSIGNED FK → adm_merit_lists ON DELETE CASCADE), application_id (BIGINT UNSIGNED FK → adm_applications ON DELETE RESTRICT), merit_rank (SMALLINT UNSIGNED NOT NULL), composite_score (DECIMAL 6,2 NULL), entrance_score (DECIMAL 6,2 NULL), interview_score (DECIMAL 6,2 NULL), academic_score (DECIMAL 6,2 NULL), sibling_bonus_applied (TINYINT 1 DEFAULT 0), merit_status (ENUM('Shortlisted','Waitlisted','Rejected') DEFAULT 'Shortlisted'), is_active, created_by, updated_by, created_at, updated_at, deleted_at. Indexes: idx_adm_mle_list, idx_adm_mle_rank, idx_adm_mle_app, idx_adm_mle_status, idx_adm_mle_score | DDL |
| BC-DB-02 | Model `MeritListEntry`: SoftDeletes, casts: composite_score/entrance_score/interview_score/academic_score→decimal:2, sibling_bonus_applied→boolean, is_active→boolean. Relations: meritList() belongsTo, application() belongsTo, allotment() hasOne | Model |

### BC-VAL — Validation
| ID | Condition | Source |
|----|-----------|--------|
| BC-VAL-01 | System-generated only — no direct create/update forms | Design |

### BC-AUTH — Authorization
| ID | Condition | Source |
|----|-----------|--------|
| BC-AUTH-01 | Read-only: visible to users with `tenant.adm-merit-list.view` | Policy |

### BC-BIZ — Business Logic
| ID | Condition | Source |
|----|-----------|--------|
| BC-BIZ-01 | Entries generated by MeritListService::computeScores() — idempotent (deletes & recreates) | Service |
| BC-BIZ-02 | Ranked by composite_score DESC, tiebreak by application_no ASC | Service |
| BC-BIZ-03 | merit_status: Shortlisted (rank ≤ seat_capacity), Waitlisted (rank > seat_capacity but ≥ cutoff), Rejected (< cutoff) | Service |
| BC-BIZ-04 | Sibling bonus applied when is_sibling=true and sibling_bonus_score > 0 | Service |
| BC-BIZ-05 | Displayed as ranked table: Rank, Application No, Student Name, Scores, Sibling Bonus flag, Status, Allotment action | View |
| BC-BIZ-06 | Status badges: Shortlisted=success, Waitlisted=warning, Rejected=danger | View |

### BC-EDG — Edge Cases
| ID | Condition | Source |
|----|-----------|--------|
| BC-EDG-01 | No entries after compute (no eligible applications) → empty table | Service |
| BC-EDG-02 | Bonus applied column shows checkmark for bonus recipients | View |
| BC-EDG-03 | Re-compute deletes all existing entries before inserting new ones | Service |
