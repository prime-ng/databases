# Known Test-Failure Constraints (MUST FOLLOW)

**Referenced by:** `03_Testcase_Creator_Agent_Prompt.md`. The agent MUST read this before generating any PHP test, and obey it.
**Provenance:** distilled from a peer test agent's hard-earned constraints, then **verified against this codebase** (`prime_ai`, `prime_testing`, consolidated DDLs) on 2026-07-09. See `Testing_Prompt/Phase1_Verification_Harness_Results.md` for the evidence table. **Only verified items are stated as rules here.** Two of the peer agent's constraints were found FALSE here and are inverted below (marked ⚠️).

> Golden principle: these are guardrails against *false* test failures (tests that fail for environmental/harness reasons, not real defects). When a constraint below conflicts with what you observe in the real source at generation time, trust the source and note the discrepancy.

## A. Tenancy & test style  *(verified: H1, H10)*

1. **Follow the module's committed sibling for style AND tenancy helper.** Browser-Dusk features (e.g. `Class`) use a private `initializeTenantContext()`; HTTP feature-test features (e.g. `HrStaff`) use `initTenant()` + `DatabaseMigrations` + `actingAs()`. The `DuskTestCase` base class provides **no** init method — the test file defines its own. Mirror the nearest same-module sibling.
2. **Resolve the tenant via `Modules\Prime\Models\Domain`** (host → `tenancy()->initialize($domain->tenant)`). **Never** use `$this->artisan('tenancy:init')` (does not work in tests) and **never** `\App\Models\Tenant` (class does not exist — the model is `Modules\Prime\Models\Tenant`, table `prm_tenant`).
3. **Always guard teardown:** `if (function_exists('tenancy') && tenancy()->initialized) { tenancy()->end(); }`.
4. **Prime-side vs tenant-side (toggle tenancy scaffolding):** determine from the DDL header comment (`Database: tenant_db` vs `prime_db`) and table prefix — central `prm_*` and central `sys_*` live in `prime_db` (no tenant init needed); module-prefixed tables (`bha_`, `acc_`, `hrs_`, `sys_*` tenant copy, etc.) are per-tenant (require tenant init). Emit tenancy `setUp/tearDown` **only** for tenant-side features.

## B. Users & factories  *(verified: H2, H2b [corrected at Gate 4], H3)*

5. **Tests run in the `prime_testing` runner, which HAS `App\Models\User`** — and this is the model the golden `Class` reference, the `DuskTestCase` base class, and the committed `HrStaff` sibling all use. It has `HasFactory` + a dynamic `$table` bound to `sys_users` in testing, and a runner `UserFactory` at `prime_testing/database/factories/UserFactory.php`. **Default to `use App\Models\User;` + `User::factory()->create([...])` to match the sibling.** *(Correction: the earlier "App\Models\User does not exist" note was based on checking the APP repo `prime_ai` — but tests execute in the RUNNER repo `prime_testing`, where it exists. The peer agent's "never App\Models\User" rule does not apply here.)*
6. **Use a module User model only when the feature's service/type-hints require it.** `Modules\Prime\Models\User` and `Modules\SchoolSetup\Models\User` exist in `prime_ai` (both have `HasFactory` and `password` fillable). Switch to one of these only if a Service or Policy type-hints it; otherwise stay on `App\Models\User` to match the sibling.
7. ⚠️ **`password` IS fillable here** on every User model (cast `'password' => 'hashed'`). *(The peer agent's "password not fillable → use direct assignment" rule is FALSE in this codebase — do not apply it.)* Create users via the factory or mass-assignment.
8. **`sys_users` real columns (verified):** `emp_code VARCHAR(20) NOT NULL UNIQUE`, `prefered_language INT UNSIGNED NOT NULL` (FK → `glb_languages`; note the misspelling "prefered"), and ⚠️ **`user_type ENUM('PRIME','EMPLOYEE','TEACHER','STUDENT','PARENT','OTHER') NOT NULL` DOES exist** in tenant `sys_users` *(the peer agent's "user_type does not exist" is FALSE here)*. The runner `UserFactory` sets `emp_code` + `prefered_language` but **may not set `user_type`** — pass a valid `user_type` (e.g. `'EMPLOYEE'`) in the `factory()->create([...])` override when the column is required and the factory omits it.
9. **`emp_code` ≤ 20 chars.** Unique suffix pattern: `'_' . uniqid()` (~14 chars). Never `uniqid().'_'.date('YmdHis')` (~28 chars — overflows VARCHAR(20)).
10. **`glb_languages` is a VIEW** (`CREATE VIEW glb_languages AS SELECT * FROM global_master.glb_languages`) referenced by `prefered_language`. Ensure a valid language id exists before creating users, or the FK insert fails.

## C. Soft-delete, media & typed properties  *(verified: H5, U2)*

11. **`forceDelete()` may hit the media table.** Models with `InteractsWithMedia` (spatie/medialibrary) query the media table on force-delete; **this project uses `sys_media`** (INT UNSIGNED PK), not the default `media`. Always wrap cleanup: `try { $m->forceDelete(); } catch (\Throwable) {}`.
12. **`withTrashed()`/`onlyTrashed()`/`forceDelete()` only if the model uses `SoftDeletes`.** Verify with `in_array(SoftDeletes::class, class_uses_recursive(Model::class))`; otherwise it throws `BadMethodCallException` — document as a DDL/model gap, don't add the trait in the test.
13. **Initialize all typed properties with defaults** (`private ?User $userA = null;`) — `tearDown()` accesses them and throws "must not be accessed before initialization" otherwise.

## D. Assertions & HTTP  *(verified: U1, U3, U4, H8)*

14. **Dusk `Browser` has NO `assertStatus()`.** For status codes use Laravel HTTP test methods (`$this->getJson()/postJson()/putJson()/deleteJson()` → `assertStatus/assertOk/assertForbidden/assertNotFound`). For browser flows verify via `assertPathBeginsWith`, `assertSee`, success/error banners. Dusk also cannot do `.post()/.put()/.delete()` — use HTTP test methods for API/AJAX endpoints.
15. **Always authenticate before validation/negative tests** (`$this->actingAs($user)` before POST) — unauthenticated posts redirect to login and produce no validation errors.
16. **Browse closures don't capture outer variables** — pass them: `$this->browse(function (Browser $b) use ($record) { ... })`.
17. **MySQL 8 `COLUMN_TYPE` variance:** assert schema types with `assertStringContainsString('int', ...)` (or an accepted-types array), never `assertEquals('int unsigned', ...)` — MySQL 8 may report `int` / `binary(16)` etc.
18. **Respect column limits in generated data:** TINYINT ≤ 127; ENUM values must match the DDL **exactly and case-sensitively** (`'text'` ≠ `'Text'` — cross-check FormRequest `in:` against DDL `ENUM`); VARCHAR within declared size.

## E. Environment prerequisites  *(verified: H6, H7)*

19. **⚠️ Target module must be ENABLED.** `prime_testing/modules_statuses.json` currently has **nearly every module `false`** (only `Syllabus` true). A disabled module returns **404 on all routes** (Dusk and HTTP). Before generating runner/prereq notes, state that the target module must be enabled in `modules_statuses.json`; document this as an environment prerequisite in the Validation Report, **not** a test-code fix.
20. **`APP_ENV=testing` for Dusk runs** (bypasses CSRF; else state-changing requests get 419). The runners set it; keep asserting authenticated flows. The `DuskTestCase` base warns when `APP_ENV != testing`.
21. **Prime/central features run on `http://127.0.0.1:8000`, NOT `test.localhost`.** The committed base `PrimeDuskTestCase` (`prm_PrimeDuskTestCase_TestCas.php`) hardcodes `$primeBaseUrl='http://127.0.0.1:8000'` and calls `$this->fail(...)` in `setUp()` if the host isn't `127.0.0.1`. Prime-side (central `prm_*`/`sys_*`, `prime_db`) browser features must extend the module's central base (e.g. Billing → `BillingDuskTestCase`) and use its `authenticateCentral()`/`visitAuthenticated()`/`centralUrl()` chain — do NOT use the tenant `DUSK_TENANT_URL`/`initializeTenantContext()` scaffolding. *(Evidence: prm_PrimeDuskTestCase_TestCas.php:9,18-20.)* `[Codebase-verified]`
22. **Module-local test base classes are filename↔classname-mismatched and only resolve via the preloader.** `tests/Browser/Modules/preload.php` builds `class_alias` from the filename-derived name (e.g. `prm_BillingDuskTestCase_TestCas`) and also stubs missing parents, so a subclass may `extends BillingDuskTestCase` (short alias) even though the physical class is `prm_..._TestCas`. Mirror the sibling's `use ...\BillingDuskTestCase;` + `extends BillingDuskTestCase` verbatim; `php -l` passes regardless (syntax-only), and the alias resolves at runtime. *(Evidence: preload.php:212-241; prm_ConsolidatedPaymentTab_TestCas.php:6-8.)* `[Codebase-verified]`
23. **A module's `routes/api.php` is NOT necessarily registered — verify the module's `RouteServiceProvider::map()` before asserting any module API route exists.** Some modules override `map()` to call only `mapWebRoutes()` (no `mapApiRoutes()`), so a module `apiResource(...)` in `routes/api.php` is never registered even though the file exists. A test assuming such an endpoint is live gets a 404 for a wiring reason, not a defect. When probing a module API, assert with `Route::has('<name>.index')` and/or `method_exists(Controller::class, 'index')` rather than assuming registration; use `$this->getJson()` and accept the dead-route status set `{401,403,404,405,500}` when proving a dead API. *(Evidence: MarksheetGeneration `RouteServiceProvider::map()` calls only `mapWebRoutes()`; `Modules/MarksheetGeneration/routes/api.php` apiResource is unregistered AND the controller lacks index/store/show/update/destroy — audit BUG-MSH-001.)* `[Codebase-verified] [Per-feature-verify]`
24. **Prime/central modules register their WEB routes in the central app `routes/web.php`, NOT in the module's own `Modules/{Module}/routes/web.php` (which may be an empty central-domain stub).** Do not conclude a central module's routes are missing just because its module `routes/web.php` is empty — grep the app-level `prime_ai/routes/web.php` for the route group and assert with `Route::has('<group>.<name>')`. *(Evidence: `Modules/Billing/routes/web.php` only contains an empty `central_domains` group loop; every Billing route — `billing.invoicing-payment.*`, `billing.payment-details`, `billing.consolidated.store`, `billing.billing-cycle.*` — is registered under the `billing.` group in `prime_ai/routes/web.php:322-421`.)* `[Codebase-verified]`

25. **The `activityLog()` helper routes by tenancy state — assert the RIGHT sink for the feature's DB scope.** `app/Helpers/activityLog.php` writes to `Modules\Prime\Models\ActivityLog` (table **`sys_central_activity_logs`**, connection `mysql`) when `tenancy()->initialized` is false (prime/central features), and to `Modules\GlobalMaster\Models\ActivityLog` (tenant table **`activity_logs`**) when tenancy is initialized. Both share the columns `subject_type, subject_id, user_id, event, properties(json), ip_address, user_agent, timestamps` (no soft-delete on either). For **prime-side** features (central `prm_*`/`sys_*`, no tenant init) assert activity via `sys_central_activity_logs`; for tenant-side features use the tenant `activity_logs`. `sys_central_activity_logs` has **no consolidated DDL** in `2-DDL_Tenant_Consolidated/` — its schema comes from a central migration only, so assert it with `Schema::hasTable('sys_central_activity_logs')` (fail-soft guard) plus the model `$fillable`, not a DDL-file `assertStringContainsString`. *(Evidence: app/Helpers/activityLog.php:35-39; Modules/Prime/app/Models/ActivityLog.php:17-32; no `sys_central_activity_logs` CREATE TABLE in `_prime_db_v4.sql`.)* `[Codebase-verified]`

26. **A module's own `Modules/{Module}/database/migrations/` may be EMPTY — real tenant migrations live in `prime_ai/database/migrations/tenant/`.** For MarksheetGeneration the module-local migrations dir holds only `.gitkeep`; all 23 `create_msh_*` migrations are in `database/migrations/tenant/2026_06_16_115725…115747`. Do NOT assert a module-local `MIGRATION_FILE` exists or `assertStringContainsString('Schema::create', …)` against it in `test_01` — it false-fails. Derive schema truth from `Schema::hasTable/hasColumns` + `SHOW INDEX`/`SHOW COLUMNS` against the live tenant DB (and the consolidated DDL), plus the FormRequest file (which does exist under the module). If you want migration-content asserts, resolve the file from `base_path('database/migrations/tenant')` by glob, not the module path. *(Evidence: `Modules/MarksheetGeneration/database/migrations/` = only `.gitkeep`; 23 files under `prime_ai/database/migrations/tenant/`.)* `[Codebase-verified] [Per-feature-verify]`

27. **A migration whose FILENAME says "rename X to Y" may be a no-op — read its BODY, never trust the name.** `database/migrations/tenant/2026_06_15_145407_rename_sys_dropdown_table_to_sys_dropdowns.php` renames `sys_dropdown_table` → `sys_dropdown_table` (same name) under an always-false guard, with a docblock stating the table stays `sys_dropdown_table`. The real runtime table is **`sys_dropdown_table`**, confirmed by `Dropdown::$table`, msh FK `->on('sys_dropdown_table')`, and FormRequest `exists:sys_dropdown_table,id`. This directly contradicts audit note DOC-MSH-002 (which claimed `sys_dropdowns` from the filename alone). Rule: assert the status/dropdown FK target as `sys_dropdown_table`, and generally verify any "renamed" table by its migration body + the Eloquent model `$table`, not the audit or the filename. *(Evidence: rename migration body is `Schema::rename('sys_dropdown_table','sys_dropdown_table')`.)* `[Codebase-verified]`

28. **Some `glb_*` models (global_master tables) are owned by the Prime module but bind to a NON-default connection `global_master_mysql`, and physically live in the `global_master` database — NOT `prime_db`/`mysql`.** Assert their schema truth with `Schema::connection('global_master_mysql')->hasTable/hasColumn(...)` and query/seed them via `Model::on('global_master_mysql')` (or `DB::connection('global_master_mysql')`), or the default-connection lookups return empty/false and the test false-fails. Example: `Modules\Prime\Models\Menu` sets `protected $connection = 'global_master_mysql'; protected $table = 'glb_menus';` while the controller/routes live under the Prime module and central `central.system-config.menu.*` group. Central activity for such features still routes to `sys_central_activity_logs` on the default `mysql` connection (see #25) because tenancy is not initialized. Also note the **consolidated DDL can lag the runtime schema**: `_global_db_v4.sql` `glb_menus` omits `menu_for` and `permission`, yet the model fills and the controller filters on them — use fail-soft `hasColumn` guards rather than DDL-file `assertStringContainsString` for such columns. *(Evidence: Modules/Prime/app/Models/Menu.php:15-17,20-34; `_global_db_v4.sql` glb_menus lines 119-139 has no `menu_for`/`permission`.)* `[Codebase-verified] [Per-feature-verify]`

29. **The runner (`prime_testing`) does NOT contain the app's `Modules/*` PHP SOURCE on disk — app classes autoload via a path mapping, but raw source files are not under the runner root.** So a test that proves a defect by scanning source TEXT (e.g. a stray `// dd($request->all());s` debug comment, a MISSING `in:` enum rule in a controller method, a not-implemented notification) cannot `File::get(base_path('Modules/...'))` — that path does not exist in the runner. Resolve the separate app repo path instead: try `env('MAIN_PROJECT_PATH')`, then `base_path('../prime_ai/<relative>')`, then `dirname(base_path()).'/prime_ai/<relative>'`, and **fail-soft `markTestSkipped()` if none is readable** so partial/CI environments stay green. (Class existence / route registration is still assertable directly — `class_exists()`, `method_exists()`, `Route::has()` — because those resolve through the autoloader; only raw file-text reads need the app-repo path.) *(Evidence: `ls prime_testing/Modules/StudentProfile/app/Http/Controllers/AttendanceController.php` → No such file; the same class is nonetheless usable as `Modules\StudentProfile\...` at runtime.)* `[Codebase-verified]`

30. **The consolidated DDL can diverge from the live migration in BOTH directions for soft-delete and GENERATED columns — always assert these against the live schema (`Schema::hasColumn` / `information_schema`), never the DDL file.** In StudentProfile the DDL spec (`StudentProfile_DDL_v1.6.sql`) OMITS `deleted_at` on `std_health_profiles`/`std_vaccination_records`/`std_student_documents`/`std_student_attendance`, yet the real create-migrations add `$table->softDeletes()` (so the column DOES exist) — while the Eloquent models do NOT use the `SoftDeletes` trait (so `->delete()` still hard-deletes). Conversely the DDL declares `std_student_academic_sessions.current_flag` as `INT GENERATED ALWAYS AS (...) STORED`, but the migration creates a plain `integer('current_flag')->nullable()` (audit BUG-STD-11). Rule: to prove a "generated" column, read `information_schema.COLUMNS.EXTRA` (expect it to NOT contain `GENERATED` when the migration made it plain); to prove soft-delete, combine `Schema::hasColumn(table,'deleted_at')` with `in_array(SoftDeletes::class, class_uses_recursive(Model::class))` and report the two independently — the column and the trait can disagree. Do NOT `assertStringContainsString` against the consolidated DDL for these facts, and do NOT add the trait/generated-column in the test. *(Evidence: `database/migrations/tenant/2026_06_15_151303_create_std_health_profiles_table.php:36` softDeletes; `..._151307_create_std_student_academic_sessions_table.php:19` plain `integer('current_flag')->nullable()`; `StudentProfile_DDL_v1.6.sql` health/vaccination tables have no `deleted_at`, line 222 declares current_flag GENERATED STORED.)* `[Codebase-verified] [Per-feature-verify]`

31. **`Gate::before` grants ALL abilities to Super Admin — authorization NEGATIVE tests must use a NON-super-admin, unpermissioned user or they FALSE-PASS.** `app/Providers/AppServiceProvider.php` registers `Gate::before(fn($user,$ability) => ($user->is_super_admin && $user->super_admin_flag) || $user->hasRole('Super Admin') ? true : null)`. The default Dusk admin (`root@tenant.com`) is typically a Super Admin, so ANY `Gate::authorize(...)`/`->can(...)` check is bypassed for it — a "limited user is blocked" test that logs in as the admin will wrongly report the gate as enforced (403 never fires because the controller was never reached OR the gate short-circuits to allow). To exercise a permission gate, create a fresh user, clear `is_super_admin`/`super_admin_flag` (force-fill 0) AND `syncRoles([])`/`syncPermissions([])`, then `loginAs()` it. Also note: string abilities like `tenant.<res>.<action>` resolve to Spatie-registered permission gates (not the model Policy) — an ability with no matching permission row and no Policy method is DENIED by default, so a limited user gets 403 whether the permission is missing or merely un-granted. When an audit claims a controller's `Gate::authorize` is "commented out", verify against the CURRENT source before asserting 403 — the calls may have been restored since the audit (e.g. StudentProfile GAP-STD-06: audit 2026-06-30 said `StdLeaveController` gates were commented out, but current source has active `Gate::authorize` on all 8 methods). Probe the observed status against a documented set rather than hard-asserting 403. *(Evidence: app/Providers/AppServiceProvider.php:64-73; Modules/StudentProfile/app/Http/Controllers/StdLeaveController.php gates active on index/review/updateReview/edit/update/getStudentsBySection/getApplicationsByStudent/storeRemark.)* `[Codebase-verified]`

32. **To assert real APP source content (gate strings, blade partials, `.bkp`/backup files, FormRequest presence) from the `prime_testing` runner, resolve the file via reflection — `base_path()` points at the RUNNER, not `prime_ai`.** In the runner `base_path()` = `prime_testing`, but application source lives in `prime_ai` (autoloaded via a composer path repo). Guessing the app path or globbing `base_path()` false-fails. Instead anchor on an already-loaded class: `(new \ReflectionClass(Modules\...\SomeController::class))->getFileName()` returns the absolute `prime_ai/Modules/{Module}/app/Http/Controllers/...php`; derive the module root with `dirname($file, 4)` and the app root with `dirname($file, 6)`, then `File::get()`/`glob()` under those. Always wrap in `try/catch` + `markTestSkipped` when the class/file is absent so partial checkouts stay green. This is the robust way to prove source-level audit findings (e.g. `Gate::authorize('tenant.student.*')` present / `school-setup.student.*` absent, `is_super_admin` absent from the edit `_student-login.blade.php`, `edit.blade.bkp` present, only `StudentLeaveTypeRequest.php` under `app/Http/Requests`) — and, combined with #26, to locate central tenant migrations at `dirname($controller,6).'/database/migrations/tenant'` when the module-local `database/migrations/` is empty. *(Evidence: StudentProfile StudentEdit tests `_52/_54/_80/_82/_83` use `ReflectionClass(StudentController::class)->getFileName()` → `Modules/StudentProfile/app/Http/Controllers/StudentController.php`; module-local `database/migrations/` empty, migrations resolved from the app-root tenant dir.)* `[Codebase-verified]`

## Usage in generated artifacts
- The **`{prefix}_{Feature}_TestCas.php` PHP** must comply with A–D.
- The **Validation Report** must list any constraint that shaped the tests and any environment prerequisite (E19/E20).
- When you discover a **new** real failure/fix during generation, append it here (see the feedback-loop rule in `03_`) with an evidence note, so the agent compounds over time.
