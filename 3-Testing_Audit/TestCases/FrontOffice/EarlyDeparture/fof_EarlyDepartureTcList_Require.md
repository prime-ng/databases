## 1. Feature Information

| Field | Value |
|-------|-------|
| Module | FrontOffice (FOF) |
| Feature | EarlyDeparture (Log Early Departure — student mid-day parent pickup) |
| Prefix | `fof_` (verified vs DDL `CREATE TABLE fof_early_departures`) |
| Primary table | `fof_early_departures` |
| Index URL | `/front-office/early-departures` (route `fof.early-departures.index`) |
| Create URL | `/front-office/early-departures/create` (`fof.early-departures.create`) |
| Store | POST `/front-office/early-departures` (`fof.early-departures.store`) → redirects to `/front-office/visitor-management?tab=early-departures` |
| Show / Edit / Update | `.../{earlyDeparture}` (GET show, GET `/edit`, PUT update) |
| Destroy | DELETE `.../{earlyDeparture}` (`fof.early-departures.destroy`) |
| Toggle status | POST/PATCH `.../{earlyDeparture}/toggle-status` (`fof.early-departures.toggleStatus`) — **JSON**, **no activity log** |
| Trash / Restore / ForceDelete | GET `/early-departures/trash/view`, GET `/{id}/restore`, DELETE `/{id}/force-delete` |
| Controller | `Modules\FrontOffice\Http\Controllers\EarlyDepartureController` |
| Service | `Modules\FrontOffice\Services\EarlyDepartureService` (`logDeparture`, `syncAttendance`, `generateDepartureNumber`) |
| Job | `Modules\FrontOffice\Jobs\EarlyDepartureAttSyncJob` (ATT sync retry) |
| Model | `Modules\FrontOffice\Models\EarlyDeparture` (extends `App\Models\BaseModel`, `SoftDeletes`) |
| FormRequest | `EarlyDepartureRequest` (`authorize(): return true` — SEC-FOF-003) |
| Permissions | `frontoffice.early-departure.{view,create,update,delete,restore,forceDelete}` via `Gate::authorize()` string gates (toggleStatus uses `update`) |
| Activity log | `sys_activity_logs` via `Modules\GlobalMaster\Models\ActivityLog` (helper `activityLog()`). Events: **Created** (service), **Updated**, **Deleted** (soft + force), **Restored**. toggleStatus → **none**. |
| CRUD type | Full CRUD + soft-delete lifecycle + ATT-sync FSM (service/job driven) |
| Soft delete | Yes (`deleted_at`; model uses `SoftDeletes`) |
| Pagination | index 25/page (today only); trash 15/page |
| Auto-number | `departure_number` = `ED-YYYYMMDD-NNN`, generated by service with `lockForUpdate()` |
| DB scope | TENANT-SIDE (tenant_db, `fof_*`) → tenancy init in setUp, end in tearDown |

**Index business rule:** the index lists **only today's** departures (`whereDate('departure_time', now()->toDateString())`, ordered `departure_time` desc). Older records are not shown on the index (visible via show/trash by ID).

## 5. Manual Test Steps (workflow / complex flows only)

Simple CRUD/validation cases are fully specified by the Expected Result column in §3. The steps below cover the ATT-sync FSM, the create→sync flow, and permission negatives — where a human tester needs explicit DB / activity-log checks.

### MT-1 — Log an early departure (create → auto-number → ATT sync → activity)

| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Enable FrontOffice in `modules_statuses.json`; `php artisan route:clear` | `/front-office/early-departures` reachable |
| 2 | Log in as an admin with `frontoffice.early-departure.create` | Dashboard loads |
| 3 | Visit `/front-office/early-departures/create` | Form renders; "Departure Number" shows "Auto-generated (ED-YYYYMMDD-NNN)" (readonly) |
| 4 | Select a Student, set Departure Time = now, Reason = Medical, Collecting Person Name, Relation = Father; Submit "Log Departure" | Redirect to `/front-office/visitor-management?tab=early-departures` with success flash "Early departure ED-… logged successfully." |
| 5 | DB check | `SELECT departure_number, att_sync_status, created_by FROM fof_early_departures ORDER BY id DESC LIMIT 1;` → number matches `ED-YYYYMMDD-NNN`; `att_sync_status` = `Failed` if no ATT module (or `Synced` if installed); `created_by` = logged-in user id |
| 6 | Activity check | `SELECT event FROM sys_activity_logs ORDER BY id DESC LIMIT 1;` → `Created` |
| 7 | If ATT module absent | Flash "ATT sync is unavailable … attendance service is not installed." AND `att_sync_status='Failed'`, `att_synced_at` NULL, `updated_by=0` (ORM-FOF-001 — background path writes user 0) |

### MT-2 — ATT-sync FSM (Pending → Failed → retry)

| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Create a departure with no ATT module installed | `att_sync_status='Failed'`; a flash warning; a retry job dispatched (`EarlyDepartureAttSyncJob`) |
| 2 | Inspect the queue | Job present (3 tries, backoff 60/120/300s). **JOB-FOF-001:** the job carries no tenant context and no `$timeout` → on a real queue worker it may run outside tenancy and silently no-op |
| 3 | DB check | `att_sync_status` never left `Pending` after the sync attempt (BR-FOF-013: failure is not silent) |
