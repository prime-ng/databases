# Fine Detail — Requirement Document

## 1. Screen Purpose & Overview

The Fine Detail screen tracks and manages outstanding, paid, and waived late payment fines applied to student transport invoices. It enables accountants to review overdue balances and process late fee waiver adjustments.

---

## 2. Common Business Use Cases

1. **Auditing Late Fines:** An accountant checks a student's late fee penalty after a delayed payment.
2. **Waiving a Fine:** Authorizing a partial or complete late fee waiver because a student was hospitalized, reducing their net outstanding balance.
3. **Auditing Outstanding Dues:** Tracking how many days a fee has been overdue and how much net fine has compiled.

---

## 3. Database Schema & Data Dictionary

All fields map to the `tpt_student_fine_detail` table:

* `id` (INT UNSIGNED): Primary Key, Auto-increment.
* `student_fee_detail_id` (INT UNSIGNED): FK to `tpt_student_fee_detail`. Mapped invoice reference.
* `fine_master_id` (INT UNSIGNED): FK to `tpt_fine_master`. Linked late fee rule policy.
* `fine_days` (TINYINT): Total count of days the payment was delayed beyond the due date and grace buffer.
* `fine_type` (ENUM): Late fee calculation model: 'Fixed' or 'Percentage'.
* `fine_rate` (DECIMAL(5,2)): Numeric rate used for calculations.
* `fine_amount` (DECIMAL(10,2)): Base calculated fine amount generated by the system.
* `waved_fine_amount` (DECIMAL(10,2)): **CRITICAL SCHEMA ALIGNMENT NOTE:** Spelled as `waved_fine_amount` (without the 'i') in the DDL. Represents the waiver amount.
* `net_fine_amount` (DECIMAL(10,2)): Net late fee payable after waiver reductions.
* `Remark` (VARCHAR(512)): Waiver justification notes.
* `created_at` (TIMESTAMP): Creation date-time.
* `deleted_at` (TIMESTAMP): Set for soft deletes.

## 4. Screen Fields & Input Rules

| Field Name (Screen Label) | UI Control Type | Validation Rules & Constraints | Source Database Mapping |
| :--- | :--- | :--- | :--- |
| **Invoice Reference** | Read-only Text | Auto-populated. Links to the outstanding invoice. | `student_fee_detail_id` |
| **Calculated Fine** | Read-only Text | Displays base calculated fine. | `fine_amount` |

| **Waiver Remarks** | Text Area | Required if `waved_fine_amount > 0`. Max 512 chars. | `Remark` |

## 5. Business Logic & Validation Policies

### Waiver Limits
* The waiver amount cannot exceed the calculated fine:
  $$0.00 \le \text{waved\_fine\_amount} \le \text{fine\_amount}$$
* Revisions to waivers are blocked once the parent invoice status is updated to `Paid`.

### Calculations & Mathematical Formulas
* **Net Fine Amount**:
  $$\text{net\_fine\_amount} = \text{fine\_amount} - \text{waved\_fine\_amount}$$
* **Parent Invoice Update**: When a waiver is saved, the parent invoice total in `tpt_student_fee_detail` is updated:
  $$\text{tpt\_student\_fee\_detail.fine\_amount} = \text{net\_fine\_amount}$$
  $$\text{tpt\_student\_fee\_detail.total\_amount} = \text{tpt\_student\_fee\_detail.amount} + \text{net\_fine\_amount}$$

## 6. Detailed Step-by-Step Manual Testing Plan

### Test Case 1: Process Complete Fine Waiver (Happy Path)
1. Go to `/transport/fine-detail` and click "Waiver Action" on a student record (e.g. Bobby, with outstanding fine of ₹80.00).
2. Enter Waiver Amount: `80.00`.
3. Enter Remarks: "Medical emergency waiver".
4. Click Save. Confirm that:
   - Bobby's Net Fine displays as `0.00`.
   - In `tpt_student_fee_detail`, the total payable amount is reduced by ₹80.00.

### Test Case 2: Validate Waiver Bounds
1. Locate Bobby's record with a calculated fine of ₹80.00. Click "Waiver Action".
2. Enter Waiver Amount: `100.00` (exceeding calculated fine).
3. Click Save.
4. Verify validation error: "Waiver amount cannot exceed the calculated fine."

### Test Case 3: Waiver Remarks Requirement
1. Click "Waiver Action" on an overdue record.
2. Enter Waiver Amount: `50.00`.
3. Leave Waiver Remarks blank and click Save.
4. Verify validation error: "Waiver remarks are required for audit trail when waiving a fine."

## 7. Laravel Dusk Automation Test Guidance

### 1. Key Element Selectors
* **Waiver Console Button**: `@waiver-action-btn-1` (dynamic row ID)
* **Calculated Fine Display**: `@fine-amount-display`
* **Waiver Input Field**: `input[name="waved_fine_amount"]`
* **Remarks Input Field**: `textarea[name="Remark"]`
* **Submit Waiver Button**: `@submit-waiver-btn`

### 2. Dusk Integration Test Code Block

```php
namespace Tests\Browser;

use Tests\DuskTestCase;
use Laravel\Dusk\Browser;
use App\Models\User;

class TransportFineDetailTest extends DuskTestCase
{
    public function testFineWaiverAllocationsAndValidations()
    {
        $this->browse(function (Browser $browser) {
            $browser->loginAs(User::find(1))
                    ->visit('/transport/fine-detail')
                    ->waitFor('@waiver-action-btn-1')
                    ->click('@waiver-action-btn-1')
                    
                    // Exceeding amount check
                    ->type('waved_fine_amount', '100.00') // Assume calculated fine is 80
                    ->type('Remark', 'Excuse')
                    ->click('@submit-waiver-btn')
                    ->assertSee('Waiver amount cannot exceed the calculated fine')
                    
                    // Missing remarks check
                    ->type('waved_fine_amount', '50.00')
                    ->type('Remark', '')
                    ->click('@submit-waiver-btn')
                    ->assertSee('Waiver remarks are required')
                    
                    // Correct submission
                    ->type('Remark', 'Approved by Principal')
                    ->click('@submit-waiver-btn')
                    ->pause(1000)
                    ->assertDontSee('@submit-waiver-btn'); // Modal closed
        });
    }
}
```
