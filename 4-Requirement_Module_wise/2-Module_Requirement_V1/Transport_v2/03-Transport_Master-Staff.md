# Staff Master — Requirement Document

## 1. Screen Purpose & Overview

The Staff screen registers and manages the transport crew, including drivers, helpers, and transport coordinators. It tracks essential background check milestones (such as police verification status), government identification credentials, driving experience, and licensing rules. 

A primary objective is to verify that crew members assigned to vehicles (especially drivers) possess active, valid driving licenses and have successfully passed background screenings.

---

## 2. Common Business Use Cases

1. **Onboarding a New Driver:** The administrator registers a new driver, logs their commercial license details, license expiry date, and driving experience.
2. **Checking Helper Police Verification:** The administrator reviews the roster to see if helper background checks are pending, noting warnings for unverified personnel.
3. **QR Code Verification Assignment:** A helper is onboarded, and the system automatically generates a unique QR code used by the helper to clock in via the companion app.

---

## 3. Database Schema & Data Dictionary

All fields map to the `tpt_personnel` table:

* `id` (INT UNSIGNED): Primary Key, Auto-increment.
* `user_id` (INT UNSIGNED): FK to `sys_users` table. Represents system login account.
* `user_qr_code` (VARCHAR(30)): Autogenerated unique QR string.
* `id_card_type` (ENUM): ID card scanner format ('QR', 'RFID', 'NFC', 'Barcode'). Defaults to 'QR'.
* `name` (VARCHAR(100)): Staff full name.
* `phone` (VARCHAR(30)): Contact phone number.
* `id_type` (VARCHAR(20)): Government ID type classification (e.g., 'Aadhaar', 'PAN', 'Passport').
* `id_no` (VARCHAR(100)): Government ID reference number.
* `role` (VARCHAR(20)): Staff role ('Driver', 'Helper', 'Transport Manager').
* `license_no` (VARCHAR(50)): Commercial license number (Driver only).
* `license_valid_upto` (DATE): Validity expiration of driving license (Driver only).
* `assigned_vehicle_id` (INT UNSIGNED): FK to `tpt_vehicle`. Links driver to fleet asset.
* `driving_exp_months` (SMALLINT UNSIGNED): Total driving experience in months (Driver only).
* `police_verification_done` (TINYINT): 0 = Not Done, 1 = Done.
* `address` (VARCHAR(512)): Residential address.
* `is_active` (TINYINT): 0 = Inactive, 1 = Active (Soft delete indicator).
* `deleted_at` (TIMESTAMP): Set for soft deletes.

## 5. Business Logic & Validation Policies

### Driver-Specific Rules
* When **Role** is set to `Driver`, the fields `license_no`, `license_valid_upto`, and `driving_exp_months` must pass validation check:
  $$\text{driving\_exp\_months} \ge 24\text{ months}$$

### Active License Validity
* System prevents assigning any driver to a route roster (`tpt_driver_route_vehicle_jnt`) if:
  $$\text{license\_valid\_upto} \le \text{CURRENT\_DATE()}$$

### Autogeneration of QR Code
* Upon successful onboarding of a staff record, the system generates a unique QR identifier:
  $$\text{user\_qr\_code} = \text{"TPT-" } + \text{ role\_prefix} + \text{ pad\_left(id, 6, '0')}$$
  * This code is saved into `tpt_personnel.user_qr_code`.

namespace Tests\Browser;

use Tests\DuskTestCase;
use Laravel\Dusk\Browser;

class TransportStaffTest extends DuskTestCase

    public function testStaffCreationAndValidationRules()
    {
        $this->browse(function (Browser $browser) {
            $browser->loginAs(User::find(1))
                    ->visit('/transport/driver-helper')

                    ->assertSee('Drivers must have at least 24 months of experience')

                    ->type('driving_exp_months', '36')
                    ->type('license_no', 'LIC-999-COM')

                    ->click('@save-staff-btn')
                    ->assertSee('saved successfully');
        });
    }
}
