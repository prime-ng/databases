# Report: Issued Certificates — Requirement Document

## 1. Screen Purpose & Overview

The **Issued Certificates Report** tab provides administrators with an audit grid containing historical data of all issued certificates. 

The screen allows users to apply filters (by certificate type, class, section, or date range) and download standard Excel/CSV spreadsheet exports for external records keeping, compliance audits, or academic year reviews.

---

## 2. Common Business Use Cases

1. **Academic Audits**: The registrar generates a list of all Transfer Certificates (TCs) issued in the 2025-2026 academic year to match against withdraw records.
2. **Exporting Data for Boards**: Exporting class participation lists to send to regional education boards as proof of merit distribution.
3. **Tracking Specific Certificate Volume**: Reviewing how many study certificates were issued during the exam registration month.

---

## 3. Database Schema & Data Dictionary

*   **Primary Tables**: `crt_issued_certificates`, `crt_certificate_types`, `std_students`
*   **Tenant Scope**: Scoped implicitly at database level (no `tenant_id` column).

| Column Name (Export Header) | Source Table / Field | Description |
|---|---|---|
| **Certificate Number** | `crt_issued_certificates.certificate_no` | Unique certificate identifier. |
| **Recipient Name** | Concatenation of `std_students` name columns | Trimmed first, middle, and last name. |
| **Certificate Type** | `crt_certificate_types.name` | Display label of the type (e.g. Bonafide). |
| **Issue Date** | `crt_issued_certificates.issue_date` | Date of PDF generation. |
| **Validity Expiry** | `crt_issued_certificates.validity_date` | Expiration date of certificate, if applicable. |
| **Revocation Status** | `crt_issued_certificates.is_revoked` | Flag indicator (Yes / No). |
| **Generated By** | `sys_users.name` (linked via `issued_by`) | User who triggered the generation. |

## 4. Screen Fields & Input Rules

| Field Name (Screen Label) | HTML Control | Required | Validation & Constraints | Default Value |
|---|---|---|---|---|
| **Certificate Type** | Dropdown | No | Choice: Active certificate types. | All Types |
| **Filter Class** | Dropdown | No | Choice: Active class ID. | All Classes |
| **Section** | Dropdown | No | Choice: Active section ID. | All Sections |
| **Start Date** | Date Picker | No | Date. | Start of current session |
| **End Date** | Date Picker | No | Date. Must be $\ge$ Start Date. | Today |

---

## 5. Business Logic & Validation Policies

1. **Excel/CSV Data Stream**:
   * Large exports can cause timeout errors. The system generates the export either via `maatwebsite/excel` query chunking or directly streaming responses using `fputcsv` writing to output stream buffer (`php://output`).
2. **Strict Tenant Isolation**:
   * Eager load relationships: `CrtIssuedCertificate::with(['type', 'recipient'])`. Ensure tenant scoping is enforced automatically via the tenant DB connection. No cross-tenant data must be returned.
3. **Date Range Sanity**:
   * If End Date is entered without Start Date, default Start Date to 30 days prior. If Start Date is after End Date, return: *"The start date must be before or equal to the end date."*
