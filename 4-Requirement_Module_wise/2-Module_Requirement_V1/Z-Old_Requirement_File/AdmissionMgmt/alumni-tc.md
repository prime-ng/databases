# Alumni & Transfer Certificate — Requirements

## What It Does
Manage alumni status and issue Transfer Certificates (TC) with QR-verified PDF. TC issuance requires FIN fee clearance, generates a DomPDF with embedded QR code, and transitions the student to alumni status.

## Database Fields

### `adm_transfer_certificates`

| Field | Type | Conditions |
|---|---|---|
| `id` | BIGINT UNSIGNED PK | Auto-increment |
| `student_id` | INT UNSIGNED | FK → `std_students.id`. |
| `tc_number` | VARCHAR(30) | Required. UNIQUE. Format: `TC-YYYY-NNN`. |
| `issue_date` | DATE | Required. |
| `leaving_date` | DATE | Required. |
| `class_at_leaving` | VARCHAR(30) | Required. e.g., "Class 10". |
| `reason_for_leaving` | TEXT | Nullable. |
| `conduct` | ENUM('Excellent','Good','Satisfactory','Poor') | Default `'Good'`. |
| `destination_school` | VARCHAR(150) | Nullable. |
| `academic_status` | VARCHAR(100) | Nullable. e.g., "Promoted to Class 9". |
| `fees_cleared` | BOOLEAN | Default `0`. 1 = FIN fee clearance confirmed. |
| `is_duplicate` | BOOLEAN | Default `0`. 1 = re-issue of lost TC. |
| `original_tc_id` | BIGINT UNSIGNED | Nullable FK → self. Reference for duplicate TC. |
| `media_id` | INT UNSIGNED | Nullable FK → `sys_media.id`. PDF file. |
| `issued_by` | INT UNSIGNED | Nullable FK → `sys_users.id`. |
| `is_active` | BOOLEAN | Default `1`. |
| `created_by` / `updated_by` | BIGINT UNSIGNED | FK → `sys_users.id`. |
| `created_at` / `updated_at` | TIMESTAMP | Laravel standard. |
| `deleted_at` | TIMESTAMP | Nullable. Soft delete. |

**Unique:** `uq_adm_tc_number` (`tc_number`)

## Business Rules

**Fee Clearance Required (BR-ADM-004)**
- TC only after all outstanding fees cleared — blocked at service layer.
- `TransferCertificateService::issueTc()` calls FIN module balance check before proceeding.
- `fees_cleared` set to 1 only after FIN confirms zero balance.

**TC Number Format (BR-ADM-003)**
- Unique within school-year: `TC-YYYY-NNN` format.
- Generated by `TransferCertificateService::getNextTcNumber(year)` with DB lock for race-condition safety.

**Duplicate TC**
- Re-issue with `is_duplicate = 1` referencing `original_tc_id`.
- Duplicate TC uses a new `tc_number`.
- Original TC remains valid.

## TC Issuance Flow

1. FIN module fee-clearance check (hard block if outstanding balance).
2. Generate TC number with DB lock.
3. Render DomPDF TC view with:
   - School letterhead
   - Student details, class, leaving date
   - Conduct grade, reason, academic status
   - QR code encoding public verification URL (SimpleSoftwareIO/simple-qrcode)
4. Store PDF in `sys_media` (private disk).
5. Create `adm_transfer_certificates` record.
6. Update `std_students.current_status_id` → Alumni.
7. Update `std_student_academic_sessions` → session_status_id = Alumni/Left, `is_current = 0`.
8. Disable `sys_users.is_active = 0`.
9. Log to `sys_activity_logs`.

## Alumni Management

- View alumni list with TC details.
- Search by student name, class, year, TC number.
- Re-issue duplicate TC.
- Track alumni across years.

## CRUD Operations

**Issue TC**
- Route: `POST /admission/transfer-certificates` → validates fee clearance → generates PDF → creates record → updates student status
- Validates: student must have `std_student_academic_sessions.is_current = 0` or be processed for leaving

**List**
- Route: `GET /admission/transfer-certificates` → table with TC number, student, class, leaving date, issue date, conduct, download action

**View**
- Route: `GET /admission/transfer-certificates/{tc}` → detail view

**Download TC**
- Route: `GET /admission/transfer-certificates/{tc}/download` → serve PDF from sys_media

**Re-issue (Duplicate)**
- Route: `POST /admission/transfer-certificates/{tc}/reissue` → creates duplicate with new number

**Alumni List**
- Route: `GET /admission/alumni` → filterable list of alumni students with TC details
