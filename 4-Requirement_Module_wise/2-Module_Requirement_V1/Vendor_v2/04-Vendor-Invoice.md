# Vendor Invoice — Business Requirements

## What This Screen Does

The Vendor Invoice screen is where the finance team manages all billing activity against vendor agreements. This screen has two primary views: one showing agreement items that need invoices generated ("Inv. Need To Generate"), and another showing all invoices that have already been generated ("Invoicing Done").

Think of this screen as the billing desk. When a vendor has completed a month of service, the finance team comes here to generate an invoice, check the billing calculations, record any payments, and track the outstanding balance.

The invoice is always system-generated — the admin does not manually type amounts. Instead, the system reads the billing terms from the agreement (billing model, rates, tax percentages, and usage data) and automatically computes the final payable amount. This ensures accuracy and eliminates manual calculation errors.

---

## When This Screen Is Used

- Month-end billing: Finance team generates invoices for all vendors who have completed their monthly service cycle
- Admin wants to check which agreement items have not yet been invoiced and need action
- Finance needs to view invoice details, check amounts, and record payments made to vendors
- Admin wants to bulk-generate invoices for all items of a specific vendor in one action
- Finance needs to print invoices, download PDFs, or email invoices to vendors
- Admin wants to add a remark to an invoice (e.g., "Payment held pending account verification")
- Admin needs to toggle an invoice item's status to active or inactive (to pause billing)

## The Two Views

### View 1: "Inv. Need To Generate" (Pending Invoice List)

This view shows all agreement items that are currently active and do not yet have an invoice generated for the current billing period.

**How to use:** Select filters (data type = "Inv. Need To Generate," date range, vendor), then click Search. The system shows a list of agreement items waiting to be invoiced.

**Actions available:**
- Generate invoice for a single item
- Select multiple items and generate all invoices in bulk
- View the item's agreement details

**What is shown per row:**
- Vendor name
- Agreement reference number
- Item name
- Fixed charge, unit rate, minimum guarantee quantity
- Status (Active/Inactive)
- Action button

### View 2: "Invoicing Done" (Generated Invoice List)

This view shows all agreement items for which invoices have already been generated in the selected date range.

**Actions available:**
- Add payment (record that the school has paid this invoice)
- View invoice details (breakdown of amounts, taxes, payments)
- Add a remark to the invoice
- Download PDF of the invoice
- Email the invoice to the vendor
- Bulk select multiple invoices for bulk payment or bulk PDF download

**What is shown per row:**
- Vendor name
- Agreement reference number
- Item name
- Invoice number
- Invoice date
- Quantity used (for per-unit and hybrid billing)
- Net payable amount
- Amount paid so far
- Status (Pending / Partially Paid / Fully Paid)
- Action button

## How Invoice Amount is Calculated

The system automatically computes the invoice amount when "Generate Invoice" is triggered. The calculation depends on the billing model of the agreement item:

**Fixed Billing Model**
The fixed charge amount is directly used as the sub-total.

Example: Billing model = Fixed, Fixed Charge = ₹25,000
Sub-total = ₹25,000

**Per Unit Billing Model**
The quantity used (from the usage log or run count) is multiplied by the unit rate.

Example: Unit Rate = ₹35/jar, Qty Used = 200 jars
Sub-total = 200 × ₹35 = ₹7,000

**Hybrid Billing Model**
The fixed charge is added to a variable charge based on usage above the guaranteed minimum.

Example: Fixed = ₹10,000, Unit Rate = ₹50/trip, Min Guarantee = 100 trips, Actual Trips = 140
Billable qty = 140 - 100 = 40 trips
Variable = 40 × ₹50 = ₹2,000
Sub-total = ₹10,000 + ₹2,000 = ₹12,000

**Tax Calculation**
All applicable tax percentages (Tax1 to Tax4, e.g., CGST 9%, SGST 9%) are summed and applied to the sub-total to arrive at the tax amount.

Example: Sub-total = ₹12,000, Total Tax = 18% → Tax = ₹2,160
Net Payable = ₹12,000 + ₹2,160 = ₹14,160

**Additional Adjustments**
At the time of generation, admin can optionally enter:
- Other Charges (e.g., late delivery surcharge): added to the net payable
- Discount Amount (e.g., early payment discount negotiated): subtracted from the net payable

---

## Invoice Number and Date

The invoice number is auto-generated by the system using a timestamp-based format (e.g., INV-20250501143022456). This ensures every invoice has a unique number without manual entry.

The invoice date is automatically set to the current date when the invoice is generated.

The billing period (Billing Start Date to Billing End Date) is taken from the agreement's start and end dates, reflecting the entire contract period to which this invoice applies.

The due date is calculated by adding the payment terms (in days) from the agreement — for example, if payment terms are 30 days and the invoice date is 1 May, the due date will be 31 May.

## Business Rules and Conditions

**One Invoice Per Agreement Item Per Period**
The system prevents generating a duplicate invoice for the same agreement item and the same billing period (start date to end date). If an invoice already exists for that combination, the system blocks the action and shows an appropriate message.

**Only Active Items Can Be Invoiced**
If an agreement item is marked Inactive, the system will not generate an invoice for it. Admin must first reactivate the item.

**Agreement Must Be Active**
Invoices can only be generated for items belonging to an Active agreement. Items under Draft, Expired, or Terminated agreements cannot be invoiced.

**Usage Quantity Minimum of 1**
For per-unit and hybrid billing, the quantity used is read from the usage log. If no usage has been logged yet, the system defaults to a minimum quantity of 1 to prevent a zero-value invoice.

**Payment Cannot Exceed Net Payable**
When adding a payment, the amount entered cannot exceed the remaining balance due on the invoice. The system calculates balance due as Net Payable minus Amount Already Paid.

**Invoice Status Progression**
Invoices move through the following statuses based on payment:
- **Pending** — No payment has been received yet
- **Partially Paid** — Some payment has been received but the full amount is not yet cleared
- **Fully Paid** — The entire net payable amount has been received

**Bulk Operations**
Multiple invoice items can be selected using checkboxes for:
- Bulk invoice generation (for pending items)
- Bulk payment entry
- Bulk PDF download (as a ZIP file)
- Bulk email dispatch

**Status Toggle**
Admin can toggle the status of an agreement item and its linked invoice simultaneously using the status switch on the list. This is useful for temporarily pausing billing on a specific item.

## Workflow Steps

**Generating a Monthly Invoice (Single Item)**
Finance selects Data Type = "Inv. Need To Generate," selects the vendor and date range, clicks Search, finds the agreement item, and clicks "Generate Invoice" from the Action menu. A modal appears asking for optional Other Charges and Discount. On submit, the system calculates and creates the invoice automatically.

**Generating Invoices in Bulk**
Finance selects multiple items using checkboxes (or "Select All"), clicks the batch "Generate Invoice" button, fills in optional adjustments, and submits. The system processes each item and reports success/failure for each.

**Recording a Payment**
Finance switches to the "Invoicing Done" view, finds the invoice, clicks "Add Payment" from the Action menu. A modal appears with fields: Payment Date, Amount, Mode (Cash/NEFT/UPI/Cheque), Reference Number, Status, Remarks, and a Reconciled toggle. On submission, the invoice's paid amount and status are updated.

**Viewing Invoice Details**
Finance clicks "View Details" from the Action menu. A panel opens showing the full invoice breakdown — sub-total, tax breakdown, other charges, discount, net payable, amount paid, balance due, and payment history.

**Adding a Remark**
Finance clicks "Add Remark" from the Action menu, types the remark, and submits. The remark is saved and visible in the invoice details.

**Downloading PDF**
Finance selects one or more invoices, clicks the PDF button. The system generates a properly formatted PDF (or ZIP of multiple PDFs) and downloads it.

**Emailing Invoice to Vendor**
Finance selects one or more invoices, clicks the Email button. The system dispatches invoices via email to the vendor's registered email address in the background.

## Example Scenario

It is 5 May 2025. Finance needs to bill Sharma Transport Services for April 2025.

1. Finance opens the Vendor Invoice screen, selects Data Type = "Inv. Need To Generate," Vendor = "Sharma Transport Services," Date Range = 1 Apr 2025 to 30 Apr 2025, and clicks Search.

2. Three agreement items appear — Route A (Fixed ₹18,000), Route B (Fixed ₹20,000), Route C (Hybrid).

3. Finance selects all three and clicks "Generate Multiple Invoices." The system calculates:
   - Route A: Sub-total ₹18,000 + GST 18% = ₹21,240 Net Payable
   - Route B: Sub-total ₹20,000 + GST 18% = ₹23,600 Net Payable
   - Route C: Fixed ₹15,000 + 130 trips (30 extra × ₹50 = ₹1,500) = ₹16,500 + GST 18% = ₹19,470

4. Three invoices are created with due date 5 June 2025. Finance downloads the PDFs and emails them to the vendor.

5. On 20 May, Sharma Transport pays ₹21,240 via NEFT. Finance records this under Route A's invoice. The invoice status changes from Pending to Fully Paid.
