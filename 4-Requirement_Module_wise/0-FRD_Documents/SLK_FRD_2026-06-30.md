## Section 1 — Module Overview

### 1.1 Purpose

SyllabusBooks (SLK) is the school's digital curriculum library. It serves two interlinked purposes:

**Book Catalog and Curriculum Assignment** — Schools maintain a master registry of all textbooks and reference publications used across the curriculum. Each book is assigned to specific class, subject, and academic session combinations, with clear flags indicating whether it is the primary textbook or a supplementary reference, and whether purchase is mandatory or optional.

**Study Notes Repository** — Teachers and (optionally) students upload study notes — revision summaries, formula sheets, practice question sets, mind maps, and worksheets — tied to classes, subjects, and books. Notes pass through an approval workflow before becoming visible to students, and every download is tracked for audit purposes.

The module also tracks book chapter indexes, attaches downloadable files to books, maps book chapters to syllabus topics, and maintains download audit logs for both book files and note files.

### 1.2 Business Value

- Eliminates duplicate book registrations and conflicting book lists across departments
- Gives parents a single, official printable book list per class and academic year
- Ensures only approved study materials reach students (content governance)
- Provides usage analytics (most-downloaded books, most-rated notes) to guide teaching decisions
- Enables traceability from syllabus topic to source textbook chapter

### 1.3 Scope

**In Scope:**
- Book author registry and author-book role assignments
- Book catalog with metadata (ISBN, publisher, language, edition, NCERT/CBSE flags, cover image)
- Book-class-subject-session assignment (primary vs reference; mandatory vs optional)
- Chapter index per book
- File attachments per book (PDF, EPUB, etc.) with download tracking
- Mapping of book chapters to syllabus topics (content traceability)
- Study notes lifecycle: upload, approval workflow, visibility controls, rating
- Download audit logs for book files and note files
- Module configuration (upload limits, approval policy, content protection)
- Dashboard with tabbed view across all areas

**Out of Scope:**
- Physical book lending and library circulation tracking (covered by the Library module)
- Fee collection for book purchases or damage fines (covered by Student Fee module)
- Student purchase receipts and book distribution lists
- Marking scheme or curriculum mapping to assessment blueprints (covered by LMS Exam module)
- Third-party digital reading integrations (e-reader DRM systems, Google Books API)

### 1.4 Terminology

| Business Term | Meaning |
|---|---|
| Book Catalog | The school's master registry of all textbooks and reference publications |
| Primary Textbook | The main prescribed book for a class-subject combination (one per class-subject-session) |
| Reference Book | A supplementary book assigned to a class-subject (multiple allowed) |
| Mandatory Book | A book all students must acquire (`is_mandatory = true`) |
| Academic Session | The school year context (e.g., 2025-26) — always tenant-scoped |
| Author Role | The author's contribution level: Primary Author, Co-Author, Editor, or Contributor |
| Study Note | A teacher- or student-created study aid file linked to a class-subject |
| Note Status | Lifecycle state of a note: Draft, Pending Approval, Approved, Rejected, Archived |
| Book-Topic Mapping | A link between a specific book chapter or page range and a syllabus topic |
| Download Audit Log | A permanent, read-only record of every file download (book file or note file) |
| Module Settings | School-level configuration for upload limits, formats, approval rules, and content protection |

## Section 3 — Functional Requirements

### REQ-SLK-001: Book Author Management
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors who initiate:** School Admin, Academic Coordinator, Librarian
**Description:**
The system maintains a registry of book authors. An author represents an individual (e.g., "R.S. Aggarwal") or an organisation (e.g., "NCERT") that wrote, edited, or contributed to one or more books. Authors must exist in this registry before they can be linked to a book.

**Business Rules:** BR-SLK-001, BR-SLK-005, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-001-1: Creating an author with a name already in use returns a "name already exists" validation error and no record is saved.
- AC-001-2: An author with zero book associations can be permanently removed with no error; the action is recorded in the audit log.
- AC-001-3: An author with active book associations can be permanently removed only after all book links are resolved; blocking with an error message is the minimum; cascade is a valid alternative per BR-SLK-005.
- AC-001-4: Soft-deleting an author moves it to Trash; the author no longer appears in any active book-assignment dropdowns.
- AC-001-5: A restored author reappears in book-assignment dropdowns immediately.
- AC-001-6: Toggling an author's status returns a JSON response with `success: true` and the new `is_active` value.
- AC-001-7: The author list shows the number of books linked to each author.

**Integration:** Author records are referenced by book-author junction during book creation.

### REQ-SLK-002: Book Catalog Management
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors who initiate:** School Admin, Academic Coordinator, Librarian
**Description:**
The system maintains the school's master book catalog. Each book carries bibliographic metadata (title, ISBN, publisher, language, edition, publication year, description, tags), curriculum flags (NCERT, CBSE-recommended), and a cover image. A book is always linked to at least one class-subject-session combination when created (see REQ-SLK-003). Books support the full lifecycle: create, edit, view detail, soft-delete (archive), restore, permanent delete, and status toggle.

**Business Rules:** BR-SLK-002, BR-SLK-003, BR-SLK-004, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-002-1: A book title is required; a book cannot be saved without a title.
- AC-002-2: An ISBN, when provided, must be unique within the school's catalog; attempting to save a duplicate ISBN returns a validation error.
- AC-002-3: Permanently removing a book that is referenced by at least one active lesson plan returns an error naming the conflict.
- AC-002-4: Permanently removing a book that is referenced by at least one active question-bank entry returns an error naming the conflict.
- AC-002-5: Permanently removing a book with no lesson or question-bank references succeeds; cover image, files, chapters, and all junction records are also cleaned.
- AC-002-6: The book list supports search by title, ISBN, publisher, and language and filter by class, subject, session, NCERT flag, CBSE flag, and active status.
- AC-002-7: Cover image upload is accepted only for image files (JPG, JPEG, PNG, WEBP) up to 2 MB.

**Integration:** Books are referenced by the Lesson Plan feature (Syllabus module) and the Question Bank module. Cover images are stored via the shared media store.

### REQ-SLK-003: Book-Class-Subject-Session Assignment
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors who initiate:** School Admin, Academic Coordinator, Librarian
**Description:**
Each book can be assigned to one or more class-subject-academic-session combinations. The assignment records whether the book is the primary textbook or a reference book, and whether it is mandatory or optional. Only one book per class-subject-session may be marked as the primary textbook; assigning a second primary must automatically demote the existing one.

**Business Rules:** BR-SLK-006, BR-SLK-009, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-003-1: A book assignment correctly records the selected class, subject, and academic session (all from the school's own session registry, not the platform's global session list).
- AC-003-2: Attempting to assign the same book to the same class-subject-session twice returns a duplicate-entry error.
- AC-003-3: When a book is marked Primary for a class-subject-session that already has a primary, the existing primary is demoted to Reference before the new primary is saved.
- AC-003-4: Soft-deleting a book preserves all assignments in the audit record; the assignments are not visible on the active assignment screen.

### REQ-SLK-004: Book Chapter Index
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY]
**Actors who initiate:** School Admin, Librarian, Academic Coordinator
**Description:**
Each book can carry an indexed list of chapters. Each chapter record captures chapter number, chapter title, start page, end page, and an optional summary. Chapters are displayed in order and used as context selectors in the Notes upload form and the Book-Topic Mapping form.

**Business Rules:** BR-SLK-010 (via page range cross-check), BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-004-1: A chapter can be created for any active book; the chapter list for a book shows entries in ascending chapter-number order.
- AC-004-2: Bulk chapter creation via the chapter form saves multiple chapters in one action.
- AC-004-3: When a user selects a book in the Notes upload form or Topic Mapping form, the chapter dropdown shows only chapters belonging to that book.
- AC-004-4: Deleting a book also removes all associated chapter records (cascade on permanent delete).

### REQ-SLK-005: Book Files and File Download Tracking
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY][WORKFLOW]
**Actors who initiate:** School Admin, Librarian (upload); Subject Teacher, Student (download)
**Description:**
Each book can have multiple uploaded files (full ebook, individual chapter PDFs, EPUB, DOCX, MOBI). Each file carries a display label, edition reference, file format, a primary flag (one default download per book), and a downloadable toggle. Every file download by a student or teacher is logged automatically with the downloader's identity, IP address, browser information, and download timestamp.

**Business Rules:** BR-SLK-018, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-005-1: Uploading a file in a format not in the Settings whitelist returns a format-not-allowed error.
- AC-005-2: Uploading a file exceeding the Settings-configured size limit returns a file-too-large error.
- AC-005-3: Marking a second file as "primary" on a book demotes the existing primary file to non-primary.
- AC-005-4: Downloading a file that has `downloadable = false` is denied with an appropriate message.
- AC-005-5: Every successful download creates an automatic log entry in the book file download audit; the entry cannot be manually created, edited, or deleted.

### REQ-SLK-006: Book-Topic Mapping
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY]
**Actors who initiate:** School Admin, Academic Coordinator, Subject Teacher
**Description:**
The system enables mapping of specific book chapters or page ranges to syllabus topics. This creates traceability from curriculum topics to their source textbook material. Each mapping captures the book, the syllabus topic, chapter number and title, page range, section reference, and remarks.

**Business Rules:** BR-SLK-010, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-006-1: Visiting the Book-Topic Mapping list screen loads without errors and displays all active mappings with book name, topic name, and page range.
- AC-006-2: Saving a mapping where the start page exceeds the end page returns a validation error.
- AC-006-3: When a book has a known total page count, saving a mapping whose end page exceeds the total page count returns a validation error.
- AC-006-4: Saving a mapping with a non-existent book ID or non-existent topic ID returns a validation error.
- AC-006-5: Soft-deleting a mapping moves it to Trash; the mapping no longer appears in the active mapping list.

**Note:** The underlying data table for book-topic mappings is not yet present in the deployed database schema. This requires a schema change before REQ-SLK-006 can function. [Source: DB-SLK-01]

### REQ-SLK-007: Study Notes Management
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY][WORKFLOW][APPROVAL][NOTIFICATION]
**Actors who initiate:** Subject Teacher (always); Student (when enabled by Settings)
**Actors who process:** Subject Teacher (approves/rejects student notes); School Admin (approves/rejects teacher notes when required)
**Description:**
Study notes are digital study aids uploaded by teachers or students and made available to learners. Notes are categorised by type (Revision Notes, Practice Questions, Formula Sheet, Mind Map, Flow Chart, Cheat Sheet, Summary, Worksheet, Other). Each note is linked to a class-subject-academic-session and optionally to a specific book and chapter.

Notes follow a status workflow: Draft, Pending Approval, Approved, Rejected, Archived. Visibility can be set to Class Only, Subject Wide (all sections taking that subject), or School Wide. Each note may carry one primary file and additional supporting files.

**Business Rules:** BR-SLK-011, BR-SLK-012, BR-SLK-013, BR-SLK-014, BR-SLK-019, BR-SLK-020, BR-SLK-021
**Acceptance Criteria:**
- AC-007-1: A student cannot access the note-upload function when "Allow Student Uploads" is disabled in Settings; the upload button is hidden and the route returns a permission error.
- AC-007-2: A student-uploaded note starts in "Pending Approval" status when "Require Approval" is enabled; the teacher of the relevant subject receives a notification.
- AC-007-3: A teacher-uploaded note is immediately "Approved" when "Teacher Upload Approval — Require Approval" is disabled.
- AC-007-4: An approved note is visible to students in the configured visibility scope (class only / subject wide / school wide).
- AC-007-5: Rejecting a note requires entering a rejection reason; the uploader receives a notification with the reason.
- AC-007-6: Uploading a note file in a format not in the Notes-format whitelist (from Settings) returns a format-not-allowed error.
- AC-007-7: A note in "Draft" status is visible only to the uploader.
- AC-007-8: Archiving a note removes it from the student view immediately, regardless of its previous status.

**Integration:** Notification module is required for approval/rejection alerts. [Inferred — notification mechanism not yet confirmed in code]

### REQ-SLK-008: Note Ratings
**Priority:** Enhanced (P2) | **Tags:** [DATA_ENTRY]
**Actors who initiate:** Student (rates approved notes)
**Description:**
Students can rate approved notes on a 1-to-5 star scale. Ratings help the community identify high-quality study materials. Each student can rate a given note only once; submitting a second rating updates the previous one. Ratings are not attributed to individual students in the public view — only the average rating and total count are displayed.

**Business Rules:** BR-SLK-015, BR-SLK-016, BR-SLK-021
**Acceptance Criteria:**
- AC-008-1: A student who has not yet rated a note can submit a rating between 1 and 5; the rating is saved and the note's average is recalculated.
- AC-008-2: A student who has already rated a note can submit a new rating; the old rating is replaced and the average is recalculated.
- AC-008-3: The note list displays average rating and total count of ratings, but not the name of any individual rater.
- AC-008-4: A student cannot rate a note that is not in "Approved" status.

### REQ-SLK-009: Download Audit Log
**Priority:** Standard (P1) | **Tags:** [REPORT]
**Actors who view:** School Admin, Academic Coordinator, Librarian, Subject Teacher (own subject downloads)
**Description:**
Every download of a book file or a note file is logged automatically. The audit log is read-only. It captures the downloader's name, the item downloaded (book/file or note/file), the IP address, browser and device information, and the exact date and time. Records are permanent and cannot be deleted.

**Business Rules:** BR-SLK-017, BR-SLK-021
**Acceptance Criteria:**
- AC-009-1: Downloading a book file creates an audit entry automatically; no manual action is needed.
- AC-009-2: Downloading a note file creates an audit entry automatically.
- AC-009-3: The audit log can be filtered by book, by note, and by date range.
- AC-009-4: No user — regardless of role — can create, edit, or delete an audit log entry through the application.

A single configuration record per school controls how the entire SyllabusBooks module behaves. Settings are grouped into six areas: Book file settings, Note file settings, Student upload rules, Teacher upload approval, Content protection, and Cross-class visibility. These settings are applied at runtime to all upload, approval, and visibility logic across the module.

**Business Rules:** BR-SLK-012, BR-SLK-013, BR-SLK-014, BR-SLK-018, BR-SLK-019, BR-SLK-021
**Acceptance Criteria:**
- AC-010-1: Only a user with the School Admin role can view or edit the Settings screen.
- AC-010-2: Saving Settings immediately affects subsequent uploads (format and size checks use the new values).
- AC-010-3: Enabling "Student Uploads — Require Approval" immediately puts the next student note into Pending Approval status.
- AC-010-4: Enabling "Watermark" causes the configured watermark text to appear on all content viewed online [Enhancement — not yet implemented].
- AC-010-5: Settings persist between sessions; they are not reset on server restart.

A formatted, printable book list can be generated for any class and academic session. ## Section 6 — Workflows

### Workflow 1: Create Book with Authors and Class Assignment
**Trigger:** Librarian/Coordinator selects "Add Book"
**End States:** Book saved and active; or form validation failure

**Steps:**
1. [Actor] Fills book details (title, ISBN, language, publisher, edition, year, description, tags, NCERT/CBSE flags)
2. [Actor] Uploads cover image (optional)
3. [Actor] Assigns one or more authors with roles and display order
4. [Actor] Assigns one or more class-subject combinations with primary/mandatory flags
5. [System] Validates: title required; ISBN unique if provided; authors exist; classes and subjects exist; session belongs to school; author role valid; no duplicate author-role pair
6. [System] Saves the book record, cover image, author-junction records, and class-assignment records in a single transaction; generates a UUID identifier; records the creation in the activity log
7. [System] Redirects to the book list; shows success message

**Exception Paths:**
- ISBN already exists: validation error returned; no record saved
- An author ID does not exist: validation error
- Two authors share the same role in the form: validation error

**Notifications:** None at book creation.

---

### Workflow 2: Note Approval (Student Upload)
**Trigger:** Student submits a note when "Require Approval" is enabled
**End States:** Note Approved and visible to students; or Note Rejected (uploader notified)

**Steps:**
1. [Student] Fills note form: title, type, class, subject, session, optional book/chapter, visibility, file
2. [System] Validates file format and size against Settings; validates class-subject required
3. [System] Sets status to "Pending Approval"; saves note; notifies the relevant Subject Teacher
4. [Teacher] Receives notification; opens the approval queue; reviews the note content
5. Decision: Approve or Reject
   - Branch A — Approve: [Teacher] clicks Approve → [System] sets status to "Approved"; note becomes visible to students per its visibility scope; student receives approval notification
   - Branch B — Reject: [Teacher] enters rejection reason → [System] sets status to "Rejected"; student receives rejection notification with the stated reason

**Exception Paths:**
- File format not in whitelist: upload blocked at step 2; note not saved
- Student uploads per day limit reached: upload blocked at step 2 with a limit-reached message

**Notifications Triggered:**

| Step | Recipient | Channel | Message |
|---|---|---|---|
| Step 3 | Subject Teacher | In-app / Email | "A new note '{title}' has been submitted for approval by a student in {class} {subject}." |
| Step 5-A | Uploading Student | In-app | "Your note '{title}' has been approved and is now visible to your class." |
| Step 5-B | Uploading Student | In-app | "Your note '{title}' was not approved. Reason: {reason}." |

---

### Workflow 3: Book File Download and Audit Logging
**Trigger:** Student or Teacher clicks "Download" on a book file
**End States:** File delivered; download logged

**Steps:**
1. [Actor] Clicks Download on a book file with `downloadable = true`
2. [System] Checks permission (authenticated user with view access to the book)
3. [System] Serves the file
4. [System] Automatically creates a download audit log entry capturing: downloader identity, file reference, IP address, user agent, and timestamp

**Exception Paths:**
- File has `downloadable = false`: request blocked; message "This file is not available for download."
- User not authenticated: redirected to login
