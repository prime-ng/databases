## 1. Module Overview

### 1.1 Purpose

The Question Bank is the central, curriculum-anchored content repository for all assessment activities across the Prime-AI platform. It stores questions authored by teachers or generated by AI, maintains a structured review and approval lifecycle before questions are used in any assessment, and provides analytical feedback on question quality based on actual student response data. Every question the platform ever asks a student — whether in a quiz, a practice quest, an online exam, or a printed offline paper — originates from this module.

### 1.2 Business Value

- Eliminates duplicate question authoring: a well-tagged, approved question is reusable across any quiz, quest, or exam for the appropriate class and subject, reducing teacher effort significantly.
- Ensures cognitive balance: Bloom's Taxonomy tagging enables assessment builders to guarantee a spread of remember-through-create questions rather than producing recall-heavy papers.
- Enables AI-assisted content creation: teachers can generate draft questions from two AI providers, accelerating question bank growth while retaining human review before publication.
- Drives personalised learning: the Performance Category mapping connects question difficulty to student outcome bands (Weak / Average / Strong), enabling the Recommendation engine to serve the right question to the right student at the right time.
- Provides empirical quality feedback: Difficulty Index, Discrimination Index, and Guessing Factor — computed from real student responses — tell teachers which questions are too easy, are mis-keyed, or are heavily guessed, so the bank continuously improves in quality.

### 1.3 Scope

**In scope:**
- Question authoring (manual create, edit, clone, delete) for seven question types
- Curriculum anchoring to Class, Subject, Lesson, Topic, and Competency hierarchy from the Syllabus module
- Bloom's Taxonomy, Cognitive Skill, Complexity Level, and Question Type Specificity tagging (all required on every question)
- Rich content formats: plain text, HTML, Markdown, LaTeX (with MathJax rendering), and JSON
- Media attachments (image, audio, video, PDF) for questions, individual answer options, and teacher explanations
- Question lifecycle: Draft, In Review, Approved, Rejected, Published, and Archived states
- Version history: full content snapshots created before every modification
- Custom keyword tag system for informal search and organisation beyond the curriculum hierarchy
- Multi-topic mapping with per-topic weightage for cross-topic questions
- Performance category mapping feeding the LXP Recommendation engine
- AI-assisted question generation via two external AI providers
- Excel bulk import with a two-step validate-then-commit process (up to 500 questions per file)
- Printable question paper generation with LaTeX rendering
- Question quality statistics: Difficulty Index, Discrimination Index, Guessing Factor, and response-time metrics
- Usage logging (insert-only records created by Quiz, Quest, and Exam consuming modules)
- Complete data isolation per school (no cross-school question sharing)

**Out of scope:**
- Student assessment delivery (Quiz, Quest, and Exam modules own delivery)
- Marksheet computation or grade aggregation
- Cross-tenant question marketplace (PrimeGurukul-level feature, not designed)
- Student portal dashboard
- Staff leave or payroll management

### 1.4 Terminology

| Business Term | Meaning |
|---------------|---------|
| Question | A single assessment item comprising a question stem, answer options (if applicable), the correct answer, and an optional teacher explanation. |
| Bloom's Taxonomy Level | One of six cognitive levels — Remember, Understand, Apply, Analyse, Evaluate, Create — that classifies the mental demand of a question. |
| Complexity Level | A teacher-facing difficulty label — Easy, Medium, Hard, Very Hard — distinct from Bloom level; describes perceived content difficulty. |
| Cognitive Skill | The specific mental process a question requires: Recall, Comprehension, Application, Critical Thinking, or Creative Thinking. |
| Question Type Specificity | A sub-classification within a question type (e.g. Single-Correct vs Multi-Correct vs Assertion-Reason for MCQ; Analytical vs Descriptive for Essay). |
| Difficulty Index | The percentage of students who answered a question correctly. Low value means the question is hard; high value means it is easy. Ranges from 0 to 100. |
| Discrimination Index | Kelley's D-index: the difference in correct-answer rate between the top 27% and bottom 27% of students. A positive value shows the question effectively separates strong from weak students. A negative value flags a mis-keyed or poorly worded question. |
| Guessing Factor | For MCQ questions only: the estimated proportion of correct answers attributable to random guessing, based on the number of options and the empirical bottom-group performance rate. |
| Availability Scope | A setting on each question controlling who can see and use it: All Teachers (Global), This School Only, This Class Only, This Section Only, This Student Group Only, or One Specific Student. |
| Content Owner | Either the Platform (PrimeGurukul) — questions are read-only for school teachers and may only be cloned — or the School — questions are fully editable by authorised teachers of that school. |
| Usage Log | An immutable record created by Quiz, Quest, or Exam modules each time a question is included in an assessment. The Question Bank does not create these records itself. |
| Version Snapshot | A complete copy of a question's full state (content, answer options, taxonomy, marks) stored before any content modification. Enables audit history and informs rollback decisions. |
| Performance Category | A classification of student outcome bands (e.g. Weak, Average, Strong) from the Syllabus module. Mapping a question to a category tells the Recommendation engine what type of student to suggest it to. |

## 3. Functional Requirements

### REQ-QNS-001 — Question Creation & Management
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][WORKFLOW]
**Actors — Initiates:** Subject Teacher, Dept Head, School Admin | **Processes:** System | **Views:** All roles

**Description:** A teacher creates a question by completing a four-section form. The question is anchored to the curriculum hierarchy (Class, Subject, Lesson, Topic, Competency), tagged with all four required taxonomy dimensions, assigned a question type, given marks and negative marks, and categorised by availability scope. For MCQ and Match question types, answer options are provided with at least one marked correct. The question is saved with an initial status of Draft unless the teacher explicitly sets another valid status.

**Business Rules:** BR-QNS-001, BR-QNS-002, BR-QNS-003, BR-QNS-006, BR-QNS-007, BR-QNS-010

**Acceptance Criteria:**
- Given a teacher submits a complete MCQ question form with 4 options and 1 correct, the question saves with status = Draft and the correct option is recorded.
- Given a teacher leaves the Bloom's Taxonomy field blank, the system prevents submission and highlights the missing field.
- Given a teacher is a Subject Teacher with no admin role and the question owner is set to Platform Content, the teacher cannot edit or delete it.
- Given a teacher navigates away mid-form without saving, no partial record is created.

**Integration:** Syllabus module (curriculum hierarchy), SchoolSetup (classes, subjects), SystemConfig (user identity)

### REQ-QNS-002 — Question Types
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors — Initiates:** Teacher | **Processes:** System | **Views:** Teacher, Coordinator

**Description:** The system supports seven distinct question types. The type selected determines the answer section shown in the creation form. Each type has specific validation rules for its answer section.

| Type | Student Interface | Answer Format |
|------|-----------------|---------------|
| Multiple Choice — Single Correct (MCQ) | One answer selectable | Exactly one option marked correct |
| Multiple Choice — Multi Correct | Multiple answers selectable | One or more options marked correct |
| True / False | Two fixed choices | System-generated; teacher marks which is correct |
| Fill in the Blank | Text entry | Correct answer stored in teacher explanation field |
| Short Answer | Short text entry | Teacher marks manually after submission |
| Essay / Long Answer | Extended text entry | Rubric-based teacher marking |
| Match the Columns | Left-right pair matching | Option pairs stored with left-item and right-item |

For questions with rich mathematical content, the format may be set to LaTeX, which causes MathJax to render the content in all views where the question appears (creation preview, print, assessment delivery).

**Acceptance Criteria:**
- Given a question type is MCQ Single, only one option can be marked correct; attempting to mark a second removes the first.
- Given a question type is Essay, the answer options section is hidden and no options are required.
- Given the content format is LaTeX, MathJax renders the content in the question preview without raw LaTeX markup showing.

### REQ-QNS-003 — Bloom's Taxonomy & Full Taxonomy Tagging
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors — Initiates:** Teacher | **Processes:** System | **Views:** Teacher, Coordinator, Admin

**Description:** Every question must carry all four taxonomy tags before it can be submitted for review or published. The four tags are Bloom's Taxonomy Level (1–6), Cognitive Skill, Complexity Level (Easy through Very Hard), and Question Type Specificity. These tags drive cognitive balance analysis in assessment builders and enable the Difficulty Index and Discrimination Index statistics. They cannot be left blank on any question that progresses beyond Draft status.

**Business Rules:** BR-QNS-001

**Acceptance Criteria:**
- Given a teacher attempts to submit a question for review without selecting a Bloom's Taxonomy Level, the system displays a validation error and keeps the question in Draft.
- Given two questions in the same quiz are tagged Bloom 1 and Bloom 6, the quiz analytics can report cognitive spread across both levels.
- Given a question has Bloom Level 3, it appears in the Bloom Level 3 filter on the question list screen.

### REQ-QNS-004 — Version History
**Priority:** Standard (P1) | **Tags:** [WORKFLOW][DATA_ENTRY]
**Actors — Initiates:** Teacher (via edit action) | **Processes:** System | **Views:** Teacher, Admin

**Description:** Every time a teacher modifies a question's content — specifically the question text, answer options, marks, negative marks, or any taxonomy field — the system saves a complete snapshot of the question's prior state before applying the change. The snapshot stores the entire prior question as a JSON record including all options and metadata. A version counter on the question increments with each snapshot. Pure status changes (e.g. Approved to Published) do not create a new snapshot.

Teachers and admins can open a question's version history to see the full modification timeline, who made each change, when it was made, and a reason if one was given. The version history cannot be deleted.

**Business Rules:** BR-QNS-009

**Acceptance Criteria:**
- Given a teacher edits a question's content and saves, a version snapshot is created containing the prior state, and the version counter increments by one.
- Given a question's status changes from Approved to Published without any content change, no new version snapshot is created.
- Given a question has been modified three times, the version history screen shows exactly three entries in chronological order.

### REQ-QNS-005 — Review & Approval Workflow
**Priority:** Core (P0) | **Tags:** [WORKFLOW][APPROVAL][NOTIFICATION]
**Actors — Initiates:** Teacher (submit), Reviewer (decide), Admin (publish) | **Processes:** System | **Views:** Reviewer, Admin, Teacher

**Description:** Every question that is intended for use in assessments must pass through a review and approval process. When a teacher clicks "Submit for Review," the question enters the In Review state and appears in the review queue. A reviewer (any teacher designated as having review permissions, or an admin) examines the question and either approves it (moving it to Approved) or rejects it with a mandatory written comment (returning it to Draft). An admin then publishes the Approved question, making it available to assessment builders. Every status change made by a reviewer creates a permanent, uneditable audit entry in the review log.

The system optionally allows a fast-track path: a teacher with admin permissions may move a question directly from Draft to Approved (bypassing the In Review stage) for platform-owned or trusted content.

Questions with the AI-generated flag set must always pass through the full In Review stage; this requirement cannot be overridden.

**Business Rules:** BR-QNS-003, BR-QNS-008, BR-QNS-011

**Acceptance Criteria:**
- Given a teacher submits a question for review, its status changes to In Review and the review queue shows the question.
- Given a reviewer rejects a question without entering a comment, the system prevents the rejection and displays "A comment is required when rejecting a question."
- Given an AI-generated question is in Approved status, an admin cannot bypass the Published state — the question must be published explicitly, not silently moved to assessments.
- Given a reviewer and a teacher attempt to approve the same question simultaneously, the first action succeeds and the second receives "This question has already been reviewed."

**Notifications:** When a question is submitted for review, the assigned reviewer (or all eligible reviewers if unassigned) receives a notification. When a question is approved, the original author receives a notification. When a question is rejected, the original author receives a notification including the rejection comment.

### REQ-QNS-006 — Media Management
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY]
**Actors — Initiates:** Teacher | **Processes:** System | **Views:** Teacher, Coordinator

**Description:** Questions and their answer options may have attached media: images, audio clips, video files, or PDFs. Each media attachment is associated with a specific purpose — illustrating the question itself, appearing alongside a specific answer option, supporting the teacher's explanation, or providing a recommendation context image. The display position of the media relative to the text (above, below, left, or right) is configurable per attachment.

The media file store uses a checksum (cryptographic hash) to detect duplicate uploads: if the same file is uploaded twice, only one file record is created and both references point to it.

**Acceptance Criteria:**
- Given a teacher uploads an image for a question, the image appears in the question detail view at the position specified.
- Given the same image file is uploaded twice, only one file record exists in the media store; both questions link to that single record.
- Given a question with a PDF attachment is printed, the print view notes the attachment with a reference number.

### REQ-QNS-007 — Tag System
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY][CONFIGURATION]
**Actors — Initiates:** Teacher, Admin | **Processes:** System | **Views:** Teacher, Admin

**Description:** Teachers can define free-form keyword tags (e.g. "NCERT Important", "Board 2024", "Frequently Wrong") and attach them to questions. Tags provide a flexible search and filtering layer beyond the formal curriculum hierarchy. A tag has a unique short code and a display name. A question can carry multiple tags; a tag can appear on multiple questions.

Admins and teachers manage tags through a dedicated Tags Management screen that supports full create, edit, soft-delete, and restore operations.

**Acceptance Criteria:**
- Given a teacher searches for "NCERT Important" in the question list filter, only questions tagged with that tag appear.
- Given an admin deletes a tag, the tag is soft-deleted and no longer appears in the tag picker; questions that previously had that tag lose the association.
- Given a teacher creates a tag with a duplicate short code, the system rejects it with "A tag with this code already exists."

### REQ-QNS-008 — Multi-Topic Mapping
**Priority:** Enhanced (P2) | **Tags:** [DATA_ENTRY]
**Actors — Initiates:** Teacher | **Processes:** System | **Views:** Teacher

**Description:** A question whose content spans more than one curriculum topic may be linked to additional topics beyond its primary topic. For each additional topic, a weightage value (expressed as a percentage) indicates what proportion of the question relates to that topic. The sum of all weightage values across a question's topic links should equal 100, though this is a soft warning rather than a hard block.

**Acceptance Criteria:**
- Given a teacher links a question to three topics with weightages of 50, 30, and 20, all three links are saved and the question appears in filtered searches for each of the three topics.
- Given the topic weightages for a question sum to 120, the system shows a warning "Topic weightages should sum to 100" but allows saving.

### REQ-QNS-009 — Performance Category Mapping
**Priority:** Enhanced (P2) | **Tags:** [INTEGRATION][CONFIGURATION]
**Actors — Initiates:** Teacher, Admin | **Processes:** System | **Views:** Teacher, Admin

**Description:** Questions are mapped to student performance categories (Weak, Average, Strong) and assigned a recommendation type (Revision, Practice, or Challenge). This mapping directly powers the Recommendation engine: when a student is identified as performing weakly in a topic, the Recommendation engine serves questions tagged as Revision for that category. Average students receive Practice questions. Strong students receive Challenge questions. Each mapping also carries a priority rank to control the order in which questions are offered within a category.

**Integration:** Recommendation module reads this mapping directly; changes affect personalised learning paths immediately.

**Acceptance Criteria:**
- Given a question is mapped to the Weak category with type Revision, a student in the Weak band for that topic receives this question as a practice suggestion.
- Given a question's performance category mapping is removed, the Recommendation engine stops offering that question for that category.

### REQ-QNS-010 — Question Statistics
**Priority:** Standard (P1) | **Tags:** [REPORT][SCHEDULED]
**Actors — Initiates:** System (scheduled), Admin (on-demand trigger) | **Processes:** System | **Views:** Teacher, Admin

**Description:** The system computes seven statistical metrics for each question by aggregating student response data from the Quiz, Quest, and Exam modules. These metrics are stored in a one-to-one statistics record per question and refreshed on a nightly schedule. An admin can also trigger on-demand computation for a specific question.

The seven metrics are:
- Difficulty Index: percentage of students who answered correctly (0–100)
- Discrimination Index: difference in correct-answer rate between the top 27% and bottom 27% of students (Kelley D-index; −100 to +100; negative value flags a mis-keyed or poor question)
- Guessing Factor: MCQ only; estimated proportion of correct answers due to guessing, based on the bottom group's performance rate (null for non-MCQ questions)
- Minimum Response Time: shortest time a correct answer was given
- Maximum Response Time: longest valid response time (outliers excluded)
- Average Response Time: mean valid response time
- Total Attempts: count of evaluated, non-null student responses across all modules

A statistics view screen shows these metrics for a single question. An analytics overview shows question-bank-wide distributions.

**Business Rules:** BR-QNS-004 [D31 formula contract — see statistics_help in module knowledge]

**Acceptance Criteria:**
- Given a question has been answered by 100 students with 70 correct, the Difficulty Index shows 70.
- Given the Discrimination Index is negative for a question, the statistics view flags the question as "Potentially Mis-keyed — Review Recommended."
- Given a question type is Essay, the Guessing Factor is blank (not computed).
- Given the statistics scheduler runs at night, all questions whose answer data has changed since the last run are recomputed.

### REQ-QNS-011 — Usage Logging
**Priority:** Standard (P1) | **Tags:** [INTEGRATION]
**Actors — Initiates:** Quiz, Quest, Exam modules (external) | **Processes:** System | **Views:** Teacher, Admin

**Description:** Every time a question is included in an assessment, the consuming module (Quiz, Quest, or Exam — not the Question Bank) creates a usage log record noting the assessment type, the specific assessment's identity, and the timestamp. The Question Bank uses these records to gate editing and deletion: a question that has been answered by any student cannot be edited or deleted. The usage log is append-only; no record is ever modified or removed.

Teachers can view a list of all assessments in which a specific question has been used, including the date used.

**Acceptance Criteria:**
- Given a question has a usage log entry, the Question Bank detail view shows "Used in 3 assessments."
- Given a question has been answered by a student, the Edit button on that question shows a message "This question has been answered by students. Use Clone to create a variant."
- Given an admin attempts to force-delete a question that has usage log entries, the system blocks the deletion.

### REQ-QNS-012 — Bulk Import via Excel
**Priority:** Standard (P1) | **Tags:** [DATA_ENTRY]
**Actors — Initiates:** Teacher, Admin | **Processes:** System | **Views:** Teacher, Admin

**Description:** Teachers can import up to 500 questions at a time from a standard Excel file downloaded from the Question Bank. The import follows a two-step process: validate first, then commit. In the first step, the system parses every row and reports errors (missing fields, unrecognised codes, invalid values) and warnings (likely duplicates). The teacher can correct errors and re-upload, or choose to import only the valid rows and skip the problematic ones. In the second step, the confirmed questions are created as Drafts. Imported questions cannot skip the review and approval process.

**Acceptance Criteria:**
- Given an Excel file with 200 rows, 180 valid and 20 with errors, the validation summary shows "180 valid, 20 with errors" and allows importing only the valid rows.
- Given an imported question has a class code that does not exist in the school's setup, that row is flagged as invalid and not imported.
- Given the teacher clicks "Import Valid Rows Only," exactly 180 Draft questions are created; none of the 20 erroneous rows appear in the bank.

### REQ-QNS-014 — AI-Assisted Question Generation
**Priority:** Core (P0) | **Tags:** [DATA_ENTRY][INTEGRATION]
**Actors — Initiates:** Teacher, Admin | **Processes:** AI System (external) | **Views:** Teacher, Admin

**Description:** A teacher can generate draft questions by specifying a curriculum context (Class, Subject, Lesson, Topic), a question type, a Bloom's Taxonomy level, a Complexity Level, and a count (up to 20). The system calls the selected AI provider (either an OpenAI model or a Google Gemini model), builds a curriculum-aware structured prompt, and returns a list of generated draft questions. Each generated question is saved with status = Draft and the AI-generated flag set to true, so it must pass through the full review workflow before use.

AI provider API keys must never appear in source code — they are stored in the server environment and loaded via the application's configuration system. The generation endpoint is rate-limited to prevent runaway API costs. A dedicated form request validates all input before any AI call is made.

**Business Rules:** BR-QNS-008

**Acceptance Criteria:**
- Given a teacher requests 5 MCQ questions on "Photosynthesis" at Bloom Level 3, the system calls the configured AI provider and returns up to 5 Draft questions with the AI-generated flag set.
- Given no AI provider key is configured, the system displays "AI Question Generation is not available — please contact the administrator" and makes no API call.
- Given a teacher submits 11 generation requests within one minute, the 11th request is refused with "Too many requests — please wait before generating more questions."
- Given a source code search is run for the literal text of any AI API key, no match is found anywhere in the codebase.

**Integration:** OpenAI API (structured prompt, JSON response parsing), Google Gemini API (same contract)

## 5. Data Requirements

### 5.1 Key Business Entities

**Question** (central entity): a single assessment item identified by a globally unique identifier, anchored to the curriculum hierarchy, carrying full taxonomy tags, owned by a school or the platform, and progressing through a managed lifecycle.

**Answer Option**: one of up to five choices for MCQ and Match questions, associated with a question, ordered by display position, and marked correct or incorrect.

**Question Tag**: a free-form keyword label (e.g. "Board 2024") that may be attached to many questions to support informal search.

**Media Asset**: a physical file (image, audio, video, or PDF) stored with a checksum for deduplication, linked to a question or option with a display position and purpose context.

**Review Log Entry**: an immutable record of a reviewer's decision (approve or reject) on a question at a point in time, including the comment and the reviewer's identity.

**Version Snapshot**: a complete point-in-time copy of a question's full state, captured before each content modification.

**Usage Log Entry**: an immutable record created by a consuming module (Quiz, Quest, or Exam) each time a question is included in an assessment.

**Question Statistics**: a computed metrics record (one per question) holding Difficulty Index, Discrimination Index, Guessing Factor, response-time metrics, and the date of last computation.

**Performance Category Mapping**: a link from a question to a student performance band (Weak / Average / Strong) with a recommendation type and a priority rank.

### 5.2 Privacy Classification

| Entity | Privacy Level | Notes |
|--------|--------------|-------|
| Question content | Internal | Visible to teachers; not PII |
| Answer options | Internal | Not PII |
| Usage log (student answers via stats) | Confidential | Statistical aggregates only — no individual student record stored in QNS tables |
| Review log (reviewer identity + comment) | Internal | Staff record; not PII but sensitive to review culture |
| Media assets | Internal | May contain photos of text materials; not student PII |

## 6. Workflows

### Workflow 1 — Question Lifecycle (Primary FSM)

**Trigger:** Teacher saves a new question or changes a question's status.
**End States:** Published (active use), Archived (retired).
**Actors:** Teacher (author), Reviewer, Admin, System.

| Step | Actor | Action | System Response |
|------|-------|--------|-----------------|
| 1 | Teacher | Completes creation form and saves | Question created with status = Draft |
| 2 | Teacher | Clicks "Submit for Review" | Status → In Review; review queue entry created; reviewer notified |
| 3 | Reviewer | Reviews question content | No status change |
| 4a | Reviewer | Clicks "Approve" (comment optional) | Status → Approved; review log entry created; teacher notified |
| 4b | Reviewer | Clicks "Reject" (comment required) | Status → Rejected → Draft; review log entry created; teacher notified with comment |
| 5 | Teacher (if rejected) | Edits question content | Version snapshot created before edit |
| 5a | Teacher (if rejected) | Re-submits for review | Returns to Step 2 |
| 6 | Admin / Teacher | Clicks "Publish" | Status → Published; question appears in all eligible assessment pickers |
| 7 | Admin | Clicks "Archive" | Status → Archived (terminal) |

**Exception Path:** If the assigned reviewer becomes unavailable, the question remains in In Review indefinitely. An admin must manually intervene to change the status. No automatic escalation or timeout exists in the current design.

**Alternative Path (Fast-Track):** An admin may move a question directly from Draft to Approved, bypassing In Review. This creates a review log entry. The question still requires a separate Publish action.

**Illegal Transitions (system blocks these):**
- In Review → Published (must go through Approved first)
- Archived → Published (must return to Draft first)
- Published → Draft if students have answered the question
- AI-generated question: Draft → Approved (must go through In Review)

### Workflow 2 — AI Question Generation

**Trigger:** Teacher submits the AI Generation form.
**End State:** Draft questions created, ready for teacher review.
**Actors:** Teacher, AI System (external), System.

| Step | Actor | Action | System Response |
|------|-------|--------|-----------------|
| 1 | Teacher | Opens AI Generator screen | Form displays; provider, curriculum, and type selectors shown |
| 2 | Teacher | Selects Provider, Class, Subject, Lesson, Topic, Question Type, Bloom Level, Complexity, Count | — |
| 3 | System | Validates form input | Rejects if required fields missing; rejects if count > 20 |
| 4 | System | Checks rate limit (max 10 requests/min/user) | Returns HTTP 429 if limit exceeded |
| 5 | System | Calls AI provider API with structured curriculum-aware prompt | API key loaded from server configuration, never from source code |
| 6 | System | Parses JSON response into question records | — |
| 7 | System | Creates Draft question records with AI-generated flag = true | — |
| 8 | Teacher | Reviews generated questions on the AI Review screen | Can edit fields, then submits each for review |
| 9 | Normal review workflow | Proceeds as Workflow 1 | AI-generated flag prevents bypassing In Review |

**Exception Path:** If the AI provider API returns an error or times out, the system displays a user-friendly error message. No partial questions are created. The teacher may retry.

### Workflow 3 — Excel Bulk Import

**Trigger:** Teacher uploads an Excel file via the Import screen.
**End State:** Valid questions created as Drafts.
**Actors:** Teacher, System.

| Step | Actor | Action | System Response |
|------|-------|--------|-----------------|
| 1 | Teacher | Downloads the standard import template | Excel file delivered |
| 2 | Teacher | Fills template (up to 500 rows) and uploads | — |
| 3 | System | Validates file format and all rows | Reports count: valid, errors, warnings (likely duplicates) |
| 4 | Teacher | Reviews validation summary | May fix errors and re-upload, or proceed with valid rows only |
| 5 | Teacher | Confirms import | — |
| 6 | System | Creates confirmed rows as Draft questions | Success summary: "X questions imported, Y skipped" |

**Exception Path:** If the file exceeds 500 rows, the system rejects it immediately. If a row references a class or subject code that does not exist in the school's setup, that row is marked as invalid.

### Workflow 4 — Question Statistics Computation

**Trigger:** Nightly scheduled job or admin's on-demand trigger.
**End State:** Statistics record updated for each question.
**Actors:** System (automated), Admin (on-demand).

| Step | Actor | Action | System Response |
|------|-------|--------|-----------------|
| 1 | System / Admin | Trigger computation | Job dispatched to background queue |
| 2 | System | Identifies questions with new answer data since last computation | Delta check on answer timestamps |
| 3 | System | For each question: aggregates correct/incorrect answers from Quiz, Quest, and Exam modules | — |
| 4 | System | Computes Difficulty Index, Discrimination Index (Kelley 27% split), Guessing Factor, time metrics | Null if fewer than 4 attempts per 27% group |
| 5 | System | Updates (or creates) statistics record; sets Last Computed timestamp | — |
| 6 | System | Writes Performance Category mapping rows if statistics cross thresholds | Feeds Recommendation engine |

**Exception Path:** Computation is wrapped per-question in a transaction with a consistent read. If computation fails for one question, that question is logged as failed and the job continues with the rest. A system alert is raised if more than 10% of questions fail.
