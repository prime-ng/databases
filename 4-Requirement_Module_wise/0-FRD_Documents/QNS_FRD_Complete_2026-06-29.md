# SECTION 1 — FUNCTIONAL REQUIREMENTS DOCUMENT

## 1. Module Overview

### 1.1 Purpose

The Question Bank is the central, curriculum-anchored content repository for all assessment activities across the Prime-AI platform. It stores questions authored by teachers or generated by AI, maintains a structured review and approval lifecycle before questions are used in any assessment, and provides analytical feedback on question quality based on actual student response data. Every question the platform ever asks a student — whether in a quiz, a practice quest, an online exam, or a printed offline paper — originates from this module.

### 1.2 Business Value

- Eliminates duplicate question authoring: a well-tagged, approved question is reusable across any quiz, quest, or exam for the appropriate class and subject.
- Ensures cognitive balance: Bloom's Taxonomy tagging enables assessment builders to guarantee a spread of remember-through-create questions rather than accidentally creating a recall-heavy paper.
- Enables AI-assisted content creation: teachers can generate draft questions from OpenAI GPT-4o-mini or Google Gemini 2.0 Flash, accelerating bank growth significantly while retaining human review before publication.
- Drives personalized learning: the Performance Category mapping connects question difficulty to student outcome bands (Weak/Average/Strong), enabling the LXP Recommendation engine to serve the right question to the right student.
- Provides empirical quality feedback: Difficulty Index, Discrimination Index, and Guessing Factor (computed from real student responses) tell teachers which questions are too easy, mis-keyed, or heavily guessed.

### 1.3 Scope

**In scope:**
- Question authoring (manual create/edit/clone/delete) for six question types
- Curriculum anchoring to Class, Subject, Lesson, Topic, Competency hierarchy from Syllabus module
- Bloom's Taxonomy, Cognitive Skill, Complexity Level, and Question Type Specificity tagging
- Rich content formats: plain text, HTML, Markdown, LaTeX (MathJax rendering), and JSON
- Media attachments: image, audio, video, PDF for questions, options, and explanations
- DRAFT → IN_REVIEW → APPROVED → PUBLISHED → ARCHIVED review workflow
- Version history: full JSON snapshots on content modification
- Keyword tag system for informal search beyond the curriculum hierarchy
- Multi-topic mapping with topic weightage
- Performance category mapping for LXP personalized learning paths
- AI question generation (OpenAI GPT-4o-mini and Google Gemini 2.0 Flash)
- Excel bulk import with pre-validation and confirm-before-commit two-step process
- Printable question paper generation (with LaTeX rendering)
- Question statistics: Difficulty Index, Discrimination Index, Guessing Factor, time metrics
- Usage logging (insert-only; written by Quiz/Quest/Exam consuming modules)
- Data isolation per school tenant (no cross-school question sharing)

**Out of scope:**
- Actual student assessment delivery (Quiz/Quest/Exam modules own delivery)
- Marksheet computation or grade aggregation
- Staff/HR leave management or payroll
- Student portal dashboard (separate module)
- Cross-tenant question marketplace (not designed; would require PrimeGurukul-level workflow)

### 1.4 Terminology

| Business Term | Meaning |
|---------------|---------|
| Question | A single assessment item (a question stem, options if MCQ, correct answer, explanation) stored in the Question Bank. |
| Bloom's Taxonomy Level | One of six cognitive levels (Remember, Understand, Apply, Analyze, Evaluate, Create) that classifies the cognitive demand of a question. |
| Discrimination Index | A statistical measure (Kelley's D-index) of how well a question differentiates high-scoring from low-scoring students. Positive values indicate good discrimination. |
| Difficulty Index | The percentage of students who answered a question correctly. Low value = hard question; high value = easy question. |
| Guessing Factor | For MCQ questions: the estimated proportion of correct answers attributable to random guessing, based on the number of options and empirical bottom-group performance. |
| Availability Scope | A setting on each question controlling who can see and use it: All Teachers (Global), This School Only, This Class Only, This Section Only, This Student Group Only, or One Specific Student. |
| Content Owner | Either the Platform (PrimeGurukul) — questions are read-only for school teachers and can only be cloned — or the School — questions are fully editable by authorized teachers. |
| Usage Log | An immutable record created by Quiz/Quest/Exam modules each time a question is included in an assessment. The Question Bank does not create these records itself. |
| Version Snapshot | A complete copy of a question's full state (content, options, taxonomy, marks) stored before any content modification. Enables audit and rollback. |
| Review Workflow | The DRAFT → IN_REVIEW → APPROVED/REJECTED → PUBLISHED lifecycle that every question must pass through before use in any formal assessment. |
| Performance Category | A classification of student performance level (Weak, Average, Strong) from the Syllabus module, used to route appropriate questions to students via the Recommendation engine. |
| AI Generator | An interface allowing teachers to request question drafts from OpenAI (GPT-4o-mini) or Google Gemini (2.0 Flash) using structured curriculum-aware prompts. Generated questions are always created as DRAFT. |

## 3. Functional Requirements

### REQ-QNS-001 — Question Creation and Management [DATA_ENTRY] [WORKFLOW]
**Priority:** Core (P0) | **Code Status:** PARTIAL (~85%) — auth gaps on some methods

Each question record captures the following grouped information:

**Identity and content:** An internal title (not shown to students), a toggle for whether to display the title, the question text itself, a content format selector (Plain Text / HTML / Rich Text / LaTeX / JSON), and an optional teacher explanation revealed to students after answering.

**Curriculum anchoring:** Every question is anchored to a Class, Subject, Lesson, Topic, and Competency. All five are required and are drawn from the Syllabus module's established curriculum hierarchy. A question cannot be saved without this complete chain.

**Taxonomy tags:** Every question must carry a Bloom's Taxonomy level, a Cognitive Skill, a Complexity Level (Easy/Medium/Hard/Very Hard), and a Question Type Specificity. All four are required.

**Assessment metadata:** Marks (decimal, default 1.00), Negative Marks (default 0.00), and Expected Time to Answer (seconds, optional hint for assessment timers).

**Usage flags:** Independent Boolean flags control which assessment types may use the question: Quiz, Quest/Practice, Online Exam, and Offline Exam. A question may be eligible for any combination.

**Ownership and availability:** Questions are owned by either the Platform (PrimeGurukul) or the School. Availability scope controls who can see the question: All Teachers (Global), This School, This Class, This Section, This Student Group, or One Specific Student.

**Reference source:** Optional fields for the textbook the question is sourced from (with page reference), an external reference code, and free-text reference material.

**Acceptance Criteria:**
- Given a teacher creates an MCQ with four options and exactly one marked correct, the question saves with status "Draft" and version number 1.
- Given a teacher attempts to save without selecting a Bloom Level, the system refuses and highlights the missing field.
- Given a teacher saves a question with Negative Marks equal to its full marks value, the system refuses.
- Given an unauthenticated user attempts to access the question list, the system returns an access-denied response.
- Given a teacher edits a question that is currently in use in an active exam, the system blocks the edit and displays the assessment context where it is in use.

### REQ-QNS-002 — Question Types and Rich Content Formats [DATA_ENTRY] [CONFIGURATION]
**Priority:** Standard (P1) | **Code Status:** PARTIAL — schema exists; full UI for all 6 types needs completion

The system supports seven question formats. The format is selected via the Question Type field linked to the Syllabus module's question type catalogue:

| Type | Name | Options Required | Answer Capture |
|------|------|-----------------|---------------|
| MCQ (Single) | Multiple Choice — One Correct | Yes (minimum 2, maximum 5) | One option marked correct |
| MCQ (Multi) | Multiple Choice — Multiple Correct | Yes (minimum 2) | One or more options marked correct |
| True/False | True or False | System-generated (2 options) | Single Boolean choice |

When the content format is LaTeX, the question view, edit preview, print, and all assessment delivery screens must include MathJax or KaTeX for rendering. This must be conditionally loaded only when a question in scope uses LaTeX format.

**Acceptance Criteria:**
- Given a teacher selects MCQ (Single) and marks two options as correct, the system refuses and requires exactly one.
- Given a teacher selects Essay type, the options section disappears from the form.
- Given a question with LaTeX content is displayed, mathematical expressions render correctly using MathJax.
- Given a True/False question is created, the system auto-generates two options (True and False) with ordinal 1 and 2.

### REQ-QNS-003 — Bloom's Taxonomy and Taxonomy Tagging [CONFIGURATION] [DATA_ENTRY]
**Priority:** Core (P0) | **Code Status:** DONE (~95%) — fully implemented in CRUD

Every question carries a complete taxonomy profile:

- **Bloom's Taxonomy Level** (6 levels in ascending cognitive order): 1-Remember, 2-Understand, 3-Apply, 4-Analyze, 5-Evaluate, 6-Create. Assessment builders use this to generate cognitively balanced papers. Analytics reports group question distribution by Bloom level.
- **Cognitive Skill**: A more granular classification of the mental process required — Recall, Comprehension, Application, Critical Thinking, Creative Thinking, and others as configured in the Syllabus module.
- **Complexity Level**: A teacher-facing difficulty rating — Easy, Medium, Hard, Very Hard. Distinct from Bloom level: a Remember-level question can still be rated Hard based on content obscurity.
- **Question Type Specificity**: A sub-classification within the question type — for MCQ: Single-Correct, Multi-Correct, Assertion-Reason; for Essay: Analytical, Descriptive, Narrative.

All four taxonomy fields are mandatory before a question can be submitted for review.

**Acceptance Criteria:**
- Given a question is saved without a Bloom Level, the submit-for-review action is blocked.
- Given an assessment builder filters by Bloom Level = "Apply," only questions with that exact level appear in results.
- Given a teacher creates a question at Bloom Level 1 (Remember) and Complexity Level = Hard, both values are stored independently and correctly.

### REQ-QNS-004 — Version History [WORKFLOW] [DATA_ENTRY]
**Priority:** Standard (P1) | **Code Status:** PARTIAL (~75%) — snapshot created on update, but version-triggering logic in controller not service

Every content modification to a question creates a Version Snapshot before the change is applied. A snapshot captures the full prior state: question fields, all answer options, and media references in a JSON record.

**What triggers a new version:** Changes to question text, content format, question type, marks, negative marks, or any answer option's text or correct-answer flag.

**What does NOT trigger a new version:** Status transitions (Draft → In Review, Approved → Published) and metadata-only changes (taxonomy tags, availability scope, usage flags, reference source).

The Version History screen shows each snapshot with: version number, change reason (optional text the teacher supplies), the staff member who made the change, and the timestamp. Teachers and administrators can view the complete modification history for any question.

**Acceptance Criteria:**
- Given a teacher edits a question's text, a version snapshot record is created capturing the previous state before the change.
- Given a question has been content-edited three times, three version records exist with version numbers 1, 2, and 3.
- Given a question's status changes from Approved to Published with no content change, no version snapshot is created.
- Given a teacher views version history, they see each version with the change reason and the name of the staff member who made the change.

### REQ-QNS-005 — Review and Approval Workflow [WORKFLOW] [APPROVAL]
**Priority:** Core (P0) | **Code Status:** PARTIAL (~60%) — approve/reject in QuestionBankController; dedicated controller not built; no notifications

Questions follow a structured review lifecycle before they can be used in any assessment:

**Draft:** The initial state for all newly created, imported, or AI-generated questions. The question is editable and not visible in assessment builders.

**In Review:** The teacher submits the question for review. The question is locked for content edits while under review.

**Approved:** A reviewer (Department Head or School Admin) has checked and approved the question. The question remains editable by an Admin but is not yet in assessment pickers.

**Published:** An Admin explicitly publishes the question. Only Published questions are visible and selectable in Quiz, Quest, and Exam builders.

**Rejected:** A reviewer rejects the question with a mandatory written comment explaining the issue. The question reverts to Draft status so the teacher can revise and resubmit.

**Archived:** A question is retired from active use. No further transitions are possible. Archived questions are excluded from all assessment pickers but remain in version history.

Every status transition triggered by a reviewer creates an entry in the Review Log capturing: the reviewer's name, the action taken, any comment provided, and the date and time.

**Acceptance Criteria:**
- Given a teacher clicks "Submit for Review," the question status changes to In Review and the teacher can no longer edit its content.
- Given a reviewer rejects a question without providing a comment, the system refuses and requires a rejection reason.
- Given a reviewer approves a question, a review log entry is created with the reviewer's name and approval timestamp.
- Given an AI-generated question is submitted, the system does not allow bypassing the In Review stage even if the submitter is an Admin.
- Given an Admin clicks "Archive" on a Published question, no further status transitions are possible.

### REQ-QNS-006 — Media Attachments [DATA_ENTRY]
**Priority:** Standard (P1) | **Code Status:** PARTIAL (~75%) — model and CRUD exist; policy gate bug on media store controller

Questions and their answer options may have media attachments: Image, Audio, Video, and PDF files.

Media can be attached at four context levels:
- **Question media:** Images or diagrams that illustrate the question stem itself.
- **Option media:** Media specific to one answer choice (useful for image-based options).
- **Question explanation media:** Diagrams shown to the student in the teacher's explanation after answering.
- **Option explanation media:** Media clarifying why a specific option was correct or incorrect.

Media files are stored in the Media Store with their filename, file path, storage location (local or cloud), file size in bytes, and a SHA-256 checksum for deduplication. If the same file is uploaded twice (same checksum), the system links to the existing store record rather than duplicating the file.

**Acceptance Criteria:**
- Given a teacher uploads an image to a question, the image appears inline in the question view and in the print layout.
- Given a teacher uploads the same image file twice, only one Media Store record is created; both questions link to the same record.
- Given a teacher attempts to attach a file type that is not Image/Audio/Video/PDF, the upload is rejected.

### REQ-QNS-007 — Keyword Tag System [CONFIGURATION] [DATA_ENTRY]
**Priority:** Standard (P1) | **Code Status:** DONE (~90%) — well-implemented

Custom keyword tags provide flexible search and organisation beyond the formal curriculum hierarchy. Tags are free-form labels that teachers create at the school level (examples: "NCERT Important," "Board Exam 2024," "Frequently Incorrect," "Practice Set A").

Tags are created and managed by School Admins and Teachers. Each tag has a short code and a full name. Questions may carry multiple tags. Tags are searchable via autocomplete in the question create and edit forms. Multiple questions may share the same tag, enabling batch filtering and export by topic collection.

**Acceptance Criteria:**
- Given a teacher creates a new tag named "Board 2024," the tag is immediately available for assignment to questions.
- Given a teacher searches for questions tagged "Board 2024," only questions with that tag appear.
- Given a School Admin deletes a tag, the tag is removed from the tags list but the questions that carried it are not deleted.
- Given a teacher assigns three tags to a question, all three appear in the question's detail view.

### REQ-QNS-008 — Multi-Topic Coverage Mapping [DATA_ENTRY]
**Priority:** Enhanced (P2) | **Code Status:** DONE (schema + model) — create/edit handles topic_weightage

A single question may test content from more than one topic — for example, an algebra problem that also requires geometry knowledge. The system supports mapping each question to multiple Syllabus topics with a percentage weightage.

The primary topic (used for fast indexing and backward compatibility) is stored directly on the question record. Additional topics are captured in a separate mapping table. When multiple topics are assigned, the sum of their weightage values should equal 100. This is enforced as a soft warning at save time, not a hard error.

**Acceptance Criteria:**
- Given a teacher maps a question to two topics with weightage 60 and 40, both mappings are saved and the combined weightage is 100.
- Given a teacher maps a question to two topics with weightage 60 and 50, the system saves but shows a warning that weightage does not sum to 100.
- Given a teacher views a question with multi-topic mapping, all mapped topics and their weightage values appear in the detail view.

### REQ-QNS-009 — Performance Category Mapping [CONFIGURATION] [INTEGRATION]
**Priority:** Enhanced (P2) | **Code Status:** DONE (schema + model + controller handling) — no automated update from statistics

Questions are linked to Performance Categories from the Syllabus module to power personalised learning paths. Each link carries a Recommendation Type (Revision, Practice, or Challenge) and a priority rank within the category.

The intent: when the Recommendation engine identifies a student as "Weak" in a topic, it queries this mapping to surface questions with Recommendation Type = Revision. "Average" students receive Practice questions. "Strong" students receive Challenge questions.

The QuestionStatisticsService automatically updates priority rankings based on computed Difficulty Index bands:
- Difficulty 0–29.99 (Very Hard) → priority 9 (high — revision material)
- Difficulty 30–69.99 (Moderate) → priority 5 (standard practice)
- Difficulty 70–100 (Easy) → priority 2 (challenge material)

**Acceptance Criteria:**
- Given a teacher maps a question to the "Weak" performance category with Recommendation Type = Revision, that mapping appears in the Recommendation engine's query results for weak-performing students.
- Given the statistics service computes a Difficulty Index of 20 for a question, its performance category mapping priority is automatically updated to 9.

### REQ-QNS-010 — Question Statistics [REPORT] [SCHEDULED]
**Priority:** Standard (P1) | **Code Status:** PARTIAL (~70%) — QuestionStatisticsService exists with full formula; sync route exists; not yet queued

After students answer questions in quizzes, quests, and exams, the system computes statistical quality metrics for each question. These metrics are stored as a single statistics record per question and updated whenever new response data is available.

**Metrics computed:**

| Metric | Formula | Meaning |
|--------|---------|---------|
| Difficulty Index | (Correct answers ÷ Total attempts) × 100 | % of students who answered correctly. Low = hard. |
| Discrimination Index | (Top-27%-correct-rate − Bottom-27%-correct-rate) × 100 | How well the question separates high from low scorers. Kelley's D-index, clamped to −100 to +100. |
| Guessing Factor | MCQ only: Bottom-27%-correct-rate × 100 if attempts ≥ 30; else 100 ÷ option count | Estimated guessing contribution. |
| Min Time (seconds) | Minimum response time among students who answered correctly | |
| Max Time (seconds) | Maximum response time within outlier ceiling (expected time × 3, max 3600s) | |
| Average Time (seconds) | Average of valid response times within outlier ceiling | |
| Total Attempts | Count of evaluated, non-null answer rows across all assessment types | |

Statistics computation should run as a scheduled background job (not blocking any HTTP request). An Admin may also trigger on-demand computation for a specific question.

**Acceptance Criteria:**
- Given 10 students answer a question and 7 answer correctly, the Difficulty Index computes to 70.00.
- Given fewer than 4 attempts exist in either the top or bottom 27% group, the Discrimination Index is recorded as "not yet computed" (null).
- Given an Admin triggers on-demand computation, the statistics record shows a "Last Computed" timestamp updated to the current time.
- Given the statistics job runs, it reads answer data from both Quiz/Quest responses and Exam responses.

### REQ-QNS-011 — Question Usage Logging [DATA_ENTRY] [REPORT]
**Priority:** Standard (P1) | **Code Status:** PARTIAL (~60%) — model exists; display view exists; records written by consuming modules

Every time a question is added to a Quiz, Quest, or Exam, a usage log record is created by the consuming module. The Question Bank does not create these records; it only displays them.

The usage log records: which question was used, which assessment type (Quiz, Quest, Online Exam, Offline Exam), the specific assessment identifier (quiz ID, exam ID), and the date and time of use.

From the Question Bank, teachers and administrators can view the usage history of any question — seeing every assessment where it has appeared, with dates. This visibility informs decisions about whether to retire or revise a question that has been widely used.

The QuestionUsageCheckService enables the Question Bank to block direct content editing of any question that is currently in use in an active assessment. The staff member is shown which assessments are using the question before being blocked.

**Acceptance Criteria:**
- Given the Quiz module adds a question to a quiz, a usage log record appears in the Question Bank's usage history for that question.
- Given a teacher attempts to edit a question that is currently in use in an active exam, the system blocks the edit and shows the exam context.
- Given a teacher views a question's detail page, a "Usage History" section lists all assessments that have used this question.

### REQ-QNS-012 — Excel Bulk Import [DATA_ENTRY]
**Priority:** Standard (P1) | **Code Status:** PARTIAL (~70%) — import classes exist; auth gap on validate/start endpoints

Teachers may import large numbers of questions from a structured Excel template in a two-step process:

**Step 1 — Validate:** The teacher uploads the Excel file. The system parses every row, validates required fields, checks for duplicates (same question text + class + subject), and reports any issues without creating any records. The teacher receives either a validation-passed confirmation or a downloadable error report showing exactly which rows failed and why.

**Step 2 — Confirm and Import:** If validation passes, the teacher confirms the import. The system then creates all valid questions as Draft records, ready for review. The teacher receives a count of questions created and any rows that were skipped.

All imported questions are created with status = Draft. They must go through the standard review workflow before use in assessments.

**Import file format:** One question per row. Required columns: question text, question type code, class code, subject code, lesson code, topic code, Bloom level, complexity level. Optional columns: answer options A through E, correct option indicator, marks, negative marks, teacher explanation.

**Acceptance Criteria:**
- Given a teacher uploads a valid Excel file with 20 questions, the validation step reports 20 rows passed and 0 errors.
- Given a teacher uploads a file where row 5 has a duplicate question text matching an existing question in the same class and subject, row 5 is flagged as a duplicate in the validation report and skipped on import.
- Given the validation step passes and the teacher clicks "Confirm Import," 20 Draft questions are created.
- Given a teacher attempts to upload a file that is not Excel or CSV format, the upload is rejected.

### REQ-QNS-014 — AI Question Generation [DATA_ENTRY] [INTEGRATION]
**Priority:** Core (P0) | **Code Status:** CRITICAL GAP (~30%) — UI exists but returns hardcoded demo data; zero authorization; API keys moved to env() but not config('services.*')

Teachers and Administrators can generate draft questions using AI providers. The AI Generator interface accepts:
- AI provider selection (OpenAI GPT-4o-mini or Google Gemini 2.0 Flash)
- Class, Subject, Lesson, and Topic (cascading dropdowns)
- Question type, Bloom Level, Complexity Level, Cognitive Skill, Question Type Specificity
- Number of questions to generate (default 5, maximum 20)
- Optional additional instructions for the AI prompt

On submission, the system calls the selected AI provider using a structured, curriculum-aware prompt. The AI response is parsed into structured question records. Each generated question is saved as Draft with a flag marking it as AI-generated.

The teacher reviews the generated questions, edits as needed, and submits each for standard review. AI-generated questions cannot bypass the review workflow.

The AI generation endpoint must be rate-limited (maximum 10 requests per user per minute) to prevent runaway API costs.

**Security Requirements:**
- API keys must be stored in environment configuration only, accessed via the application configuration layer (not read directly from environment variables in controller code).
- AI generation must require explicit authorization — unauthorized users cannot trigger AI calls.
- Rate limiting must be enforced at the route level before the AI provider is contacted.

**Acceptance Criteria:**
- Given a teacher submits a generation request for 5 MCQ questions on "Photosynthesis" at Bloom Level Apply, the system calls the configured AI provider and returns up to 5 Draft questions.
- Given an AI provider key is not configured, the system returns a user-friendly error: "AI question generation is not available. Please contact your administrator."
- Given a teacher makes 11 AI generation requests within one minute, the 11th request is refused with an over-limit message.
- Given an unauthenticated user calls the AI generation endpoint, access is refused.
- Given the source code is inspected, no literal API key string appears anywhere in the codebase.

## 5. Data Requirements

### 5.1 Core Entities

**Question** (qns_questions_bank)
The central entity. A Question represents one assessment item anchored to the curriculum hierarchy, tagged with full taxonomy, carrying content in one of five formats, with status tracking, version counting, ownership, and availability scope.

Privacy classification: Internal (question text is educational content, not PII). Creator identity (created_by) is Internal.

**Answer Option** (qns_question_options)
Child entity of Question. Each option has text content, an ordinal for display order, a correct-answer flag, and an explanation. Questions have zero to five options depending on type. Options cascade-delete with the parent question.

Privacy: Internal.

**Media Store** (qns_media_store)
Stores physical media file metadata: UUID identifier, owner context, media type (Image/Audio/Video/PDF), filename, file path, MIME type, storage location (local or cloud), file size in bytes, and SHA-256 checksum for deduplication.

Privacy: Internal (educational media files).

**Question Media Link** (qns_question_media_jnt)
Junction entity linking a Question or Answer Option to a Media Store record. Carries a purpose context: Question (illustrates the question stem), Option (media for a specific option), Question Explanation, Option Explanation, or Recommendation (media for learning path context).

**Question Tag** (qns_question_tags)
A keyword label with a short code (unique across the school) and a display name. Tags are informal and school-created, existing outside the formal curriculum hierarchy.

**Version Snapshot** (qns_question_versions)
An immutable record storing the complete prior state of a question before a content modification. Contains the full JSON snapshot (question fields, options, media references), version number, change reason, and creating user.

Privacy: Internal (audit record).

**Review Log** (qns_question_review_log)
An immutable record of each review action taken on a question: reviewer identity, action taken (approved/rejected), comment, and timestamp. Insert-only — records are never updated or deleted.

Privacy: Internal (staff workflow audit).

**Question Statistics** (qns_question_statistics)
One record per question. Stores computed quality metrics: Difficulty Index, Discrimination Index, Guessing Factor, response time range and average, total attempt count, and computation timestamp.

Privacy: Internal (aggregated, not individual student-identifiable).

**Question Usage Log** (qns_question_usage_log)
An immutable record created by consuming modules (Quiz/Quest/Exam) when a question is included in an assessment. Records the question, the assessment type, the specific assessment identifier, and the usage timestamp. Insert-only.

Privacy: Internal.

**Usage Type** (qns_question_usage_type)
A pre-seeded reference table with four rows: Quiz, Quest/Practice, Online Exam, Offline Exam. Not editable by schools.

**Topic Coverage Mapping** (qns_question_topic_jnt)
Maps questions to multiple Syllabus topics with percentage weightage. The primary topic is stored on the question record; additional topics use this junction.

**Performance Category Mapping** (qns_question_performance_category_jnt)
Maps questions to Syllabus performance categories (Weak/Average/Strong bands) with a Recommendation Type (Revision/Practice/Challenge) and priority rank. Used by the Recommendation engine.

## 6. Workflows

### Workflow 1: Question Authoring Lifecycle

**Trigger:** Teacher clicks "Create Question" or opens an existing Draft question.
**End States:** Published (active in assessments), Archived (retired), Rejected and awaiting revision.
**Actors:** Subject Teacher | Department Head / School Admin | System

Steps:
1. Teacher selects question type, content format, curriculum anchoring (Class → Subject → Lesson → Topic → Competency), and enters question content.
2. Teacher selects all required taxonomy tags (Bloom Level, Cognitive Skill, Complexity, Type Specificity).
3. Teacher adds answer options (if MCQ/Match), marks correct answers, and optionally uploads media.
4. Teacher saves as Draft. System creates the question with version number 1 and status = Draft.
5. Teacher clicks "Submit for Review." System validates taxonomy completeness (BR-QNS-001) and MCQ correct-option rule (BR-QNS-002). If valid, status transitions to In Review.
6. Reviewer (Department Head or Admin) receives the review task and opens the question.
7. Reviewer approves → status moves to Approved. Review log entry created.
   Reviewer rejects (with mandatory comment) → status moves to Rejected. Review log entry created. Teacher is notified.
8. If Rejected: Teacher revises the question content → new version snapshot created → status auto-returns to Draft → teacher may resubmit.
9. Admin publishes the Approved question → status moves to Published. Question now appears in assessment builders.

**Exception Paths:**
- Teacher saves without completing taxonomy: save allowed; review submission blocked until all fields are populated.
- Admin fast-tracks a trusted question from Draft directly to Approved (skipping In Review): allowed for Platform-reviewed content; review log entry created.
- Reviewer is not available: question remains In Review until actioned; no auto-timeout in current design.

**Notifications Triggered:**
| Step | Recipient | Message |
|------|-----------|---------|
| Submit for Review (step 5) | Designated reviewer(s) | "A new question has been submitted for your review: [title]" |
| Reject (step 7) | Question author | "Your question [title] has been rejected. Reason: [comment]" |
| Approve (step 7) | Question author | "Your question [title] has been approved and is ready for publishing" |

---

### Workflow 2: AI Question Generation

**Trigger:** Teacher opens AI Question Generator and submits generation parameters.
**End State:** Draft questions created; teacher proceeds to review and submit workflow.
**Actors:** Subject Teacher / School Admin | System | External AI Provider

Steps:
1. Teacher selects AI provider, class, subject, lesson, topic, question type, Bloom level, complexity, count (1–20), optional instructions.
2. System checks authorization and rate limit (max 10 requests per user per minute).
3. System constructs a curriculum-aware structured prompt incorporating all selected parameters.
4. System sends HTTP request to the selected AI provider API using the key from application configuration.
5. AI provider returns a structured CSV/JSON response with question data.
6. System parses the response and creates Draft question records (status = Draft, created_by_AI = 1).
7. Teacher reviews each generated question, edits content as needed, and submits each for standard review.
8. Standard review workflow proceeds (Workflow 1 from step 5 onward).

**Exception Paths:**
- API key not configured: system returns user-facing error "AI question generation is not available"; no API call made.
- Rate limit exceeded (11th request in 1 minute): system returns "Too many requests" response; no API call made.
- AI provider returns invalid or unparseable response: system logs the error and returns "Generation failed; please try again" to the teacher.
- AI-generated question fails form validation (missing required field): question is skipped; teacher sees a count of created vs skipped.

---

### Workflow 3: Excel Bulk Import

**Trigger:** Teacher selects "Import Questions" and uploads an Excel file.
**End State:** Batch of Draft questions created, ready for standard review.

Steps:
1. Teacher downloads the standard import template.
2. Teacher fills in questions (one per row) and uploads the file.
3. System runs validation pass: parses all rows, checks required fields, valid codes, foreign key references, and duplicate detection (same content + class + subject).
4. If any errors: system returns a downloadable error report showing row numbers and error descriptions. No questions are created. Teacher corrects the file and restarts.
5. If validation passes: teacher sees a summary (N rows passed, 0 errors) and a "Confirm Import" button.
6. Teacher confirms. System creates all valid questions as Draft records.
7. System displays: "X questions imported successfully."

**Exception Paths:**
- File is not in Excel/CSV format: upload rejected immediately.
- All rows are duplicates: validation reports 0 new questions; import aborted.
- Session expires between validate and confirm: teacher must re-upload and re-validate.

---

### Workflow 4: Question Statistics Computation

**Trigger:** Scheduled background job (daily or weekly) or Admin triggers on-demand computation for a specific question.
**End State:** Statistics record updated with latest computed metrics.

Steps:
1. System loads answer data from two sources: Quiz/Quest response tables (lms_quiz_quest_attempt_answers) and Exam response tables (exam_attempt_answer), filtered to evaluated, non-null is_correct rows.
2. System counts total attempts. If zero, statistics update is skipped for this question.
3. System computes Difficulty Index: (correct answers ÷ total attempts) × 100.
4. If total attempts allow split (4+ in each 27% group): System ranks students by their overall assessment percentage, takes top 27% and bottom 27%, computes per-group correct rates, and derives the Discrimination Index = (top rate − bottom rate) × 100, clamped to [−100, +100].
5. If MCQ: System computes Guessing Factor using bottom-27% correct rate (if ≥ 30 attempts) or the baseline 100 ÷ option count (cold start).
6. System computes response time metrics using only valid times (> 0 seconds, < ceiling).
7. System upserts the statistics record (one row per question).
8. System updates performance category priority rankings on all linked category mappings based on Difficulty Index bands.

**Exception Paths:**
- Fewer than 4 attempts in top or bottom 27% group: Discrimination Index stored as null.
- No correct answers: Difficulty Index = 0.00; Guessing Factor computation proceeds normally.
- Non-MCQ question type: Guessing Factor stored as null.

## 7. Reporting and Analytics

### RPT-QNS-001 — Question Bank Bloom Distribution Report
**Purpose:** Show cognitive balance of the question bank per class and subject.
**Audience:** School Admin, Department Head, Exam Coordinator
**Frequency:** On demand
**Contents:** Count of questions per Bloom level (1-6), grouped by class and subject. Percentage distribution per level. Comparison against recommended distribution (e.g., CBSE balanced paper norms).
**Filters:** Class, Subject, Status (Published only, or all approved)
**Export:** PDF, Excel

### RPT-QNS-002 — Per-Question Statistics Report
**Purpose:** Show quality metrics for one question to inform revision or retirement decisions.
**Audience:** Subject Teacher, School Admin
**Frequency:** On demand (after each statistics computation)
**Contents:** Difficulty Index with interpretation band (Very Hard / Moderate / Easy), Discrimination Index with interpretation (Poor / Fair / Good / Excellent), Guessing Factor, Min/Max/Average response time, total attempt count, last computation timestamp.
**Filters:** Single question selected
**Export:** PDF

### RPT-QNS-003 — Question Bank Analytics Dashboard
**Purpose:** Bank-wide quality overview and growth tracking.
**Audience:** School Admin, Department Head
**Frequency:** On demand / weekly
**Contents:** Total question count by status (Draft / In Review / Approved / Published / Archived); AI-generated vs manually authored ratio; questions by subject; average Difficulty Index distribution; questions flagged for review (negative discrimination index).
**Filters:** Date range, class, subject
**Export:** PDF, Excel

### RPT-QNS-004 — Question Usage Report
**Purpose:** Track which questions are widely used and identify overused or underused content.
**Audience:** Exam Coordinator, School Admin
**Frequency:** On demand / per exam cycle
**Contents:** Questions sorted by usage count; assessment type breakdown (Quiz / Quest / Online Exam / Offline Exam); last used date; flag for questions used in > 3 assessments in the same academic year.
**Filters:** Class, Subject, Academic Year, Assessment Type
**Export:** Excel

### RPT-QNS-005 — AI-Generated Question Review Report
**Purpose:** Track the volume and status of AI-generated questions to assess AI contribution to the bank.
**Audience:** School Admin
**Frequency:** On demand / monthly
**Contents:** Count of AI-generated questions by status; count approved vs rejected vs pending; average time from generation to approval; common rejection reasons (from review comments).
**Filters:** Date range, subject, AI provider
**Export:** PDF, Excel

| — (new record) | Create / Import / AI Generate | — | DRAFT | current_version = 1; review_log = none |
| DRAFT | Teacher submits for review | BR-QNS-001 (taxonomy complete) + BR-QNS-002 (MCQ correct option) | IN_REVIEW | Content locked for teacher edits |
| DRAFT | Admin fast-approves | Admin permission | APPROVED | review_log entry created |
| IN_REVIEW | Reviewer approves | Reviewer permission | APPROVED | review_log entry (reviewer_id, reviewed_at, APPROVED) |
| IN_REVIEW | Reviewer rejects | BR-QNS-011 (comment required) | REJECTED | review_log entry (reviewer_id, comment, REJECTED); notification to teacher |
| APPROVED | Admin publishes | Admin permission | PUBLISHED | Question appears in assessment builders |
| APPROVED | Admin archives | Admin permission | ARCHIVED | Terminal; removed from all active picks |
| REJECTED | Teacher revises content | Teacher is author | DRAFT | New version snapshot created if content changed; question unlocked |
| PUBLISHED | Admin archives | Admin permission | ARCHIVED | Terminal; removed from assessment builders |
| ARCHIVED | — | No transitions permitted | — | — |

**Illegal transitions (must be blocked):**
- DRAFT → PUBLISHED (must pass through IN_REVIEW and APPROVED)
- IN_REVIEW → PUBLISHED (must pass through APPROVED)
- PUBLISHED → any state except ARCHIVED
- ARCHIVED → any state
