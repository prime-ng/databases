# SystemConfig (SYS) — Requirement Conditions Catalog
**Version:** 1.0 | **Date:** 2026-06-30 | **Source:** SYS_FRD_2026-06-30.md + SYS_FRD_Complete_2026-06-30.md
**Module:** SystemConfig | **Type:** Central | **DB:** prime_db + global_db

---

| Condition ID | Entity / Field | Condition (Business Language) | Type | Trigger | On-Violation Behaviour |
|---|---|---|---|---|---|
| BR-SYS-001 | Platform Setting / Key | The setting key must not change after the setting is first saved | Validation | Setting update | Strip key from update payload; no validation error — silently ignored |
| BR-SYS-002 | Menu Item / System Identifier | The menu system identifier (code) must not change after the item is first saved | Validation | Menu update | Strip code from update payload |
| BR-SYS-003a | Menu Item / Category + Parent | A category heading item must have no parent | Validation | Menu create / edit / reorder | HTTP 422: "Category headings cannot have a parent item." |
| BR-SYS-003b | Menu Item / Non-Category + Parent | A non-category item (is_category = false) may have a parent that exists in the menu registry | Validation | Menu create / edit | Allow; parent must be a valid, non-deleted menu item |
| BR-SYS-004 | Menu Item / Sort Position | After any drag-drop reorder, all siblings at the moved item's level receive sequential sort positions starting from 1 | Calculation | Menu reorder (drag-drop) | Post-save sibling loop; no user-visible error |
| BR-SYS-005a | Platform Setting / Value visibility | If is_public = false, the value is shown as "••••••••" in all list views | Permission | Settings list render | Mask in view; never expose value to non-admin or API callers |
| BR-SYS-005b | Platform Setting / API exposure | A setting with is_public = false must not be included in any API response unless the caller holds a platform-admin identity | Permission | Settings API | Exclude the record entirely from the response payload |
| BR-SYS-006a | Platform Setting / Sensitive key audit | If a setting's key contains "password", "api_key", "secret", or "token", the actual value is excluded from every audit log entry | Permission | Setting update | Audit log records "value updated (hidden for security)" instead of the before/after values |
| BR-SYS-006b | Platform Setting / Sensitive key form | If a setting's key contains "password", "api_key", "secret", or "token", the edit form must render a password-type input | Usability | Setting edit form render | Render <input type="password"> |
| BR-SYS-007 | Dropdown Value / Dropdown Need existence | A Dropdown Value cannot be created unless a matching Dropdown Need exists for the same table-column pair | Validation | Dropdown value create | Error: "No dropdown requirement is configured for this field." |
| BR-SYS-008 | Dropdown Value / Group Key derivation | The group key for a Dropdown Value is always derived server-side from the Dropdown Need (tablename.columnname); it cannot be supplied or overridden in the request body | Validation | Dropdown value create / edit | Derive server-side; ignore any submitted key field |
| BR-SYS-009a | Dropdown Value / Display Order (create) | Display order is auto-assigned as MAX(ordinal within key group) + 1 on every create | Calculation | Dropdown value create | Auto-assign; no user input required or accepted |
| BR-SYS-009b | Dropdown Value / Display Order (uniqueness) | Display order must be unique within the same group key | Validation | Dropdown value edit | Error: "This display order is already in use within this pick-list group." |
| BR-SYS-009c | Dropdown Value / Display Text (uniqueness) | Display text must be unique within the same group key | Validation | Dropdown value create / edit | Error: "This value already exists in this pick-list group." |
| BR-SYS-010 | Platform User / Super Admin singleton | Exactly one Super Admin may exist at any time; a second Super Admin cannot be created, the existing one cannot be demoted, and the existing one cannot be deleted | Concurrency / Validation | User management | Database trigger: INSERT of second super-admin fails; UPDATE demoting is_super_admin fails; DELETE fails |
| BR-SYS-011 | Menu Sync / Permission | Only a Super Admin may trigger a menu synchronisation | Permission | Sync trigger | HTTP 403 for any other actor; the sync operation does not execute |
| BR-SYS-012a | All Mutations / Audit — required | Every create, update, delete, restore, toggle-status, and reorder operation on settings, menus, dropdown needs, and dropdown values must produce an activity log entry | Workflow | All mutation endpoints | If audit write fails, the mutation proceeds; the logging failure is recorded separately |
| BR-SYS-012b | All Mutations / Audit — content | Each audit log entry must include: entity type, entity primary key, acting user identity, event type, client IP address, and before-and-after JSON where applicable | Workflow | All mutation endpoints | Missing any of these fields makes the audit entry non-compliant |
| BR-SYS-013 | Setting Model / Canonical source | The authoritative Setting model is the one in the SystemConfig module; any duplicate Setting model in other modules must be removed and all imports updated | Architecture | Code review / deployment | Duplicate model causes import ambiguity and wrong-connection queries |
| BR-SYS-014 | Dropdown Need / Uniqueness | The combination of (database tier, table name, column name) must be unique across the entire Dropdown Needs registry | Validation | Need create | Error: "A dropdown requirement for this table and column already exists." |
| BR-SYS-015 | Dropdown Need / System protection | A Dropdown Need with is_system = true cannot be edited or deleted through any application interface | Permission | Need edit / delete | Error: "This dropdown requirement is system-protected and cannot be changed." |
| BR-SYS-016 | Dropdown Value / Deletion block | A Dropdown Value cannot be permanently deleted if any school data record references it | Validation | Value delete | Error: "This value is referenced by {N} school record(s). Deactivate it instead of deleting." Deactivation is always permitted. |
| BR-SYS-017 | Menu Translation / Uniqueness | Only one translation record may exist per menu item + language combination; create and update operations must use upsert semantics | Validation | Translation create / update | Use updateOrCreate; never INSERT if record already exists for that combination |
| BR-SYS-018 | SYS Routes / Middleware | All SystemConfig routes must be registered under the central domain middleware group: web, auth, verified — and must never include InitializeTenancyByDomain, PreventAccessFromCentralDomains, or EnsureTenantIsActive | Architecture / Permission | RSP configuration | If tenant middleware is present, the central domain returns 403 from PreventAccessFromCentralDomains; confirmed by TEN-D-002 |
| BR-SYS-019a | School-Path Create / Need creation | A school administrator may not create Dropdown Needs; the need creation pathway is hidden and inaccessible at the school-path entry point | Permission | School-path form render | Hide the "Create New Need" control; reject any request that attempts to create a need from a school-path session |
| BR-SYS-019b | School-Path Create / Need selector | In the school-path dropdown value creation form, only Dropdown Needs with tenant_creation_allowed = true appear in the need selector | Permission | School-path form render | Filter the selector to tenant_creation_allowed = 1 |
| BR-SYS-020 | Backup Run / Async execution | A backup run must be queued as a background job; it must not execute synchronously within the HTTP request-response cycle | Workflow | Backup create | Dispatch RunBackupJob to the queue; return immediately with a "queued" confirmation |
