v2 — 3 tables → 20, in 6 layers

The decision rule is one question: what is the thing under test?

- A rule, formula or algorithm, no DB → Unit
- What the server does when a request arrives → Feature
- What the browser does — JS, modal, Alpine state, drag-drop → Dusk

▎ If a test would still be meaningful with the UI deleted, it does not belong in Dusk.

And here's the part that makes this mechanical for you: your TcLists are already decomposed into BC-DB / BC-VAL / BC-AUTH / BC-BIZ / BC-SM / BC-REF. Layer assignment maps straight onto those types, so it's a lookup, not a judgement call. Evidence you're already feeling this: Rule Card #14 exists because Dusk\Browser has no assertStatus(), so your agents must switch to HTTP methods to assert a 403. That's not an environment quirk — that's Dusk telling you a server-side assertion belongs at the Feature layer. A large share of your 48-rule card is workarounds for asserting server facts through a browser.

On other tools — I'd add Larastan/PHPStan (highest value per hour of anything in the plan; catches the isCasted() / non-existent-column class of bugs with no test written), Pint, composer audit, and a route-vs-policy coverage script. I'd explicitly not add Playwright or Cypress: little gain over Dusk, and you'd pay for a second toolchain, second CI runner, second selector vocabulary, and a JS/PHP split for your team.
