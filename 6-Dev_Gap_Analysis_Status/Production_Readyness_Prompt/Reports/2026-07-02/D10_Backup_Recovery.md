# D10 — Backup / Recovery Audit

**Project:** Prime-AI (`/Users/bkwork/Herd/prime_ai`)
**Date:** 2026-07-02 | **Auditor:** DevOps & Deployment Engineer (read-only)

## Verdict

**FAIL — tenant data is effectively unprotected.** In a one-DB-per-school architecture, there is **no mechanism that backs up all tenant databases**: the Spatie config covers only the central `prime_db` connection, tenant DBs are backed up only if an admin manually lists them in a `sys_backup_schedules` row (a static list that never picks up new schools), the only destination disk is `local` on the same server as the databases, backup jobs go to a `backup` queue that no configured worker consumes, failure notifications are disabled, and no restore procedure exists. A single server loss destroys every school's data and every backup simultaneously.

## How backups actually work today (traced)

1. `config/backup.php` — stock Spatie: `databases: [env('DB_CONNECTION','mysql')]` (central `prime_db` only), files `include: base_path()`, destination `disks: ['local']` (= `storage/app/private` on the same host), `notifications: []` (empty).
2. `routes/console.php` calls `BackupScheduleService::register()` — reads `sys_backup_schedules` rows (cron expressions) and, per row, dispatches `RunBackupJob` with a **frozen** `databases_json` list of connections + tenant UUIDs chosen when the schedule was created. Whole registration is wrapped in a silent `catch (Throwable)`.
3. `Modules/SystemConfig/app/Jobs/RunBackupJob.php` — dynamically registers `backup_tenant_{uuid}` connections (DB name `tenant_{uuid}` per `config/tenancy.php` prefix), overrides `backup.backup.source.databases`, then runs `backup:run --only-db --disable-notifications`, storing the zip on the `local` disk and recording a `BackupRun` row.
4. `BackupService::dispatch()` puts the job `->onQueue('backup')` — a queue that neither Horizon's supervisor config (`queue: ['default']`) nor any supervised worker (none exist) consumes.
5. Spatie's own `backup:run` / `backup:clean` are **never** scheduled directly; `stancl` `tenants:run backup:run` is used nowhere.
