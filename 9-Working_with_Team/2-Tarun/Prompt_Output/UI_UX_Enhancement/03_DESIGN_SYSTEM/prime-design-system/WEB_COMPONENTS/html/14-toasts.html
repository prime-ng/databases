Toasts

Transient, non-blocking status messages. Each is a neutral surface card with a left accent border + tinted leading icon per intent — accent, don't fill. Status is conveyed by colour and icon and a text title, and every toast carries a live-region role for screen readers.

Intent variants

Success, info, warning and error. Notice the shared card shell — only the left border, icon tint and icon glyph change. Errors use role="alert" (assertive); the rest use role="status" (polite).

Usage: confirm an action succeeded or surface an async result. Styles Bootstrap .toast/.btn-close; Prime adds .p-toast + .p-toast--success/-info/-warning/-danger (left border + tinted .p-toast__icon). Keep titles ≤ 4 words and messages one line. Use role="alert" only for errors that interrupt; everything else is role="status" so it's announced without stealing focus.

Auto-dismiss with progress bar

Auto-hiding toasts get a thin .p-toast__progress bar that shrinks over the dismiss duration, telling the user how long they have to act. The animation is disabled under prefers-reduced-motion.

</div>
Usage: set the timer with the --p-toast-duration custom property (default 5s) and the bar animation matches it automatically. Pair with Bootstrap's new bootstrap.Toast(el, {delay: 6000}) if you drive dismissal in JS. Never auto-dismiss error toasts the user must act on — drop the __progress bar and require a manual close for those.

Stack positioning

Multiple toasts collect in a .toast-container pinned to a screen corner (here top-0 end-0 = top-right). Newest on top; the container gaps them evenly.
