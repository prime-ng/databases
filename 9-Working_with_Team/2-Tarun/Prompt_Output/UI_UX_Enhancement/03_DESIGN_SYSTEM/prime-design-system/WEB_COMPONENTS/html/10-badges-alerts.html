Badges & Alerts

Status pills, alert banners and inline validation. Every status conveys meaning by colour + icon + text together — never colour alone — and uses tinted accents rather than saturated fills.

Status badges

Domain-status pills (.p-badge--*). Each carries a tinted background, a coloured leading icon, and a text label so it stays legible in greyscale and for colour-blind users.

Usage: record status in tables and detail headers (student active/inactive, admission approved/rejected, invoice paid/unpaid). Always keep the icon and the label. Prime helper .p-badge with semantic modifiers from badges.css.

Bootstrap .badge mapped to Prime colours

Legacy Bootstrap .badge.bg-* markup still works — the token bridge re-renders the saturated fills as Prime tinted pills. Handy when migrating existing Blade views without rewriting every badge.

Primary Secondary Success Warning Danger Info Light 12 
<span class="badge bg-primary">Primary</span>
<span class="badge bg-success">Success</span>
<span class="badge bg-danger">Danger</span>
<!-- counter pill -->
<span class="badge bg-primary p-badge--count">12</span>
Usage: drop-in for existing Bootstrap badges. Styled classes: .badge, .bg-primary/-secondary/-success/-warning/-danger/-info/-light. Prefer the semantic .p-badge--* pills for status; use these for neutral tags/counts. For a hard-count chip add .p-badge--count.

Alert banners

Bootstrap .alert.alert-* restyled to the Prime accent pattern: a left accent bar + subtle tint + leading status icon + heading + message, with an optional dismiss button. Each has role="alert".

<!-- tones: alert-success / alert-info / alert-warning / alert-danger -->
Usage: page-level feedback and system notices. Styled Bootstrap classes: .alert, .alert-success/-info/-warning/-danger, .alert-dismissible, .btn-close, .alert-link. The dismiss button needs Bootstrap’s JS bundle (loaded below) and an aria-label. Icon + title + colour all signal the tone together.

Inline validation messages

Small icon + text lines shown directly under a form field (.p-inline-msg). No border or fill — just a coloured glyph and a short message. Wrap the live one in aria-live="polite".

Looks good — verification link sent.

Roll number 9B-041 is already assigned.

Above the ₹15,000 auto-approval limit — needs principal sign-off.

Used for SMS fee reminders and attendance alerts.

<input class="form-control is-invalid" aria-describedby="m-roll" aria-invalid="true">
<p class="p-inline-msg is-invalid" id="m-roll" aria-live="polite">
  <i class="bi bi-x-circle"></i> Roll number 9B-041 is already assigned.
</p>

<!-- variants -->
<p class="p-inline-msg is-valid"><i class="bi bi-check-circle"></i> Looks good</p>
<p class="p-inline-msg is-warning"><i class="bi bi-exclamation-triangle"></i> Needs sign-off</p>
<p class="p-inline-msg is-hint"><i class="bi bi-info-circle"></i> Helper text</p>
Usage: per-field feedback under inputs. Link the message to its input with aria-describedby, mark the field aria-invalid="true" on error, and put aria-live="polite" on messages that appear after validation. Variants: .is-valid, .is-invalid, .is-warning, .is-hint (all from alerts.css). Each carries its own icon so status isn’t colour-only.
