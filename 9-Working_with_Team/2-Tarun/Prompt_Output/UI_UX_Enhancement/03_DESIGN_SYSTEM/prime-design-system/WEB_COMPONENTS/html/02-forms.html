Forms & Inputs

Token-driven Bootstrap/AdminLTE form controls: 44px+ targets, primary focus ring, and validation shown by colour + icon + text. Every input is paired with a <label for>; validity uses a left-accent border, never a full colour fill.

Text input

The default single-line control. Always pair it with a top <label for> tied by matching id.

<div class="p-field">
  <label for="f-name" class="form-label">Student full name <span class="p-req" aria-hidden="true">*</span></label>
  <input type="text" class="form-control" id="f-name" name="student_name"
         placeholder="e.g. Aarav Sharma" autocomplete="name">
</div>
Usage: Base of most forms. Styles Bootstrap .form-control + .form-label. Prime .p-field supplies vertical rhythm; .p-req flags required fields. Focus shows the primary ring; hover softens the border.

Password — show / hide toggle

An .input-group with a trailing icon-button that flips the field between password and text. The button carries an aria-label and swaps bi-eye / bi-eye-slash.

<div class="input-group">
  <input type="password" class="form-control" id="f-pass" name="password"
         placeholder="Enter password" autocomplete="current-password">
  <button class="btn btn-outline-secondary btn-icon" type="button"
          data-pw-toggle="f-pass" aria-label="Show password" title="Show password">
    <i class="bi bi-eye" aria-hidden="true"></i>
  </button>
</div>

<script>
document.querySelectorAll('[data-pw-toggle]').forEach(function (btn) {
  btn.addEventListener('click', function () {
    var input = document.getElementById(btn.getAttribute('data-pw-toggle'));
    var show = input.type === 'password';
    input.type = show ? 'text' : 'password';
    btn.querySelector('i').className = show ? 'bi bi-eye-slash' : 'bi bi-eye';
    btn.setAttribute('aria-label', show ? 'Hide password' : 'Show password');
    btn.setAttribute('title', show ? 'Hide password' : 'Show password');
  });
});
</script>
Usage: Login / set-password screens. The icon-only toggle keeps both aria-label and title in sync so screen readers and hover tooltips announce the current action.

Number

Numeric entry with min/max/step and an inputmode hint for mobile keypads.

<label for="f-roll" class="form-label">Roll number</label>
<input type="number" class="form-control" id="f-roll" name="roll_no"
       min="1" max="60" step="1" inputmode="numeric" placeholder="1–60">
Usage: Counts, roll numbers, marks. Set inputmode="numeric" for the right mobile keypad and constrain with min/max so the browser validates on submit.

Email

type="email" gives native format validation and the email keyboard on mobile.

<label for="f-email" class="form-label">Parent email</label>
<input type="email" class="form-control" id="f-email" name="email"

Visible to class teachers and the parent portal.

Select — single & multiple

Native .form-select. Single selects show a token-tinted caret; adding multiple switches to a list box.

<label for="f-class" class="form-label">Class</label>
<select class="form-select" id="f-class" name="class_id">
  <option value="" selected disabled>Choose a class…</option>
  <option>Grade 6 — A</option>
</select>

<label for="f-subjects" class="form-label">Subjects</label>
<select class="form-select" id="f-subjects" name="subjects[]" multiple size="4">
  <option selected>Mathematics</option>
  <option>English</option>
</select>
Usage: Bounded choices. Use a disabled placeholder <option> as the prompt. For multi-select, name with [] and add a hint that Ctrl/⌘ selects several.

File upload

The styled native .form-control[type=file] for simple cases, plus a nicer drag-drop-look label (.p-filedrop) that hides the raw input.

<!-- Simple styled file input -->
<label for="f-doc" class="form-label">Upload document</label>
<input type="file" class="form-control" id="f-doc" name="document">

<!-- Drag-drop-look label (input visually hidden but focusable) -->
<label class="p-filedrop" for="f-photo">
  <i class="bi bi-cloud-arrow-up p-filedrop-icon" aria-hidden="true"></i>
  <span><strong>Click to upload</strong> or drag & drop</span>
  <span class="p-filedrop-hint">PNG or JPG, up to 2 MB</span>
  <input type="file" id="f-photo" name="photo" accept="image/png,image/jpeg">
</label>
Usage: Documents and photos. The .p-filedrop label stays keyboard-accessible (the input is only visually hidden) and lights up on hover/focus. Set accept to steer the file dialog.

Search with clear button

.p-search wraps a bi-search prefix and a bi-x-circle clear button that appears only when the field has a value.

<div class="p-search has-value">
  <i class="bi bi-search p-search-icon" aria-hidden="true"></i>
  <input type="search" class="form-control" id="f-search" name="q" placeholder="Name or admission no.">
  <button type="button" class="p-search-clear" data-search-clear="f-search" aria-label="Clear search">
    <i class="bi bi-x-circle" aria-hidden="true"></i>
  </button>
</div>

<script>
document.querySelectorAll('.p-search .form-control').forEach(function (input) {
  var wrap = input.closest('.p-search');
  var sync = function () { wrap.classList.toggle('has-value', input.value.length > 0); };
  input.addEventListener('input', sync); sync();
});
document.querySelectorAll('[data-search-clear]').forEach(function (btn) {
  btn.addEventListener('click', function () {
    var input = document.getElementById(btn.getAttribute('data-search-clear'));
    input.value = ''; input.dispatchEvent(new Event('input')); input.focus();
  });
});
</script>
Usage: List/table filters. The .has-value class (toggled by the script) reveals the clear button; the icon-only clear carries an aria-label. The prefix icon tints to primary on focus.

Validation states

Valid (.is-valid), invalid (.is-invalid) and a neutral hint (.form-text). Each state pairs a colour with an icon and text — never colour alone. Invalid inputs set aria-invalid and aria-describedby.

Looks good — number is available.
Enter a valid email like name@school.edu.in.
We only use this for attendance and fee alerts.
<!-- Valid -->
<input type="text" class="form-control is-valid" id="v-ok" aria-describedby="v-ok-fb">
<div class="valid-feedback" id="v-ok-fb">
  <i class="bi bi-check-circle" aria-hidden="true"></i> Looks good — number is available.
</div>

<!-- Invalid -->
<input type="email" class="form-control is-invalid" id="v-bad"
       aria-invalid="true" aria-describedby="v-bad-fb">
<div class="invalid-feedback" id="v-bad-fb">
  <i class="bi bi-exclamation-triangle" aria-hidden="true"></i> Enter a valid email…
</div>

<!-- Neutral hint -->
<input type="tel" class="form-control" id="v-hint" aria-describedby="v-hint-help">
<div class="form-text" id="v-hint-help">We only use this for attendance and fee alerts.</div>
Usage: Styles Bootstrap .is-valid/.is-invalid + .valid-feedback/.invalid-feedback and neutral .form-text. Prime renders validity as a left-accent border + soft ring + inline SVG glyph, and the feedback text starts with an icon so meaning survives without colour. Link the message with aria-describedby and set aria-invalid on failures.
