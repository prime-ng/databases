Buttons

Token-driven Bootstrap/AdminLTE .btns. Solid fills are reserved for the one primary action on a screen; everything else uses outline or ghost so the accent guides the eye instead of shouting.

Solid intent fills

Semantic fills for primary actions. Use at most one solid button per view; reach for outline/ghost for the rest. Lighter fills (warning / success / info) carry dark text for AA contrast.

<button type="button" class="btn btn-primary">Primary</button>
<button type="button" class="btn btn-secondary">Secondary</button>
<button type="button" class="btn btn-success">Success</button>
<button type="button" class="btn btn-danger">Danger</button>
<button type="button" class="btn btn-warning">Warning</button>
<button type="button" class="btn btn-info">Info</button>
Usage: Styles Bootstrap .btn + .btn-primary/.btn-secondary/.btn-success/.btn-danger/.btn-warning/.btn-info. Pair color with a text label (and an icon where the action is not obvious) — color is never the only signal.

Ghost buttons

Text-only accent buttons for low-emphasis / inline actions (toolbars, table rows, cards). The .btn-ghost base is neutral; add an intent modifier to accent it.

<button type="button" class="btn btn-ghost">Ghost</button>
<button type="button" class="btn btn-ghost btn-ghost-primary">Ghost Primary</button>
<button type="button" class="btn btn-ghost btn-ghost-danger">Ghost Danger</button>
Usage: Prime helper .btn-ghost (+ .btn-ghost-primary / .btn-ghost-danger). Best for destructive or secondary actions you want present but quiet — e.g. a "Delete" that only fills its background on hover.

Outline buttons

Bordered accents — the default choice for secondary actions sitting beside a solid primary.

<button type="button" class="btn btn-outline-primary">Primary</button>
<button type="button" class="btn btn-outline-secondary">Secondary</button>
<button type="button" class="btn btn-outline-success">Success</button>
<button type="button" class="btn btn-outline-danger">Danger</button>
<button type="button" class="btn btn-outline-warning">Warning</button>
<button type="button" class="btn btn-outline-info">Info</button>
Usage: Styles Bootstrap .btn-outline-*. Transparent until hover, when they take a subtle tint of their own color — never a full fill.

Accent, don't fill

The core principle in one row: a single solid primary carries the main action; the supporting actions stay outline / ghost so the hierarchy is obvious at a glance.

<!-- one solid = the primary action; the rest recede -->
<button type="button" class="btn btn-primary"><i class="bi bi-check2"></i> Save changes</button>
<button type="button" class="btn btn-outline-secondary">Save &amp; add another</button>
<button type="button" class="btn btn-ghost">Cancel</button>
Usage: Never place two solid intent fills side by side — it flattens the hierarchy. One fill + outline + ghost keeps a clear "do this first" read.

Sizes

.btn-sm (32px), default (40px), .btn-lg (48px). Default and large both clear the 44px comfortable-touch guideline; reserve .btn-sm for dense desktop tables.

<button type="button" class="btn btn-primary btn-sm">Small</button>
<button type="button" class="btn btn-primary">Default</button>
<button type="button" class="btn btn-primary btn-lg">Large</button>
Usage: Styles Bootstrap .btn-sm / .btn-lg. Keep one size per action group; don't mix sizes within a single toolbar.

Icon + label

Icon-left (leading, for create/confirm) or icon-right (trailing, for "continue / next" flows). The gap spacing is built into .btn, so just place the <i> before or after the text.

<!-- icon left: icon then label -->
<button type="button" class="btn btn-primary"><i class="bi bi-plus-lg"></i> Add student</button>

<!-- icon right: label then icon -->
<button type="button" class="btn btn-outline-primary">Continue <i class="bi bi-arrow-right"></i></button>
Usage: Icons are decorative here — the text label carries meaning, so no extra ARIA is needed. Use bi bi-* Bootstrap Icons.

Icon-only

Square, tappable icon buttons for toolbars & table rows. Because there's no visible text, an aria-label (and usually a title tooltip) is required.

<button type="button" class="btn btn-icon btn-outline-secondary"
        aria-label="Edit" title="Edit"><i class="bi bi-pencil"></i></button>
<button type="button" class="btn btn-icon btn-ghost btn-ghost-danger"
        aria-label="Delete" title="Delete"><i class="bi bi-trash"></i></button>
Usage: Prime helper .btn-icon keeps the button square (40px). The aria-label is not optional — a screen reader has nothing else to announce.

Loading

Add .is-loading to swap the label for a spinner while an async action runs. Text is visually hidden but the button keeps its width (no layout jump); pair with aria-busy="true" so assistive tech announces the wait.

<button type="button" class="btn btn-primary is-loading" aria-busy="true">Saving…</button>
Usage: Prime helper .btn.is-loading. Spinner color adapts: white on solid fills, primary accent on outline/ghost/light fills. Toggle the class in JS on submit, and remove it on response.

Disabled

Use the native disabled attribute (best) — add aria-disabled="true" only on non-<button> elements (e.g. links styled as buttons) that can't take the real attribute.

Disabled link 
<button type="button" class="btn btn-primary" disabled>Disabled</button>

<!-- link-as-button can't use the disabled attribute -->
<a href="#" class="btn btn-ghost" role="button"
   aria-disabled="true" tabindex="-1">Disabled link</a>
Usage: Styled via :disabled, .disabled and [aria-disabled="true"]. Prefer disabling only when the action is truly unavailable; otherwise leave it enabled and show an inline validation message.

Block (full width)

Full-width buttons for mobile flows, modals, and narrow cards. Toggle the "Mobile" width in the toolbar to see it in context.

<button type="button" class="btn btn-primary btn-block">Continue</button>
<button type="button" class="btn btn-outline-secondary btn-block">Back</button>
Usage: Prime helper .btn-block sets display:flex; width:100%. Stack a solid primary above an outline secondary in mobile action sheets.
